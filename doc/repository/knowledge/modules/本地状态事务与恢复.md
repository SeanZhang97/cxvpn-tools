# 本地状态事务与恢复

模块：配置、订阅与节点持久化
关键词：SQLite、WAL、强杀恢复、节点丢失、批次、版本检查、兼容导出
代码路径：`core/state_store.py`、`core/config.py`、`core/app_paths.py`、`core/desktop_runtime.py`、`core/storage_probe.py`、`core/subscription_store.py`、`core/routing_tasks.py`、`core/routing_speedtest.py`、`main.py`、`api.py`、`ui/routing.js`
入口：`config.load/save`、`persist_bytes_and_nodes`、`commit_scope`
最后验证：2026-09-14 | 分支：main（工作区）

## 权威数据与事务

- 主库在 `%LOCALAPPDATA%/CXVPNTools/state.sqlite3`；schema user_version 为 3，兼容早期无 user_version 的 kv_config/node_snapshots 表。
- 安装版与直接打包版必须使用同一真实用户目录。`main.py` 在迁移/配置加载前调用
  `desktop_runtime.ensure_desktop_runtime()`；它以临时新文件及主库/JSON 的最终路径识别启动器的
  文件重定向。仅比较路径字符串或 GetCurrentPackageFullName 不足以确认实际数据位置。
- 检测到重定向后，由桌面窗口的 `Document.Application.ShellExecute` 启动；辅助进程复核路径后才
  领取任务，15 秒未领取或辅助进程异常退出则报错，不静默读取重定向副本。启动日志记录用户目录、
  主库路径与配置 revision，不记录账号/凭据正文。
- `kv_config` 保存应用配置及单调配置 revision；`provider_cache` 保存订阅定义、完整正文与元数据；`node_snapshots` 保存安全展示快照；`config_providers` 保存当前配置的订阅引用。
- `store_clock` 分配事务批次。`transaction` 使用 WAL、synchronous=FULL、BEGIN IMMEDIATE，锁等待上限 5 秒；同线程嵌套复用连接，内层异常即使被捕获也将外层标记为只能回滚。所有连接显式关闭。
- `config.save` 在同一事务内保存配置、导入尚未入库的对应缓存并绑定引用/当前快照版本；订阅更新的正文、定义、元数据和快照在一个短事务内写入。网络、Controller、Windows 服务调用在写事务外完成，SQLite 不替代运行态回滚。
- 通用设置保存只接受字段级 patch。`creds`、`credential_status`、`authorization`、`routing` 属于专用
  业务链拥有的字段，通用接口发现这些字段即拒绝整次请求；旧前端的整份页面快照不能覆盖当前凭据。
- `operation_scope` 在领取时捕获持久化配置 revision；`commit_scope` 同时检查 API 路由版本与数据库配置版本。改变配置后，旧任务不能把结果归到新配置名下。
- 测速网络请求并发执行，结果回到任务拥有线程后持久化，再通知 UI，避免线程局部的 guard 在 worker 中丢失。

## 迁移与恢复

- 配置只有数据库中不存在时才从旧 config.json/其备份导入。数据库读取失败或损坏不静默写入默认配置，也不自动拿更旧 JSON 覆盖数据库。
- `%LOCALAPPDATA%/CXVPNTools/state.sqlite3` 一旦存在，启动及打包前不再扫描或合并旧安装目录、
  旧产品目录的用户数据。首次没有主库时才按既有规则迁移，损坏库也不触发旧目录覆盖。
- 快照键为订阅 ID + URL/筛选指纹。首次迁移优先当前 ID 对应节点文件；无有效文件时可使用早期仅指纹键快照。已入库后不按旧文件 mtime 自动回滚。
- 数据库未包含对应正文时，从旧 provider 文件导入。未引用的旧库记录不在自动文件清理时删除，以便保留恢复资料。
- JSON/YAML 为提交后的兼容导出，失败记录日志但不撤销数据库成功提交。`stage_cache` 直接读取数据库正文；交给服务的文件经 `ensure_cache_file` 重新物化，因此旧文件或丢失文件不决定恢复结果。
- 每次覆盖 `config.json` 前，将其完整上一版本按内容摘要保存到 `config-history`，滚动保留 20 份；
  `.bak` 仍用于相邻版本兼容，历史目录用于多次写入后的人工恢复。
- 同一清单内，未测速或时间更旧的结果不覆盖已知新延迟；节点移出真实新清单时不保留。失败/空运行目录不能用作清空有效节点的依据。历史延迟仍保留原 tested_at，不表示当前网络一定可用。
- 前端同订阅签名下保留本地非空节点，空运行组不优先于已有快照；URL/筛选改变后不继承旧订阅展示。订阅开关必须调用分流接口，禁止把 collectConfig() 交给通用 save_config。

## 验证与备份边界

- `python tests/test_state_store_recovery.py`：临时目录、版本冲突、批次一致性、嵌套回滚、迁移、非 BMP Unicode、导出失败、首屏恢复与强杀四阶段。
- 加 `--exe dist/CXVPNTools/CXVPNTools.exe` 使用真实打包代码运行同一隔离探针。入口在 GUI/worker/旧数据迁移之前分派，只接受系统临时目录下带授权标记的测试目录，不访问真实网络或用户数据。
- Windows Python 3.14 测试父进程须释放已终止子进程的 HANDLE（含 GC），否则残留映射可让 SQLite 恢复返回 SQLITE_IOERR_TRUNCATE。这是测试句柄生命周期，不能通过删除用户 WAL/shm 解决。
- 运行中备份使用 SQLite backup API，不单独复制主 db 丢弃 WAL。构建前在 `recovery-backups` 保留
  最近 5 份数据库一致性副本；构建前后核对完整配置 payload 摘要，不输出凭据。
- 正常启动可能重复提交等值配置并递增 revision；因此启动后核对除版本外还需比较实际配置内容，
  不能把 revision 改变直接判定为配置丢失，也不能把错误数据视图的摘要不变当作保留成功。
- `tests/test_shared_user_data.py --exe <产物路径>` 在带授权标记的临时用户目录运行真实打包代码：
  两个 exe 目录共用一份主库，旧安装目录 JSON 不参与覆盖，覆盖手机号、凭据及 Unicode；不启动
  GUI/worker，也不访问真实账号或网络。
