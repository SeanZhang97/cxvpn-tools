# 业务域名独立代理出口

模块：Windows 统一域名分流
关键词：业务规则集、ChatGPT、GitHub、proxy_outbounds、business_rules、独立节点、排除域名
代码路径：`core/routing_business.py`、`core/routing.py`、`core/config.py`、`core/config_maintenance.py`、`ui/routing_business.js`、`ui/routing.js`、`ui/proxy.js`、`ui/routing_activity.js`
入口：规则工作区 → 保存并应用 → `Api.apply_routing` → `RoutingManager.apply`
最后验证：2026-10-13 | 分支：main（工作区）

## 配置与兼容

- routing schema 为 10，SQLite 数据库 schema 不变。旧 routing 增加两个空列表，默认出口和既有规则语义不变；旧程序拒绝高版本 routing，降级需恢复兼容备份。
- `proxy_outbounds[]` 保存 `{id, name, provider_id, node_name}`，最多 32 项；ID 稳定且唯一，名称可编辑，节点以订阅 ID 与原始名称定位，不复制订阅凭据或 provider 正文。
- `business_rules[]` 保存 `{id, name, enabled, outbound, domains, exclude_domains}`，最多 32 项；出口只能引用 `outbound:<id>`。每项最多 200 个后缀、50 个排除后缀；启用项展开后最多 1000 条及 512 KB。
- 普通域名规则也可选择 `outbound:<id>`。默认出口保持原有选项，不引入业务出口。停用规则仍保留引用，必须改绑或移除后才能删除出口；出口所属订阅必须存在并启用。
- UI 编辑共享 routing 草稿，不立即写库；“保存并应用”继续使用原有路由锁、版本检查、运行事务、SQLite 保存和失败补偿回滚。导入导出包含两个新增列表。

## 数据面和失效边界

- 每个出口生成 `OUTBOUND-<id>` 的独立 `select` 组，只 `use` 对应 provider；过滤器精确匹配加订阅前缀的原始节点名，正则元字符转义。
- 空组固定 `empty-fallback=REJECT`，不跟随订阅手动节点、聚合选点或自动优选。节点改名/删除后保存的引用不改变；UI 根据现有节点目录提示不可用，不猜测替代节点。
- 新出口不加入订阅组选点确认名单，避免业务固定节点错误依赖该订阅的另一份手动偏好。原生应用和系统代理快切前独立回读 `/proxies`，确认组只含指定节点或仅 `REJECT`，不一致则失败并沿用外层回滚。
- 规则/组变化复用现有热重载资格判断；涉及其它字段时可能重启核心。没有主动断开全体连接的新增操作，已建立连接不会被此功能主动迁移；核心重建仍可能中断连接。
- 连接页把 `OUTBOUND-<id>` 映射为已应用出口名称，同时保留链中真实节点。域名命中解释显示规则集名称和固定节点；“快照存在”不等同于实时连通。

### 当前运行确认的边界

- `_referenced_group_ids` 负责传统订阅/聚合组选点，不包含命名出口；业务出口由 `_verify_business_outbounds` 单独读取 `/proxies`，在共享的 25 秒就绪预算内等待固定节点加载（快切独立预算 3 秒）。只接受指定节点或单成员 `REJECT`；错误节点/错误成员立即失败。未加载最终保持拒绝连接并返回警告，不自动改绑。
- `_traffic_proxy_groups` 包含生效规则中的 `outbound:<id>`。提交前在独立 8 秒预算内回读各组身份，再对有效业务出口通过 Controller `/proxies/OUTBOUND-<id>/delay` 定向探测；最多每批 8 个并行，共享另一个 8 秒预算。普通规则和业务规则引用同一出口只探测一次；全局模式和停用规则不触发业务出口探测。
- 独立探测失败保留固定绑定并返回警告；通用接管链路失败仍中止应用并回滚。通用目标走物理出口不能代替业务出口探测。节点健康检查只证明对探测目标的可达性，不证明 ChatGPT/GitHub 登录、支付、语音或区域资格。就绪与各阶段连通性预算分开，不把 25 秒描述成整个应用流程的总时长。
- `_install`、`apply`、系统代理快切均向上返回出口警告，规则页与代理首页按警告级别展示。订阅刷新保留 `selection_invalid` 的传统手动选点语义，另在 `warning`/`msg` 汇总该订阅全部失效固定出口，包含未启用规则使用的已保存出口；缓存同步警告不会被覆盖。

## 优先级与规则集维护

- VPN 服务器保护、授权入口例外和手动 bypass 保留既有优先级；其后依次为用户逐条规则、业务规则集（列表顺序）、本地内置规则、可选国内 IP 兜底、MATCH。
- 业务域名为后缀，包含主域名及子域名。排除后缀由 `AND + NOT` 实现，仅跳过当前业务规则，继续匹配后续规则，不代表强制直连。域名解释使用相同的排除逻辑。
- 全局模式不执行业务规则集。手动绕过域名与业务域名重叠时预检提示绕过优先；进程绕过同样优先。自动国内域名绕过复用 `_active_rules` 检测业务域名范围，避免在系统代理入口遮蔽业务规则。
- ChatGPT/GitHub 模板是可选的初始主要域名清单，不自动启用、不主动下载规则。添加后复制到草稿/用户配置，可补充和排除，无需重新打包，不会被后续模板静默覆盖。
- ChatGPT 模板包含 OpenAI API、用户提供的关联入口/产品域名和部分验证、登录、语音、专用 CDN、遥测、问卷与支付主机。第三方采用具体主机后缀，不接管整个 `cloudflare.com`、`livekit.cloud`、Azure、Stripe 或 Sentry 公共后缀；同一共享主机被其它网站使用时也会命中，不能按发起网站隔离。
- 官方清单支持的补充项包括 `challenges.cloudflare.com`、WorkOS 主机、`js.stripe.com`、两个指定 Sentry 主机和 `rum.browser-intake-datadoghq.com`；`cdn.auth0.com`、三个 LiveKit 主机、专用 CDN、问卷及关联入口来自用户兼容清单，未逐项进行真实流量验证，不把它们表述为官方当前必需项。
- `chatgpt.site` 未核实归属，历史 `arkoselabs.com`/`hcaptcha.com` 整域未默认加入。业务模板只支持后缀，未收录 `chatgpt-async-webps-prod-*.webpubsub.azure.com`，也不放宽到整个 Azure Web PubSub；实际需要时可在已有“有序域名规则”中添加通配规则并选择相同出口。
- 域名规则不保证完整支付流程或纯 IP/UDP 语音流量覆盖。GitHub 模板保持主要网页、API、静态资源和下载域名，不声称覆盖全部 Copilot/扩展业务。来源见下方。
- 系统代理只能处理遵循该入口的连接；Git SSH、纯 IP 和 UDP 流量不能凭域名清单承诺完整覆盖。用户需按实际应用代理/TUN 和连接信息核验。

## 规则工作区交互

- 出口按行展示名称、订阅和固定节点；局部表单覆盖全局 `.field` 的 170px 固定宽度。搜索和删除等低频操作位于“搜索 / 管理”，收起时清除节点筛选，避免不可见条件隐藏候选。
- 规则集常驻展示名称、目标出口、启用状态及域名/排除数量；域名编辑、排序和删除按需展开。空的自定义规则集创建时展开，模板默认折叠。
- 折叠状态仅驻留前端，按稳定 ID 保存，刷新或排序不重置，不计入配置脏状态；不写入 SQLite。所有节点、订阅及出口下拉复用 `enhanceRoutingSelect`，保持原组件键盘、浮层和 ARIA 行为。
- 宽窗口出口三列，窄窗口降为两列或单列；域名文本区沿用全局深色滚动条。模板适用范围和规则优先级收纳在说明折叠区，全局模式失效和节点缺失仍直接提示。

## 离线验证入口

- `.venv/Scripts/python.exe -m tests.run_business_offline`：相关配置、规范化、生成、优先级、Unicode 持久化、导入导出和事务测试；拒绝真实网络、服务、子进程。
- `.venv/Scripts/python.exe -m unittest tests.test_routing_business_mihomo`：临时本地 file provider，内置 Mihomo `-t` 检查 Unicode、独立组及 AND/NOT 语法，不启动系统接管。
- `node tests/test_ui_routing_business.js`：虚构节点、同订阅双出口、规则集、排除、引用保护、动态下拉清单、搜索和禁用状态，以及折叠/排序状态、表单标签和 Unicode 名称。
- `tests/fixtures/business_preview.html`：隔离前端样例，无真实订阅及保存操作，供人工视觉验收；截图、窗口缩放与真实业务流量尚未验证。
