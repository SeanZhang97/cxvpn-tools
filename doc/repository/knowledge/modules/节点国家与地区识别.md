# 节点国家与地区识别

- 模块：节点工作区、订阅智能优选
- 关键词：国家列表、地区、节点筛选、旗帜、ISO代码、OTHER、智能优选
- 代码路径：`ui/routing_regions.json`、`ui/routing_regions.js`、`ui/routing_nodes.js`、`ui/routing_region_picker.js`、`ui/routing.js`、`ui/style.css`、`core/routing_auto_policy.py`
- 入口：`RoutingNodeTools.regionCode`、`RoutingNodeTools.regionOptions`、`RoutingRegionPicker.render`、`normalize_policy`、`stage_region_pattern`
- 最后验证日期：2026-10-08
- 分支：main

## 数据与维护

- `ui/routing_regions.json` 是唯一地区名单，包含 249 个 ISO 3166-1 国家与地区，并补充 XK、CQ、AC、CP、DG、EA、IC、TA 共 8 个 CLDR 地区及兜底 `OTHER`；香港、澳门、台湾保留各自地区代码。
- 中文简体、繁体、英文名称及名称变体基于 [Unicode CLDR 48](https://github.com/unicode-org/cldr-json/tree/48.0.0/cldr-json/cldr-localenames-full)，二字母、三字母代码来自同版本 `codeMappings.json`。另保留既有城市名称，并补充常见节点城市和国家别名。许可随资源保存为 `ui/routing_regions.LICENSE.txt`。
- 每条记录是 `[中文显示名, 名称与代码别名列表]`。修改 JSON 后执行 `.venv\Scripts\python.exe scripts\generate_routing_regions.py`，同步生成 `ui/routing_regions.js`；前端测试核对生成结果与 JSON 完全一致。
- HTML 先同步加载 `routing_regions.js`，再加载 `routing_nodes.js`，不增加运行时网络请求。后端从 `resource_root()/ui/routing_regions.json` 读取同一资源并补充旗帜别名；普通与受保护打包均沿用已有的 `ui/` 资源收集。

## 筛选与统计

- 分类读取节点 `display_name`，缺失时读取 `name`；去掉运行态 `[订阅名]` 前缀，避免订阅名称干扰节点地区。
- 已知地区旗帜优先；名称匹配执行 NFKD 归一化并移除组合附加符号，先长名称、后短名称、最后代码。这样印度尼西亚、巴布亚新几内亚、几内亚比绍、南苏丹不会被较短国家名抢先分类。
- 英文名称和三字母代码忽略大小写；二字母代码要求大写，并检查英文数字边界，避免普通英文单词被当成国家代码。无法识别的节点归入 `OTHER`。
- 地区由节点名称与旗帜识别，不调用 GeoIP，也不声称验证服务器实际物理位置；只有地址或无地区名称的节点仍可能无法分类。
- 地区筛选统计当前选点出口的全部可选节点，不包含订阅流量、到期等元信息节点；所有实际出现的地区均可独立选择，不再截断名单或把已识别地区合并。“全部”和各地区数量应守恒。
- 地区按节点数量降序排列，同数量保留既有常用地区优先级。主栏显示“全部”和最多 5 个地区；选中的非常用地区替换最后一个快捷项，保证当前筛选可见。
- 主栏保持单行，CSS 容器查询根据地区栏实际宽度收起部分未选快捷按钮；选中地区和“更多地区”入口保留。窄窗口把排序移到下一行，浮层由三列改为两列。
- “更多地区”的隐藏 `select` 复用 `enhanceRoutingSelect`，地区浮层在已有组件上增加搜索输入和可滚动列表；不是原生浏览器下拉。搜索匹配中文、繁体、英文及代码，使用 UTF-8 数据、NFKD 归一化和组合字符处理。
- 搜索浮层支持方向键、Home、End、Enter、Escape、Tab；入口支持 Enter、Space。选点、Escape 和 Tab 关闭时恢复入口焦点，点击外部、切换页面及打开其他下拉框沿用共享关闭逻辑。
- 浮层固定定位在页面视口内，复用共享滚动/窗口缩放监听；列表设置 `scrollbar-gutter: stable` 并继承全局深色滚动条。空搜索显示必要的无结果状态，不隐藏地区名单。
- 未变化的地区数据不重建控件；数据刷新时保留搜索输入和焦点，避免后台状态刷新中断正在操作的筛选。
- 智能优选下拉框使用同一完整名单和已有 `enhanceRoutingSelect`；策略仍最多 8 个地区，不改变持久化字段、故障转移顺序和 `OTHER` 必须填写补充关键词的约束。

- `node tests/test_ui_routing_region_picker.js`：快捷项、完整地区可达性、搜索、空状态、键盘、焦点、更新、共享组件互斥、禁用态和视口边界的离线 DOM 检查；包含新滚动区域与响应式样式约束。
- `.venv\Scripts\python.exe -m unittest tests.test_routing_auto_policy`：所有已知地区能保存策略并生成地区过滤表达式，以及既有优选流程回归。
