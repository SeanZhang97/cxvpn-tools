# VPN 目标路由自动维护

模块：Windows VPN 动态目标路由
关键词：VPN, DNS, 首次访问, fake-IP, 路由租约, Named Pipe, 路由恢复, 核心定制
代码路径：`core/routing.py`、`routing-service/src/vpn_route_*.rs`、`routing-service/src/vpn_routes*.rs`、
`routing-service/src/core_job.rs`、`patches/mihomo/`、`build_mihomo.py`
入口：`build_mihomo_config`、Mihomo direct 的 TCP/UDP 出站、`RouteState.acquire`
最后验证：2026-09-15 | 分支：main（工作区实现）

## 调用链与出口隔离

1. 配置引用的 Windows VPN 出口生成 `cxvpn-managed-route=true`，PHYSICAL 和订阅不标记。
2. 定制 Mihomo 沿用现有 DNS。真实 IP 确定后，在 TCP connect/TFO 或 UDP 发送前请求路由服务。
3. 服务用当前核心 PID、进程世代及已应用 VPN 白名单验证请求，自行解析 VPN 接口 LUID。
   不接受客户端指定网关、网段、metric 或系统命令。
   每个新连接先查询 Windows 接口表：所选 VPN 网卡缺失或未连接时，验证已应用 PHYSICAL
   接口的地址族和路由，返回物理接口；此分支不创建 VPN 路由。查询错误不视为断开。
4. 已有覆盖路由直接复用。缺路由时先建立目标 IP 的保护路由，再建立 VPN 的 `/32` 或 `/128`
   活动路由，回读所选 VPN 与未绑定接口的路由选择后才允许连接。
5. 核心通过 `IP_UNICAST_IF` / `IPV6_UNICAST_IF` 绑定服务返回的实际接口，服务不转发业务数据。
   VPN 连接后，新连接自动恢复选择 VPN；不等待 GUI 状态快照或重载规则。

保护路由在 TUN 模式指向 CXVPN-TUN，system-proxy 模式指向已应用物理接口并沿用该接口的
真实下一跳。保护路由 metric=7，VPN host route metric=60000；保护接口 metric 太高或
无法证明未绑定流量仍经保护接口时拒绝该请求，不通过扩大默认路由解决。

Windows `InitializeIpForwardEntry` 默认启用自动配置标记；创建时必须显式关闭该标记、
Immortal、Publish、Loopback，并设置 NetMgmt 协议，使严格回读和所有权检查一致。

## 生命周期与异常

- 活动路由不写入 VPN 电话簿，无需重连 VPN；地址变化随核心实际连接目标处理，不提前枚举子域名。
- 同接口、同目标的多连接共享路由；不同 VPN 分开管理，共享同一保护路由。
- TCP 连接成功后持有租约，失败/取消/竞速落败释放；UDP 新目标发送前申请，关闭时释放所有租约。
- 已建立 TCP/UDP 关联保留原出口，不迁移活动连接。UDP 后续新目标若选择了另一接口，
  结束旧关联，不用旧 socket 发送；后续新关联重新选择出口。
- DNS TTL 不决定活动连接路由的删除。最后一个租约释放后保留 60 秒宽限，先删除 VPN 路由，
  再删除没有依赖的保护路由。删除 VPN 失败时保留保护路由和恢复记录。
- 写盘恢复意图先于 OS 创建。既有路由不认领；删除时比较 LUID、地址、下一跳、metric、协议
  和受控属性，外部修改过的记录不强制删除。缺失路由的新申请重新检查并补齐，不丢失旧连接计数。
- 核心进程世代重置清理旧租约；核心被 Windows Job 约束，服务异常退出时内核关闭其核心进程。
  服务启动先处理路由恢复记录；记录损坏时保留并报错，不能猜测删除系统路由。
- 客户端取消后可能仍收到迟到的申请；释放记录短暂保留为取消标记，避免释放先到、申请后到造成泄漏。
- 核心释放使用有界后台队列，最多重试 3 次；最终失败保留租约至核心退出，不误删可能仍使用的路由。
- 拒绝回环、组播、链路本地、未指定地址、IPv4-mapped IPv6 与当前配置的 fake-IP 范围；
  VPN 缺少可用 IPv6 源地址时拒绝该 IPv6 候选，由核心现有候选逻辑选择可用 IPv4。

## 并发、状态与日志

独立 `CXVPNRouteLease.v1` Named Pipe 使用受限 ACL、拒绝远程客户端，并从内核读取实际客户端 PID。
路由状态锁与原服务 manager 锁分离，最多 32 个请求同时处理，单请求准备总期限 2 秒，
4096 个路由记录、16384 个连接租约。容量满和过期请求明确失败，不能无界排队。
每次新请求核对实际接口和路由，不依赖 GUI 页面打开或日志订阅。
RAS 拨号回调成功或缓存的 Connected 不足以证明接口可用；选出口以原生接口表为准。
只有 VPN 未连接触发物理直连；VPN 已连接但目标超时、缺少 IPv6 地址、IPC 或路由检查失败时，
仍报错，不触发物理或订阅回退。物理接口不可用也明确失败。

`vpn-routes.log` 记录申请领取/开始、创建、成功/失败、释放与清理；2 MB 时保留一个轮转文件。
核心提交阶段写 debug 日志。日志不包含业务 URL 查询参数、凭据或 Controller secret。

## 构建与验证边界

运行时为固定上游 v1.19.30 的 `cxvpn.2` 补丁版本，服务 0.8.1、控制 IPC 8。
`build_mihomo.py` 维护源码、补丁和二进制摘要；日常打包校验一致性，随应用携带对应源码包。
active VPN 就绪检查要求核心回报能力 2，不能让旧核心静默忽略物理回退语义。
自定义 direct 字段必须保留 `omitempty`：物理与上游普通 direct 配置不携带此字段，
仍需通过同一上游解析器。补丁测试覆盖普通 direct 与受管 direct 的加载兼容性。
服务升级同时备份旧核心和旧服务，失败时一起恢复，避免版本摘要不匹配。

离线测试覆盖共享/多 VPN、新目标、DNS 地址变化、长连接、取消、容量、写入/删除失败、
外部路由修改、重新创建、断线/新接口、损坏恢复记录、UTF-8 和核心能力门控。
保留地址 `203.0.113.123` 的管理员原生 API 测试默认 ignored，显式开启后验证创建、回读、清理。
真实业务可达性、IPv6 网络能力和 VPN 服务器可访问范围仍需真实环境验证，不能由配置或离线测试推断。
