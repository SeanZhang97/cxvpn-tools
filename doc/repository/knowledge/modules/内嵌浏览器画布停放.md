# 内嵌浏览器画布停放

## 模块信息

- 关键词：`NativeBrowser`、`set_visible`、`parked`、`_layout`、`bring_to_front`、`browser_set_visible`、`TabStop`、`ClientSize`、`goToPage`、`show_form_in_place`、停放、不切页、最小化、原生输入
- 代码路径：`core/browser_win.py`（`NativeBrowser.set_visible`、`_layout`、`bring_to_front`）、`api.py`（`browser_set_visible`）、`ui/app.js`（`goToPage`、`syncBrowserVisibility`）、`core/worker.py`（`_start_browser`）
- 入口：主界面切页与阻断弹窗开关 → `api.browser_set_visible()`；窗口尺寸变化 → `Form.Resize`；人工兜底 → `PageShim.bring_to_front()`
- 最后验证日期：2026-11-24（隔离真实窗口 8 项、真实站点滑块 3 个场景）
- 分支：main

## 职责

让主窗口内的授权浏览器（第二个 WebView2 控件）在“浏览器页画布内”和“客户区之外”
两个位置之间切换。用户停留在其他页面、窗口最小化或隐藏到托盘时，自动化仍能收到
原生输入，并且不切换左侧菜单。不改变主 UI 铺满窗口的布局，也不改变
`browser_set_visible` 的桥接契约。

## 调用链

```text
goToPage(page) / showBlockingBrowserModal / hideBlockingBrowserModal   [ui/app.js]
  └─ syncBrowserVisibility()
       └─ bridge.browser_set_visible(browserPage && !hasBlockingBrowserModal())
            └─ Api.browser_set_visible(visible)                         [api.py]
                 ├─ worker.browser_visible = visible
                 └─ NativeBrowser.set_visible(visible)
                      └─ UI 线程: ctrl.TabStop = !parked → _layout() → 归位时 BringToFront()

worker._start_browser()
  └─ NativeBrowser(visible=worker.browser_visible) → start() → set_visible(worker.browser_visible)

Form.Resize → NativeBrowser._on_resize() → _layout()

人工兜底 (captcha_slider 自动验证失败 / captcha_handler 无 provider / web_flow 元素缺失)
  └─ PageShim.bring_to_front()
       ├─ 窗口隐藏或最小化 → show_form_in_place(form, FormWindowState.Minimized)
       ├─ 主 UI 存在 goToPage → await goToPage("browser")，显示状态由主 UI 决定
       │    └─ 无主 UI 的独立验证窗口: set_visible(True)
       └─ form.Activate()
```

## 稳定约束

- **不能用 `ctrl.set_Visible(False)` 离开浏览器页**。控件不可见时页面
  `document.visibilityState` 变为 `hidden`，`requestAnimationFrame` 停止、定时器被限到
  约 1 次/秒，CDP `Input.dispatchMouseEvent` 的确认超过 2 秒；超星滑块 SDK 在 rAF 中
  处理拖动，校验必然超时。控件全程保持 `Visible=True`。
- 以下宿主状态页面都保持 `visible`、rAF 正常、输入可送达，已逐一实测：被主界面
  WebView 盖住、控件移出客户区、窗口最小化、`Form.Hide()`（托盘隐藏）。
  被其他进程的置顶窗口完全遮挡只在本地页面验证过。
- 停放位置为 `Bounds = (-(width + 40), 90, width, height)`。子窗口被父窗口客户区裁剪，
  画布区域的鼠标命中全部落在主界面 WebView。停放期间 `ctrl.TabStop = False`，
  避免 Tab 键把焦点移入不可见的页面。
- 画布几何与 `ui/style.css` 对齐：`left/top/right/bottom = 242/90/26/24`，
  尺寸下限 320x240；`ui_view.Bounds` 始终等于真实 `ClientSize`。
- 窗口最小化时 WinForms 把 `ClientSize` 压成 0x0。`_layout()` 只让主 UI 使用真实值，
  内嵌控件沿用最近一次非零客户区尺寸（`_client_size`），还没有记录时取
  `form.RestoreBounds`。否则控件被钳到 320x240，页面重新布局，题目尺寸随之变化。
- `set_visible()` 在请求状态与当前一致时直接返回。状态在 `ctrl` 创建前就已记录，
  `_create_ctrl()` 据此决定初始位置，创建时不会闪现。
- `bring_to_front()` 是“恢复窗口并切到浏览器页”的唯一入口，正常自动化步骤不会调用它。
  调用点只有：滑块自动验证未完成转入人工拖动（`captcha_slider.handle_slider`）、
  未配置点选识别 provider 时等待人工点击（`captcha_handler`）、登录页找不到手机号输入框、
  验证码输入框或登录按钮（`web_flow`）。
  有主 UI 时显示状态由 `goToPage("browser")` → `syncBrowserVisibility()` 决定：
  `#capmodal`、`#smsmodal` 等阻断弹窗打开期间控件保持停放，原生画布不会盖住 HTML 弹窗。
- 布局只在 UI 线程执行（`_ui` → `form.Invoke`）；`_client_size` 只在 UI 线程读写。
- 运行日志关键字：`[browser] 已提交浏览器画布停放请求`、`浏览器画布已停放`、
  `浏览器画布已恢复`、`已提交人工接管请求，恢复窗口并切到浏览器页`。

## 风险与注意事项

1. **停放期间持续渲染**：内嵌浏览器创建后常驻，仅在 worker 退出时销毁。停放时页面
   仍按可见状态渲染，静态页面开销很低，带持续动画的页面会占用少量 GPU/CPU。
2. **锁屏与远程桌面断开未验证**：这两种状态下页面的可见性与输入送达没有实测数据。
3. **不要让 `js_api` 对象的公开属性指向 `NativeBrowser` 或 .NET 控件**：pywebview 注入
   `window.pywebview` 时递归遍历 `js_api` 的非函数属性（`webview/util.py` 的
   `get_functions`），走到 .NET 的 `Rectangle.Empty` 会无限递归并拖死进程。
   生产的 `Api` 暴露 `worker`，但注入发生在启动早期，此时 `worker.browser` 仍为
   `None`。隔离验证脚本必须把浏览器实例放在私有属性（`_` 前缀）中。

## 验证建议

- 离线：`node tests/test_browser_modal_visibility.js`；
  `python -m unittest tests.test_browser_reload tests.test_browser_overlay tests.test_captcha_manual_fallback`。
- 隔离真实窗口：核对 `ctrl.Bounds`、`ctrl.TabStop`，在画布区域用 `WindowFromPoint`
  与 `ChildWindowFromPoint` 网格采样确认鼠标命中，比较最小化前后的 `innerWidth x innerHeight`。
- 隔离真实站点：独立临时 profile、不可投递号码、网络层拦截短信与 `/vpn/` 接口；
  主页面注入 `goToPage` 记录器，断言自动验证期间调用次数为 0。
