## 数据与凭据边界

- 主库 `web_quick_folders`（`parent_id` 自引用 `ON DELETE CASCADE`）与 `web_quick_items`
  （`folder_id` 级联删除、`otp_account_id` 引用 `otp_accounts` 且 `ON DELETE SET NULL`），schema 6 建表；
  schema 7 仅为条目补充 `has_favicon INTEGER NOT NULL DEFAULT 0`，不扫描旧缓存或回填。
  文件夹与条目在同一父级共用 `position`（`CHECK(position>=0)`），混排靠 `position + created_at + 类型 + id`。
- `core/web_quick.py`：`MAX_DEPTH = 16`、`MAX_ENTRIES = 2000`，名称经 `_text()` 去空白、限长、拒绝控制字符；
  保存文件夹时拒绝移动到自身/后代并校验深度；`normalize_url` 拒绝非 http(s)、带凭据、控制字符与超长地址。
- `Store.move_entry(key, target_folder_id)` 是拖入文件夹的独立事务：同父级 no-op，跨父级用 `_next_position()`
  追加目标末尾，只改父级、位置和 `updated_at`，不重排其他条目或子树，也不触碰密码和自动登录字段。
  `_validate_folder_parent()` 同时供文件夹保存与移动校验目标存在、循环及 16 层深度；`target_folder_id=None`
  表示移回根目录，position 同样取根目录当前最大值加一。
- `AUTO_LOGIN_SITES` 当前为 `ifort=https://10.0.34.53`、`jumpserver=http://192.168.1.51`、
  `gitlab=https://10.0.26.27`；`platform_for_url()` 要求 origin 完全一致（含协议与端口，https 默认 443、
  http 默认 80），子域、`host.evil`、错误协议、非默认端口都返回 `None`，只有匹配站点才允许保存登录字段。
  新增平台需同时改这里、`extension/manifest.json` 的 `host_permissions`/`content_scripts.matches`、
  `extension/background.js` 的 registry 与 `extension/platforms/<平台>.js`。
- 密码用 `core/dpapi.py`（从 2FA 抽出的共用封装）以 `'CXVPNTools.WebQuick.v1:' + 条目ID` 为熵加密存 BLOB；
  2FA 的熵是 `'CXVPNTools.TOTP.v1:' + 账号ID`，两者不可混用。
  `listing()` 与全局 UI 快照只给 `has_password`；打开已有自动登录条目的编辑器时，`get_web_quick_item_password(item_id)`
  通过 `password_for_edit()` 单独解密并只返回密码，输入框默认掩码、可用眼睛显隐，关闭即清空，接口响应与日志不进入列表。
  保存时空密码仍表示保留原密码，改为普通网址会清除登录字段。
- 网页快开不参与配置 revision、不进入兼容 JSON 导出与 `.cx2fa` 备份。

## favicon 抓取与缓存

- `core/web_quick_favicon.py` 以规范化 origin 的 SHA-256 为 key；path/query/fragment 不进入 key 或文件名。
  编辑器防抖调用 `ensure()`，卡片经 `cached()` 只读缓存；`get_web_quick()` 返回持久化 `has_favicon` 并附加
  `favicon_key`，不返回图片 Base64。
- `has_favicon` 是条目自己的持久状态，不是重启时根据缓存重新计算的派生值。新建默认 `False`；保存时 URL
  未变则保留原值，URL 改变先重置为 `False`，若保存时对应 origin 已有有效 PNG 再由 API 写为 `True`。
  自动或手动采集接口接收可选条目 ID，仅在成功且结果 key 与条目当前 origin 一致时写 `True`；失败不写，
  旧网址的迟到结果不覆盖新网址状态。只有状态实际变化才增加网页快开 UI revision，配置 revision 不变。
  重建 Host 或重启应用只读 SQLite，不扫描缓存回填；缓存被单独删除时也不自动改标识，可手动重试采集。
- 抓取优先读取用户实际填写的页面，没有图标声明时才补查 origin 根页；按最终响应 URL 与首个合法 `<base>`
  解析根相对、路径相对和协议相对地址。支持 `rel=icon`、`apple-touch-icon(-precomposed)`、`fluid-icon` 和
  `msapplication-TileImage`，声明缺失或失败时依次尝试 `/favicon.ico`、`/favicon.png`、
  `/static/img/favicon.ico`、`/static/img/favicon.png`；单次最多读取 2 个 HTML 页面、4 个图片候选。
  JumpServer 根页与 `/favicon.ico` 都可能返回 HTML，实际 `/core/auth/login/` 声明 `/static/img/facio.ico`，
  因此不能只抓 origin 首页或只信 HTTP 200。支持内网 HTTP/HTTPS 和非标端口，默认执行证书链与主机名校验，
  拒绝 URL 凭据和 HTTPS 降级。经用户确认后，仅当 IP 字面量发生明确主机名不匹配时，favicon 以独立 context
  重试：`check_hostname=False` 且 `verify_mode=CERT_REQUIRED`，证书链仍必须有效；非 IP、证书链不受信、
  过期证书、协议/连接错误和 HTTP 错误均不回退。自动登录不使用该策略。
  每次重建 `ProxyHandler` opener，总超时 8 秒，每次请求最多 3 次重定向；HTML 限 512 KiB、原始图片限
  1 MiB、像素限 4 MP，日志只含 origin、异常类型/verify_code、超时、结果与耗时，不含查询或响应正文。
- Pillow 实际解码 PNG/JPEG/GIF/ICO/WebP 后统一转成最长边 64 的 PNG（≤64 KiB）；除明确 SVG MIME 外，
  不仅凭 `text/html` 等错误响应头拒绝真实栅格图片，实际 HTML、SVG、脚本和主动内容仍因解码/格式校验失败
  被排除，不会进入 WebView。转换时以整条边框最常见的非透明颜色识别纯色底并转透明（容差 55，支持透明角、
  圆角和细线主体；仅整图完全同色保持原图），缓存键使用 v4 防止旧带底图片继续生效。前端只接受
  `data:image/png;base64,...`，失败回退默认头像。
- 缓存位于用户数据目录 `web-quick-icons/`，不属于主库或另一份活动配置，可删除重建；已有有效 PNG 时只读本地，
  不自动重新下载，即使超过 7 天或显式重试也不重复请求。仅无缓存、缓存损坏或先前失败才抓取；当前策略的
  失败负缓存为 10 分钟，旧策略遗留的无版本负缓存会自动重试一次，显式重试仅跳过负缓存、不刷新有效图片。
  原子写入、同 key 锁、最多 256 个 PNG；缓存变化不增加业务 revision。

## 自动登录任务与管道协议

- `LoginManager` 状态：`pending`（120 秒等扩展领取）→ `claimed`（90 秒等结果）→
  `success|failed|timeout|expired|cancelled`；`status()`/`changes` 读取时顺带 `_sweep()` 推进超时；
  `changes` 计数与 `_web_quick_revision` 相加后作为 `wait_ui_state` 的 `web_quick_revision`，界面据此刷新。
- 同平台已有 `pending/claimed` 任务时拒绝重复提交；一次打开只提交一次登录，不做自动重试。
- 管道 `\\.\pipe\CXVPNTools.WebQuick.v1`：SDDL 仅 SYSTEM/管理员/当前用户，拒绝远程客户端，
  并用 `GetNamedPipeClientProcessId` + `QueryFullProcessImageNameW` 校验对端映像必须等于主程序真实映像
  （虚拟环境取真实解释器而非启动器）；单实例逐条处理，帧为 4 字节小端长度 + UTF-8 JSON（≤64KB），
  响应后等 1 字节确认再断开。
- 消息：`hello`（刷新 `extension_seen`）、`claim {platform, href, login}`、`report {run_id, state, detail}`。
  扩展安装/更新、Edge 启动及 Service Worker 启动时立即 `hello`，`chrome.alarms` 每分钟补偿心跳；
  当前扩展版本 1.1.1，150 秒未刷新则离线。
  只有连接状态翻转才增加 `changes` 并写连接日志，重复心跳不触发 UI 重读。
  合法 `claim/report` 也会先调用 `hello()` 刷新连接：`no_pending_run` 或格式合法的 `unknown_run` 仍证明扩展可通信，
  但 origin、平台或 payload 校验失败不会刷新；重复业务活动同样只在状态翻转时增加 `changes`。
  `claim` 在服务端再次校验 `href` 经 `platform_for_url` 属于该平台才发放凭据；`login: false` 表示已登录直接成功；
  `report` 只接受 `success/failed`，`detail` 经 `_line()` 折成单行并截断（界面展示 120 字）；
  新版后台可附带 `platform`，与 run 平台不一致时返回 `forbidden`，旧消息保持兼容。
- 整页续接在 `claim` 中携带 `run_id`：仅接受同平台、同 origin、处于 claimed 的原任务；`login:false`
  直接确认已登录，续接成功返回 `skipped/resumed`。需要继续登录时仅返回 `credentials.otp`，不重复返回
  用户名或密码；`Store.otp_account()` 只读平台与 2FA 关联，不解密密码。未知、跨平台、非 claimed 续接返回
  `invalid_resume`，伪造请求不刷新任务。
- 自动登录凭据只在 `claim` 时从主库解密（含 2FA 当前码）返回给宿主；编辑密码经独立接口单条解密，
  不携带动态口令。密码与动态口令均不写日志、不进入列表或全局 UI 快照；
  `run.log` 的 `[web-quick]` 与 `%LOCALAPPDATA%\CXVPNTools\web-quick-host.log` 只记事件名与异常类型。
- 宿主子进程：`main.py` 检测到任一参数以 `chrome-extension://` 开头即进入 `core/web_quick_host.run_child()`；
  无控制台时 `core/pipe_io.pipe_stream()` 用继承句柄包二进制标准流；宿主连不上主程序返回
  `app_not_running`/`app_unreachable`，不把系统错误文本回传扩展。

## Edge 扩展与登记

- `extension/` 随包到 `_internal/extension`（`build.py --add-data`、`build_protected.py` 同步），
  仅打包版可用：`get_web_quick().extension = {available, registered, path}`，`available` 依赖 frozen。
  manifest 固定 `key`，扩展 ID 与路径无关（当前 `foejbgigmmcgfolkladakeonkdbfncae`），版本 1.1.1，
  权限只有 `nativeMessaging` 与 `alarms`，host 仅限 iFort、JumpServer、GitLab 三个精确 origin。
- 主程序启动时把宿主清单写到用户数据目录 `com.cxvpntools.web_quick.json`（`path` 指向当前 exe），
  并登记 `HKCU\SOFTWARE\Microsoft\Edge\NativeMessagingHosts\com.cxvpntools.web_quick`，内容未变不重写；
  卸载器 `[Registry] uninsdeletekey` + `[UninstallDelete]` 清理这两项（管理员卸载时 HKCU 指卸载用户）。
- 内容脚本 `content.js`：登录路由或可见 MFA/OTP 表单稳定后 `claim(login: true)`；无待领取任务时保持静默。
  独立 OTP 页即使没有 sessionStorage 续接记录，也直接进入 OTP 步骤，不得重复填写账号密码；只有非登录、
  非 MFA 路由稳定且 `readyState === 'complete'` 2 秒后才允许按已登录处理。原生 setter + `input`/`change`
  填值，每页最多提交一次；成功判据是 adapter 的 `token()`，不是单纯离开账号密码页。
- `background.js` 使用 `CXWebQuickPlatforms` registry，只接受本扩展消息，并要求 `message.platform` 与实际
  标签页 origin 同时匹配对应 adapter；claim/report 按解析出的平台转发，跨平台或伪造来源在 Native Messaging
  前拒绝。页面消息中的 `hello` 仅允许弹出页发起，生命周期、Service Worker 启动与 alarm 由后台直接发 `hello`。
- `platforms/ifort.js`：`#login-username/#login-password/#login-btn`、登录路由 `/ais-ifort/login`、
  动态口令框 `.loginForm input[type="password"]:not(#login-password)`、错误 `.el-message--error`、
  滑块 `.verify-bar-area`（只提示人工，等待期延长到 75 秒）、USBKey 选择框与人工弹窗视为失败原因。
- `platforms/jumpserver.js`：`#id_username/#password`、`#login-form button[type=submit]`，点击后由原页面
  `doLogin()` 加密并整页 POST；`/core/auth/login/` 为账号密码路由，`/core/auth/login/mfa/` 及
  `/core/auth/(mfa|otp|captcha)` 均属认证流程，离开账号密码页本身不代表成功。MFA 识别
  `one-time-code/otp/mfa_code/mfa`，并在认证路由兼容 `code/#id_code`、“虚拟 MFA 验证码”、动态口令/验证码
  placeholder；提交按钮覆盖 button/input submit。只有离开全部认证路由、无可见 OTP 且无登录表单时才判成功，
  验证码与 `.has-error/.error-info` 作为失败原因。
- `platforms/gitlab.js`：`#user_login/#user_password`、`#new_user button[type=submit]`，整页 POST；
  `body[data-page]` 以 `sessions|registrations|passwords|unlock` 开头仍属登录流程，其余值为成功。
  OTP 为 `#user_otp_attempt/#user_backup_code`，flash 错误作为失败原因。`content.js` 在 sessionStorage 保存
  `cx-web-quick-run-v1:<platform>`，整页后先续接再决定是否处理，不向旧页面重复填写凭据。
- 证书警告（IP 访问、证书签给 `*.16q.cn`）由用户手动点“继续前往”；解压扩展需用户开开发人员模式，
  删除扩展目录不会移除 Edge 中已加载的扩展，需在 `edge://extensions` 手动移除。
- GitLab 的 `https://10.0.26.27` 证书覆盖 `*.chaoxing.com` 而非 IP，证书不匹配由用户按既有方式处理；
  页面结构检查时仅通过 `--resolve` 保留域名和 TLS 校验，运行配置仍以用户给定 IP 为准，不增加域名别名或绕过验证。

## 界面与打包约定

- `ui/web_quick.js`：`refresh()` 在页面未激活时不读取，请求/排序期间的 revision 用 `refreshPending` 合并，
  请求、拖拽或键盘操作结束后补偿刷新；搜索模式跨文件夹并显示位置且禁用排序；
  `TwoFactorOrder.attach(grid, {card, handle, prefix, selectedMessage})` 与 2FA 共用拖拽实现。
  可选 `into` 钩子只在网页快开启用：文件夹主体移入、边缘前后排序，drop 重新解析目标，dragend 不重复提交；
  键盘排序和 2FA 不传 `into` 的行为不变。移动成功后权威刷新并聚焦目标，失败恢复源焦点。
  `draggingKey()` 仅暴露鼠标会话；`#wq-path` 委托 dragover/drop/dragleave，“全部”映射为 `folder:`/`null`，
  祖先按钮映射对应 ID。只对不同父级且非自身/后代的合法目标高亮，路径 drop 先 cancel 再调用 `moveIntoFolder()`；
  目标不在 grid 时聚焦重新生成的路径按钮。拖拽中 `.wq-path-dragging` 显示移出提示，结束或导航立即清理。
  下拉用 `RoutingWorkspace.enhanceSelect`（`wq-in-folder`、`wq-parent`、`wq-otp`）；
  密码框不带静态 `value=`，编辑时按 `editorSession` 异步读取并防止旧会话回写；
  `app.js` 的 `closeModal` 对 `wq-editor`/`wq-folder-dialog` 委托给本工作区。
- 侧栏与标题使用 `ui/icons/web-quick.svg`（浏览器窗口 + 闪电），普通网址无缓存时仍用 globe；
  `open_web_quick_extensions()` 使用 `open_url(new_window=True, maximized=True)`：先创建空白新窗口，
  `core/edge_window.py` 按真实 `msedge.exe` 进程映像识别本次新增窗口，最大化并确认前台焦点后，以 `SendInput`
  输入固定 `edge://extensions`（等待上限 6 秒）；无法识别或聚焦则不发送按键。当前 Edge 会忽略命令行中的
  `edge://` 内部地址，普通 HTTP 不受影响，因此不能仅靠 URL 参数启动扩展页。
  普通自动登录仍使用原 `[path, url]` 参数，不进入原生导航路径。
- 打开编辑器时，原 URL 的 `has_favicon=true` 只调用 `loadCachedFavicon()` 回显，不自动采集；为 `false`
  或 URL 已修改时，才经 500ms 防抖调用 `fetch_web_quick_favicon(url, item_id)`。每个编辑会话按规范化 URL
  记录自动尝试，成功或失败都不在同会话重复请求，新会话可再次尝试；切换打开/登录模式不重新触发采集。
  `editorSession + 请求序号 + URL 快照` 丢弃迟到预览；卡片按 key 合并 Promise，并检查节点连接状态和 key，
  防止重渲染后旧响应写入。编辑器图标是“重新抓取网站图标”按钮，点击调用
  `refresh_web_quick_favicon(url, item_id)`，以 `ensure(force=True)` 仅跳过失败负缓存，不重复请求已有成功图标。
  `cacheFavicon()` 写入后按 `data-favicon-key` 同步当前 avatar，无需整页重绘，保留焦点、菜单和拖拽状态；
  后续建卡仍经 `loadCachedFavicon()` 读取同一缓存。无有效图片时统一使用 `fallbackFor()`：优先以
  `Intl.Segmenter` 取名称首个完整字素（回退 `Array.from`），拉丁字母大写，配青蓝渐变底纹；名称为空用
  `web-quick.svg`。初始渲染、缓存 miss、空 data URL 和图片 error 共用该默认态。真实 favicon 使用
  `wq-has-favicon` 去掉外层边框、背景和阴影，以 32px 直接展示；只有默认首字素保留渐变底纹。
  前端缓存最多 256 项，图片 `alt=''` 且禁止拖动。
