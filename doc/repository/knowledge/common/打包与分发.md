# 打包与分发

- 模块: 打包与分发（全局）
- 关键词: 打包、分发、纯净版、zip、PyInstaller、Nuitka、源码保护、WebView2、config.json、凭据
- 代码路径: `build.py`、`build_protected.py`、`打包纯净版.bat`、`dist/CXVPNTools`、`core/config.py`、`installer/`
- 最后验证日期: 2026-09-17
- 分支/版本: `main`

## 构建与产物

- 打包命令：`uv run --with pyinstaller python build.py`，PyInstaller onedir
  便携版，产物 `dist/CXVPNTools/`（约 110MB），必须整体分发（`_internal/`
  含全部资源与运行库）。
- 受保护打包：`uv run python build_protected.py`（不改动原 build.py 与
  `CXVPNTools.spec`，用独立的 `CXVPNTools-protected.spec`）。先把 `api.py`
  与 `core/*.py`（除 `__init__`）用 Nuitka 编成本机 `.pyd`，再交 PyInstaller：
  依赖分析仍基于 .py 源码（第三方/标准库收集不变），产物中业务模块的
  pyc 全部替换为 .pyd，带双断言防裸包。产物同为 `dist/CXVPNTools/`。
  依赖 Nuitka（.venv 内）与 MSVC Build Tools（本机已装）。日常迭代用
  build.py（快、不保护），对外交付用 build_protected.py。
- `core/app_paths.py` 将用户数据统一定位到
  `%LOCALAPPDATA%\CXVPNTools`。主数据库建立后不再扫描/合并旧安装目录的用户数据。
  首次无主库时，`build.py` 和 `build_protected.py` 在 PyInstaller 清空 `dist` 前，
  把旧目录配置、日志、浏览器会话、缓存和规则包合并到该目录。普通文件只补齐目标中不存在的内容；主 `config.json` 冲突时校验双方 JSON，
  有效版本优先，同为有效配置时按文件修改时间保留较新版本，另一版本以内容哈希区分后保存到
  `%LOCALAPPDATA%\CXVPNTools\migration-backups`。旧发布目录的 `routing/` 必须整体合并，
  不能只迁移 `routing_data` 或只依赖旧产品 LocalAppData 的 providers/history。
- fresh clone 不包含被 `.gitignore` 排除的 `.venv/`、`build_tmp/`、
  `routing-service/target/` 和 `runtime/routing/CXVPNRoutingHost.exe`，仓库当前也没有
  `pyproject.toml`、`uv.lock` 或 requirements 文件。新电脑首次打包需自行准备 `uv`、
  Python 运行依赖（当前验证为 `pywebview 6.2.1`、`pythonnet 3.1.0`、
  `Pillow 12.3.0`）以及 Rust MSVC toolchain；可将这些环境放在 D 盘的项目忽略目录，
  但仍复用系统已安装的 Python 与 MSVC Build Tools。
- 两种打包入口都会先调用 `build_runtime.build_routing_service()`：当
  `routing-service/Cargo.toml`、`Cargo.lock` 或 `src/*.rs` 新于包内
  `runtime/routing/CXVPNRoutingHost.exe` 时，用 Cargo release 模式增量构建并复制产物。
  开发机需要 rustup/Cargo 与 MSVC，目标机不需要 Rust；`routing-service/target/` 仅为构建缓存。
- 两种打包入口均通过 `build_lifecycle.py` 收敛本机重启：构建前只结束 CXVPNTools 当前及历史
  产品名进程并限时确认全部退出；结束前采集这些进程的精确安装目录，后续一并纳入便携数据迁移，
  避免漏掉工作区 `dist` 之外实际运行的副本。随后用 SQLite backup API 在 `recovery-backups` 保存
  一致性副本，并读取 LocalAppData SQLite 配置 revision/payload 摘要与
  兼容 JSON 摘要。PyInstaller 完成后、启动前再次核对摘要，只启动本次生成的
  `dist/CXVPNTools/CXVPNTools.exe`，并要求该精确子进程持续存活。旧窗口可见或同名旧进程不能
  作为新版启动成功证据。
- `main.py`、`build.py`、`build_protected.py` 在访问用户数据前通过 `core/desktop_runtime.py`
  检查文件最终路径。启动器的 MSIX LocalCache 重定向存在时，交给桌面窗口的
  `Document.Application.ShellExecute` 领取任务，并在桌面环境复核后运行；不能直接调用新建
  Shell.Application 的 ShellExecute 来替代。该过程不提升权限，不修改全局代理注册表。
- 桌面启动辅助文件只传必要路径/编码环境变量，15 秒领取期限，辅助进程退出有终态核对；
  普通构建等实际工作由辅助进程等待完成，保留构建退出码与 UTF-8 输出。最终配置摘要与新版
  `startup.log` 的主库路径、revision 必须来自真实用户目录，不从启动器的旧重定向视图判断。
- 分发包形态：`打包纯净版.bat` 生成 `dist/CXVPNTools-clean.zip`。新版用户数据不进入
  `dist`；脚本仍防御性剔除旧产物可能残留的 `config.json`、`webview_data` 和日志，
  打包前若程序在运行会自动强制关闭。

## 分发前提（目标机环境）

- 必须 Windows 10 x64 及以上（exe 为 x64，Python 3.14 不支持更老系统）。
- 正式应用需要 WebView2 Runtime；仅存在 Edge 浏览器不能作为依赖满足条件。
  安装器根据有效 Runtime 注册表版本检测并安装缺失组件；ZIP 版仍需自行准备依赖。
  [微软部署说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)
- 目标机无需 Python 或 Rust。Python 运行库随 `_internal` 分发；安装器另外携带并检测
  VC++ x64 Redistributable，低于所带版本时安装。Windows PowerShell、RAS、WMI、
  .NET Framework 4.x 使用 Windows 系统组件。
- 原生路由服务和 Mihomo 均为 Windows x64 本机程序；首次安装或二进制升级需要 UAC，后续
  日常代理启停通过 Named Pipe 完成。
- 程序运行时向 `%LOCALAPPDATA%\CXVPNTools` 写入配置、日志、浏览器会话和缓存；
  安装目录只需可读，可放在普通用户无写权限的位置。LocalSystem 路由服务的数据仍位于
  `C:\ProgramData`，不依赖当前用户登录会话。
- 未签名程序首次运行可能被 SmartScreen 拦截，杀软对 PyInstaller 产物存在
  误报可能；中文目录名/文件名在 Win10/11 正常。

## 安装包构建与依赖边界

- 入口：`installer/fetch_prerequisites.ps1` 按 `prereqs.lock.json` 获取离线依赖，
  `installer/build_installer.ps1` 查找 Inno Setup 6、验证依赖签名/哈希/大小、检查用户数据
  残留并编译 `CXVPNTools.iss`。产物是 `dist/CXVPNTools-<版本>-setup.exe` 与 `.sha256`。
- 安装器版本读取主 EXE 的 ProductVersion，并与 `core/version.py` 一致性校验；
  独立 spec 构建的产物也必须有正确的版本资源才能通过此检查。
- 受保护构建在 `write_spec` 中依据 `core/version.py` 生成 UTF-8 版本资源，写入
  FileVersion、ProductVersion、产品名和原始文件名；独立 spec 必须将该文件传给
  `EXE(version=...)`，不能沿用上次标准构建的版本文件。
- 两个官方依赖为 WebView2 Evergreen Standalone x64 与 VC++ v14 x64；Bootstrapper
  需要联网，不能替代 Standalone 的离线承诺。签名和锁定哈希在构建前校验，安装前再核对哈希。
- 安装模式为所有用户；WebView2 读取 HKLM32 的 EdgeUpdate Clients 中非零有效版本，
  VC++ 读取 HKLM64 的 VisualStudio/14.0/VC/Runtimes/x64 安装状态及最低版本。
  单一用户或管理员自己的 HKCU Runtime 记录不足以满足所有用户安装。
- 依赖安装发生在复制主程序前，每个运行进程由 PowerShell worker 限时 600 秒；
  失败、超时或安装后复检失败会停止安装。返回重启要求时不会立即启动主程序。
- 选择目录控制程序与离线安装包（prereqs 子目录）的位置；Evergreen 与 VC++ 实际运行库
  使用微软系统共享安装路径，不随产品卸载而删除。应用数据仍使用 LocalAppData。
- 卸载只处理自身安装清单，不递归删除整个 `{app}`。删除数据复选框默认关闭，静默卸载
  保留数据；服务停止/注销独立进行。服务现用路径仍为
  `%PROGRAMDATA%/CXVPNManager/RoutingService`，不是新产品名称根目录。
- 卸载使用其他管理员账号提权时，LocalAppData 指向该管理员；对话框展示实际目标路径，
  不扫描其他用户配置。实际安装、升级、依赖缺失实机与卸载行为尚待用户测试。
- 安装器固定 `AppId` 并启用 `UsePreviousAppDir`，1.0.0 及后续版本可覆盖升级；卸载检测
  `CXVPNTools` 互斥体，交互式卸载由用户选择强制终止并继续或取消，静默卸载不弹窗。
- 自动化开关默认值只用于首次创建配置；覆盖升级和重复安装沿用用户已有配置，不主动重置开关。
- GitHub 更新检查读取 Releases API；仓库没有正式 Release 时按“暂无可用更新”处理并指向
  Releases 页面。Mihomo 配置预检日志包含目标、退出码、输出长度和耗时，便于定位目标机上的
  配置或运行库问题。
- 随包 Mihomo 使用官方 `windows-amd64-compatible`（GOAMD64=v1）构建，兼容老旧或虚拟化
  CPU；核心哈希同时写入 Python 路由层和原生服务，替换二进制后必须重建两者。

## 源码可见性

- 打包产物无加密、无混淆：入口 `main.py` 的编译后代码对象直接内嵌在 exe 的
  CArchive（`main` 条目），其余 853 个模块（含全部业务模块 `api`、`core.*`）
  在 exe 内嵌的 `PYZ.pyz`（zlib 归档）中，标准库在
  `_internal/base_library.zip`（155 个 .pyc）。用 PyInstaller 自身库或
  pyinstxtractor 可一键提取全部模块，pycdc 等工具可反编译回近似源码；
  docstring 与字符串常量原样保留，逻辑完全可读。
- `ui/` 前端 JS/HTML/CSS 为明文随包分发；`clr_loader` 第三方包的 15 个
  `.py` 源码文件也随包分发。
- 如需闭源须另选方案（Nuitka 编译本机码 / Cython / PyArmor）；
  PyInstaller `--key` 仅防一键解包，密钥仍在 exe 内可提取，强度有限。
  已于 2026-08-31 采用 Nuitka 方案落地为 `build_protected.py`：业务模块变
  本机码不再可反编译；例外是入口 `main.py` 仍以字节码内嵌 exe，且 .pyd 中
  的字符串常量（接口地址、文案）依然可见。

## 脚本维护注意

- 构建前迁移输出中的“配置冲突”“已保留副本”和“已采用较新的旧版配置”是数据保全结果，
  不能在调用方静默忽略。若冲突备份失败，标准构建和受保护构建必须在 PyInstaller 清理
  `dist` 前中止；应用启动迁移则保留当前主配置并把问题写入 `startup.log`。

- `打包纯净版.bat` 按 GBK 编码 + CRLF 换行保存，勿转成 UTF-8/LF，否则
  cmd 解析错乱；echo 文本用全角括号（半角括号会闭合 if 块）。
- tar 固定为 `%SystemRoot%\System32\tar.exe`（不同机器 PATH 里的其他 tar
  参数支持不一致；系统自带 bsdtar 不支持 `--force-local`，勿加回）。脚本先
  `cd` 到 dist 用相对路径调用，避免 bsdtar 把盘符 `C:` 当远程主机。
- 创建 zip 必须带 `--options hdrcharset=UTF-8`，否则中文文件名按本机 GBK
  字节写入，非中文系统解压会乱码。
- 分发 zip 前需先退出本机运行实例；用于验证的 zip 也应按同一排除清单检查。
- `build_protected.py` 维护注意：Nuitka 4.x 在 Python 3.13+ 不支持 MinGW64，
  必须用 MSVC；Nuitka `--output-dir` 只接受 `--output-dir=` 形式；PyInstaller
  的 TOC 条目为 `(dest, src, typecode)`，src 在第二位；Nuitka 编译产物命名
  为"裸名 + 版本后缀 .pyd"，需按模块名布署回包目录。冷编译 16 个模块约
  8~12 分钟，clcache 命中后约 90 秒。
