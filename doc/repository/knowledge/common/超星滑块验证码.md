# 超星滑块验证码

## 模块信息

- 关键词：`slider_v2`、`handle_captcha`、`handle_slider`、`solve_offset`、`drag_slider`、`prepare_slider`、`Input.dispatchMouseEvent`、题型切换
- 代码路径：`core/captcha_slider.py`、`core/captcha_handler.py`、`core/browser_win.py`、`core/web_flow.py`
- 入口：`web_flow.ensure_authorized()` → `captcha_handler.handle_captcha()`
- 最后验证日期：2026-11-09
- 分支：main

## 职责与调用链

使用站点现有滑块控件完成本地图像匹配和原生拖动，不发送独立短信请求，
不改写站点验证码类型、Token 或成功结果，不调用视觉模型。

```text
ensure_authorized()
  └─ handle_captcha()
       ├─ 可见滑块 → handle_slider()
       │    ├─ prepare_slider() → 恢复窗口、同步浏览器页
       │    ├─ read_slider() → download_image() → solve_offset()
       │    ├─ PageShim.drag_slider() → NativeBrowser.drag_slider()
       │    └─ wait_result() → 通过 / 关闭 / 取消 / 仍打开 / 切换点选
       └─ 可见点选或滑块返回 None → 既有图标点选流程
```

## 稳定约束

- 用 `#eject` 内可见 `.cx_rightBtn`、拼图图片和背景识别滑块，不只看
  `window.captchaType`；站点脚本或风控切换可能使该变量与实际题型不同。
- 背景取自 `#cx_imgBg` 的 CSS URL，拼图取自 `.cx_imgBtn img`。支持同高度
  黑底拼图，剔除黑底、JPEG 边缘、黄色描边后匹配纹理；尺寸、有效点、纹理强度、
  分数及候选差距不满足阈值时拒绝提交。仅允许受限 HTTPS 验证码 CDN 图像路径，
  单次下载超时 10 秒、内容最大 1 MiB。
- 位移按显示宽度/背景原图宽度换算；按钮与拼图存在相对偏移，必须读取实际
  拼图位置校正，不能把按钮位移直接当答案。释放前再次核对题目、尺寸和位置。
- WebView2 隐藏或最小化时原生输入不能正常完成。`prepare_slider()` 在取图前
  恢复窗口并通过现有 `goToPage('browser')` 同步 UI 与 worker 可见状态。
- CDP 输入为按下、二维移动、校正、释放；不注入伪造的事件信任标记或校验数据。
- 同一浏览器只允许一个拖动任务；拖动期限 8 秒，异常/取消回原点再释放，
  清理另有 2 秒边界。UI 线程提交 CDP，worker 等待有界异步结果。
- `captcha_max_attempts` 限制为 1～10 次，自动阶段有 90 秒预算；下载/图片处理
  等阶段结束后检查预算，不再提交过期拖动。图片就绪等待最多 5 秒。
  自动失败后在原生浏览器内人工操作，默认等待 300 秒。
- 只有短信按钮进入发送/倒计时状态才继续登录；验证码窗口关闭本身不等于成功。
  站点可能拒绝轨迹并切换为图标点选，滑块返回 `None` 交回既有处理，避免无限刷新。
- 配置、数据库结构、用户登录态与点选模型配置契约不变；日志仅记录阶段、类型、
  来源主机、耗时和结果，不记录图像答案或验证 Token。

## 外部依赖与边界

- 使用已有 Pillow、pythonnet、WebView2，无新增核心依赖。
- 缓存策略见 [WebView2缓存新鲜度保障](../modules/WebView2缓存新鲜度保障.md)。
- SDK DOM、图像格式、校验策略由外部服务控制；单个通过样本不代表所有题目通过。
- 测试真实站点必须使用独立 profile、不可投递的假号码，并在网络层拦截短信接口；
  不应使用看似随机但可能属于他人的有效手机号，也不能仅靠假号码保证不触发发送。
