# 超星滑块验证码

## 模块信息

- 关键词：`slider_v2`、`handle_captcha`、`handle_slider`、`solve_offset`、`drag_slider`、`bring_to_front`、`Input.dispatchMouseEvent`、题型切换
- 代码路径：`core/captcha_slider.py`、`core/captcha_handler.py`、`core/browser_win.py`、`core/web_flow.py`
- 入口：`web_flow.ensure_authorized()` → `captcha_handler.handle_captcha()`
- 最后验证日期：2026-11-25（WebView2 取图与下载回退；拖动及人工兜底入口沿用 2026-11-24）
- 分支：fix/auto-renew-slider-captcha

## 职责与调用链

使用站点现有滑块控件完成本地图像匹配和原生拖动，不发送独立短信请求，
不改写站点验证码类型、Token 或成功结果，不调用视觉模型。

```text
ensure_authorized()
  └─ handle_captcha()
       ├─ 可见滑块 → handle_slider()
       │    ├─ read_slider() → PageShim.read_image_bytes()
       │    │    ├─ WebView2 Page.getResourceContent（优先）
       │    │    └─ download_image()：Python 默认下载 → 无代理直连回退
       │    ├─ solve_offset()
       │    ├─ PageShim.drag_slider() → NativeBrowser.drag_slider()
       │    └─ wait_result() → 通过 / 关闭 / 取消 / 仍打开 / 切换点选
       │         （自动验证未完成 → page.bring_to_front() → 等待人工拖动）
       └─ 可见点选或滑块返回 None → 既有图标点选流程
```

## 稳定约束

- 用 `#eject` 内可见 `.cx_rightBtn`、拼图图片和背景识别滑块，不只看
  `window.captchaType`；站点脚本或风控切换可能使该变量与实际题型不同。
- 背景 URL 取自 `#cx_imgBg` 的 CSS，拼图 URL 取自 `.cx_imgBtn img`。取图优先通过
  `PageShim.read_image_bytes()` 尝试调用 WebView2 CDP `Page.getResourceContent` 读取
  当前页面已加载的 Base64 图片，避免只依赖 Python 独立网络栈。2026-11-25 新版实测
  该 CDP 调用可能失败，不能作为唯一图片来源；读取不可用时回退 Python 默认下载，
  网络错误再用 `ProxyHandler({})` 直连一次；
  三种路径共用单图 10 秒期限，浏览器读取占最多 2 秒，内容最大 1 MiB。所有路径仅允许
  受限 HTTPS 验证码 CDN 图像路径，错误日志保留脱敏后的底层原因，不记录挑战 URL。
- 支持同高度黑底拼图，剔除黑底、JPEG 边缘、黄色描边后匹配纹理；尺寸、有效点、
  纹理强度、分数及候选差距不满足阈值时拒绝提交。
- 故障定位：自动续期与手动授权共用上述滑块链路。若 WebView2 网络记录中的验证码
  图片已为 HTTP 200，而 `[slider]` 在本地匹配前连续出现背景/拼图 `URLError`，说明
  失败点是 Python 独立取图，不是未调用自动滑块，也不是匹配或拖动失败。新版日志的
  `来源=WebView2/Python/Python直连` 和脱敏错误原因用于确认实际回退路径；只有出现
  “本地匹配通过，已提交拖动任务”才表示流程进入拖动阶段。
- 位移按显示宽度/背景原图宽度换算；按钮与拼图存在相对偏移，必须读取实际
  拼图位置校正，不能把按钮位移直接当答案。释放前再次核对题目、尺寸和位置。
- 自动验证期间不切换左侧菜单，也不恢复窗口：不在浏览器页时内嵌控件停放在客户区之外，
  窗口最小化或隐藏到托盘都不影响拖动。禁止用 `Visible=False` 隐藏控件，页面会进入
  `hidden` 状态，原生输入超时。机制见 [内嵌浏览器画布停放](../modules/内嵌浏览器画布停放.md)。
  只有自动验证失败转入人工等待时才调用 `page.bring_to_front()` 恢复窗口并切到浏览器页。
  窗口位置规则（2026-11-24）：显示时沿用原坐标，最小化时按 Windows 保存的普通或最大化布局恢复。
- CDP 输入为按下、二维移动、校正、释放；不注入伪造的事件信任标记或校验数据。
- 同一浏览器只允许一个拖动任务；拖动期限 8 秒，异常/取消回原点再释放，
  清理另有 2 秒边界。UI 线程提交 CDP，worker 等待有界异步结果。
- `captcha_max_attempts` 限制为 1～10 次，自动阶段有 90 秒预算；下载/图片处理
  等阶段结束后检查预算，不再提交过期拖动。图片就绪等待最多 5 秒。
  自动失败后恢复窗口并切到浏览器页，等待用户在内置浏览器人工拖动，默认等待 300 秒。
- 只有短信按钮进入发送/倒计时状态才继续登录；验证码窗口关闭本身不等于成功。
  站点可能拒绝轨迹并切换为图标点选，滑块返回 `None` 交回既有处理，避免无限刷新。
- 配置、数据库结构、用户登录态与点选模型配置契约不变；日志仅记录阶段、类型、
  来源主机、耗时和结果，不记录图像答案或验证 Token。

## 外部依赖与边界

- 使用已有 Pillow、pythonnet、WebView2，无新增核心依赖。
- 缓存策略见 [WebView2缓存新鲜度保障](../modules/WebView2缓存新鲜度保障.md)。
- SDK DOM、图像格式、校验策略由外部服务控制；单个通过样本不代表所有题目通过。
- 测试真实站点必须使用独立 profile、不可投递的假号码，并在网络层拦截短信接口；
  不应使用看似随机但可能属于他人的有效手机号，也不能仅靠假号码保证不触发发送。
