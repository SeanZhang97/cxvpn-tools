# 统一用户数据与恢复方案

日期：2026-09-14；分支：main。

## 已确认的事实

- 安装目录 `D:/develop/CXVPNTools` 与工作区打包目录中的 app_paths/config/state_store 模块实现一致，数据根目录来自当前用户 LocalAppData，不随 exe 目录变化。
- 主库为用户目录 `CXVPNTools/state.sqlite3`；`config.load()` 优先主库，`config.json` 只用于无主配置时首次迁移及提交后的兼容导出。
- 从 Codex 启动的进程实际打开了其 MSIX `LocalCache/Local/CXVPNTools` 中的旧副本；逻辑路径相同，文件最终路径不同。该视图中的主库 revision 为 5，真实用户主库 revision 为 94，后者账号与订阅完整。
- 主数据并未丢失，不执行历史恢复或覆盖。文件摘要不变只能说明构建没有改变被检查的副本，不能证明检查目标是安装版使用的主库。
- `GetCurrentPackageFullName` 在受影响子进程中仍可能返回无包身份，不能单靠包身份判断。由桌面窗口的 `Document.Application.ShellExecute` 启动的诊断进程已确认读取真实用户目录。
- 启动入口与打包入口仍会扫描旧安装目录并合并非配置文件，即使当前用户主库已经存在；该行为不符合已建立主存储后只读写用户目录的边界。

## 调用链与调整

1. `main.py -> app_paths.migrate_legacy_user_data -> Api -> config.load -> state_store`。
2. `Api.save_config` 及专用业务 API -> `config.save -> state_store.transaction`；事务成功后导出用户目录 JSON，JSON 不是第二个主存储。
3. `desktop_runtime` 在主程序、普通及受保护构建入口最早检查新建临时文件与既有主数据文件的最终路径。发现重定向时，通过桌面 Shell 领取启动请求后重新运行；桌面辅助进程仍有重定向则失败，不进入配置加载/迁移。
4. 主数据库已存在时，不再读取/合并任何旧安装目录用户数据；首次没有主库时仍兼容旧数据导入。损坏主库保持失败，不用默认值或历史 JSON 自动覆盖。
5. 启动日志记录实际用户目录、主数据库位置和读取配置版本，以运行态证据核对加载目标，禁止记录配置正文或凭据。辅助请求仅传命令路径及必要的路径/编码环境变量，不复制 Token 等环境变量；请求结束清理临时文件。
6. 不更改 Windows 代理、Codex 配置及公共配置 schema；此前 Codex 手动开启、软件代理关闭后联动关闭的改动继续保留。

## 本机数据保护

- 实际主库已经完整，保留它及旧重定向副本，不做恢复覆盖或删除。
- 打包先切换到桌面环境，再关闭旧进程、使用 SQLite backup API 备份真实主库并记录摘要；不把本机数据放入仓库或 dist。
- 新版只使用真实用户主库；旧重定向副本不参与读取、迁移或配置合并。不根据历史文件时间猜测用户选择。

## 验证与交付

- 最小离线测试：当前主库优先、安装目录配置/缓存不再合并、旧版首次迁移兼容、损坏库不回退、保存后跨目录启动读取同一配置及 Unicode。
- 使用带标记的临时用户目录扩展现有打包探针；从两个不同 exe 目录保存/读取同一份测试数据，不调用 GUI、VPN、浏览器或真实网络。
- 先语法/相关单测，再重新打包。核对主用户配置、Codex 配置摘要、产物不含用户数据、新进程启动日志中的目录和版本；配置内容与版本元数据分开核对。

Windows 文件重定向依据：[Microsoft MSIX 运行机制](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)；桌面 Shell 启动方式参考：[Microsoft 桌面 Shell 启动说明](https://devblogs.microsoft.com/oldnewthing/20131118-00/?p=2643)。
