# Codex 代理配置同步方案

日期：2026-09-12  
范围：cxvpn-tools 本机代理与用户 Codex 配置同步

## 目标与边界

cxvpn-tools 使用当前生效的 `routing.mixed_port` 生成 Codex 用户配置中的代理环境变量，并在代理成功启用、系统代理激活、端口变化、启动时有效运行以及关闭代理时维护这些字段。Codex 配置根目录使用 `CODEX_HOME`，未设置时使用 `%USERPROFILE%\\.codex`；不访问插件缓存目录，不结束 Codex 进程，也不把用户配置或快照提交到仓库。

该配置只覆盖 Codex 读取这些环境变量的进程。内置浏览器、插件独立进程及不继承 `config.toml` 的请求不在控制范围内，日志只说明边界，不宣称所有网络请求都已强制代理。

## 调用链与模块位置

- `Api.start()` 在启动自检后启动路由后台，并提交已有的待机核心复核；复核确认当前运行态后调用 Codex 同步，覆盖软件启动时代理已经有效的场景。
- `Api._apply_routing_locked()` 是所有 UI、托盘和配置恢复应用的统一提交边界。`RoutingManager.apply()` 完成启用事务后，调用 `core.codex_proxy.sync(config['mixed_port'])`；快速开启路径在 `_fast_toggle_system_proxy()` 成功回读系统代理后也调用同步。
- 关闭路径在系统接管停止并返回成功后调用 `core.codex_proxy.restore()`。关闭后进入待机核心不改变 Codex 的“代理关闭”恢复语义。
- 端口变化会随完整 `apply()` 事务进入成功分支，因此不需要 UI 单独操作配置。启动复核发现当前代理已有效时执行一次同步；发现残留代理被关闭时执行恢复。

同步模块只依赖 `app_paths.user_data_root()`、环境变量和日志回调，不依赖 UI。它负责 Codex 路径解析、目标字段定义、快照、局部 TOML 合并、原子写入与恢复判定。

## 配置合并策略

目标字段为：

- `[features] respect_system_proxy = true`
- `[mcp_servers.node_repl.env]` 的大小写敏感六组代理变量和 `NO_PROXY`/`no_proxy`
- `[shell_environment_policy.set]` 的同一组代理变量

读取时先以 UTF-8/UTF-8 BOM 读入并用 `tomllib.loads` 校验；目标文件缺失按空文档处理。写入只解析 section 头和当前 section 内的顶层键，替换目标键的整行值；不存在的 section 或键追加到对应 section 末尾。注释、空行、其他键、其他 MCP section 和表结构保持原文。目标字符串使用 TOML 基本字符串双引号并转义反斜杠、双引号和控制字符。

生成候选内容后再次用 `tomllib.loads` 校验；校验失败、原文件解析失败、目录或临时文件写入失败时不调用 `os.replace`，原文件保持不变。候选文件以 UTF-8 写入、`flush` + `fsync` 后原子替换，并尽力 `fsync` 所在目录。

## 快照与恢复策略

首次修改任一字段前，将该字段是否存在及原始 TOML 值保存到 `%LOCALAPPDATA%\\CXVPNTools\\codex_proxy_snapshot.json`（通过 `app_paths.user_data_root()`），同时保存本工具最后写入值。快照只含目标字段和值，不含完整 config.toml。

同步时更新快照中的 `last_written` 和 `mixed_port`。关闭时仅恢复当前文件中仍等于 `last_written` 的字段；字段被用户改过、section 被删除或值已不同则保留用户内容，并记录字段路径警告。恢复完成后删除已恢复字段的快照；仍有用户改动字段时保留快照以便后续人工处理。

快照和配置文件均通过临时文件原子替换。快照损坏或版本未知时不覆盖用户配置，记录警告并跳过恢复；下次同步可建立新的受控快照。

## 失败处理与日志

日志记录请求提交、后台执行、成功、跳过、失败及耗时，包含阶段和异常类型；不记录完整配置、Token、Cookie、密码、API Key 或代理配置文件内容。成功同步提示“需要重启 Codex 才能让已运行进程重新加载”，不自动结束 Codex。

代理事务成功但 Codex 写入失败时不回滚已经成功的路由事务，返回原路由结果并写入可定位警告；关闭恢复失败同样不改变 Windows 系统代理快照逻辑。系统代理注册表仍由现有 `proxy_guard`/原生服务事务维护。

## 验证计划

新增纯离线 `tests/test_codex_proxy.py`，使用临时 `CODEX_HOME` 和用户数据目录覆盖：缺少文件创建、完整配置局部更新、缺少 section 补齐、端口从 17890 变更、幂等同步、关闭恢复、用户手动改值保护、损坏 TOML、权限/写入中断原文件不变，以及中文/UTF-8 保留。验证只读本地文件，不访问真实 Codex、网络、服务或注册表。

实现后先执行 Python 语法检查和该测试文件；再按仓库规则停止旧进程、运行 `uv run --with pyinstaller python build.py`，核对 `%LOCALAPPDATA%\\CXVPNTools\\config.json` 保留、发行目录未混入用户配置或快照、产物时间戳和新版进程状态。最后更新 changelog、知识库索引和相关模块知识。
