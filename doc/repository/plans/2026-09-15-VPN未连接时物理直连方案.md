# VPN 未连接时物理直连

日期：2026-09-15 | 分支：main | 状态：已实施、测试、打包并启动；当前已连接网络验证通过

## 行为与调用链

用户要求规则所选 VPN 未打开时走物理网络，连接后自动恢复 VPN。
现有 worker 的连接快照供 UI 使用，具有刷新延迟；核心连接前已经调用原生路由服务。
在该现有链路决定本次连接出口，避免再增加一套后台配置重载和 GUI 状态同步。

1. 服务从已应用配置读取 PHYSICAL 接口，并验证当前 VPN 网卡是否存在且已连接。
2. 未连接时，验证物理接口及该地址族的路由，返回物理接口名；不创建 VPN 路由。
3. 已连接时维持原 VPN 路由准备；目标超时、权限/IPC/路由错误不触发物理回退。
4. 核心按服务返回接口绑定本次 TCP/UDP socket。UDP 后续新目标若需切换接口则结束旧关联，
   由后续新关联重新选择；已有 TCP 连接不迁移。每次新连接重新核对状态。

## 健壮性与兼容

- 复用受限 IPC、进程世代校验、租约、取消、回收和用户路由保护，不修改用户规则或 VPN 配置。
- 状态查询错误与已断开分开处理，查询错误明确失败；IPv6 缺少源地址不等同整个 VPN 断开。
- 返回实际接口为 IPC 新契约，升级核心能力与服务版本，旧核心不能静默继续使用旧语义。
- 仅更新现有未连接提示与相关说明，不增加宣传性 UI。
- 升级/事务失败沿用成对回退；不迁移已有连接，不因网站超时任意改出口。

## 验证

相关离线测试覆盖断开、恢复、多 VPN 独立状态、状态查询失败、路由失败、物理接口失败、
UDP 接口变化、取消和 Unicode；构建定制核心、原生服务和应用。
真实验证只在当前 VPN 状态下检查网页和实际出口，不主动断开其它 VPN 或修改路由配置。
完成打包、真实用户配置核对和新版启动；未具备的真实网络场景如实保留验收边界。

实际结果：Python 75 项、Rust 41 项、Go 5 项相关测试通过；Windows 缺失 VPN 的物理接口
选择测试通过。当前 VPN 保持连接，office/mooc1 根地址 HTTP 连通，未主动断开 VPN。
