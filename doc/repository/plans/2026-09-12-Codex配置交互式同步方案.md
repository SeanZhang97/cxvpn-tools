# Codex 代理配置交互式同步方案（重新设计）

日期：2026-09-12
范围：cxvpn-tools 本机代理与用户 Codex 配置同步的正式功能整合

## 背景与重新设计动机

上一版实现（`core/codex_proxy.py`）只在代理启停链路中做后台自动同步，UI 仅有
只读状态摘要。用户期望把该能力升级为正式功能：

1. 在软件内提供「立即同步」入口，每次触发时把代理配置写入 Codex 配置文件；
2. 提供「还原」入口，恢复本工具改写过的字段；
3. 提供「查看配置文件」入口，在软件内查看 Codex 配置文件内容。

自动挂钩（代理有效后校正 / 代理关闭后恢复 / 启动校正）继续保留，成为手动
入口之外的兜底机制。

## 目标与边界

- 代理端口来自 `routing.mixed_port`，同步时动态读取当前生效配置，禁止写死 17890。
- Codex 配置目录：优先 `CODEX_HOME`，未设置时使用 `%USERPROFILE%\.codex`；
  不访问 Codex 插件缓存目录，不自动结束 Codex，只提示重启后生效。
- 不修改 Windows 全局代理注册表逻辑；现有系统代理启停与快照恢复行为保持兼容。
- 该配置只覆盖 Codex 读取这些环境变量的进程。内置浏览器、插件独立进程及不继承
  `config.toml` 的请求不在控制范围内；UI 与日志只说明边界，不宣称所有网络请求都
  已被强制代理。

## 调用链与模块位置

### 手动链路（新增）

```
ui/app.js 按钮点击
  → window.pywebview.api.sync_codex_proxy() / restore_codex_proxy() / read_codex_config()
    → api.Api（校验参数、记录生命周期日志）
      → core.codex_proxy.sync(mixed_port) / restore() / read_config()
        → 快照 codex_proxy_snapshot.json（%LOCALAPPDATA%\CXVPNTools\）
        → 原子改写 CODEX_HOME\config.toml
```

- `sync_codex_proxy()` 从 `_cfg_get().routing` 经 `routing.normalize_config` 取当前
  `mixed_port`，不接收 UI 传入端口。
- `restore_codex_proxy()` 幂等：无快照或快照为空时直接返回成功。
- `read_codex_config()` 只读并返回原文（UTF-8/BOM 兼容），返回时不写日志正文，
  日志仅记录路径存在性、行数与耗时。

### 自动链路（保留）

- `Api.start()` 启动自检与待机核心复核确认代理有效 → `_sync_codex_proxy` 校正。
- 路由启用事务 / 系统代理快切成功后 → `_sync_codex_proxy`。
- 代理关闭成功后 → `_restore_codex_proxy`。
- 路由模块继续只调用 `core.codex_proxy`，UI 不直接操作 Codex 配置。

## 配置合并策略

沿用上一版并保持不变：

- 目标字段：`[features] respect_system_proxy = true`；`[mcp_servers.node_repl.env]`
  与 `[shell_environment_policy.set]` 下大小写敏感六组代理变量与 `NO_PROXY`/`no_proxy`。
- 逐行 patch：仅替换目标 section 顶层目标键所在行的值；缺失 section/键追加；
  注释、空行、无关键、其他 MCP section、表结构保持原文。
- 目标字符串使用 TOML 基本字符串双引号并转义反斜杠、双引号与控制字符。
- 生成候选文本后用 `tomllib.loads` 校验；校验失败、原文件解析失败、写入失败时
  不调用 `os.replace`，原文件保持不变。候选以 UTF-8 写入、`flush` + `fsync` 后原子替换。

## 快照与恢复策略

沿用上一版并保持不变：

- 首次修改任一字段前，把该字段是否存在及原始值保存到
  `app_paths.user_data_root()/codex_proxy_snapshot.json`，同时记录 `last_written`、
  `mixed_port` 与 `config_path`。快照不含完整 config.toml。
- 恢复时仅处理当前值仍等于 `last_written` 的字段；用户手动改过的字段保留并记录
  字段路径警告。恢复完成后删除已恢复字段；仍有用户改动字段时保留快照并暴露给 UI。
- 快照损坏或版本未知时不覆盖用户配置，记录警告并跳过恢复。

### 状态摘要（新增，供 UI 渲染）

`core.codex_proxy.status()` 返回：配置文件路径与是否存在、快照是否存在、
托管字段总数、`last_written` 端口、偏离 `last_written` 的字段列表（用户已修改或
从未同步）、当前端口与 `last_written` 是否一致。UI 据此渲染按钮可用性与摘要文案。

## UI 设计

Codex 页面（设置型页面）包含两张卡片：

1. **代理配置卡**：当前 mixed-port、配置文件路径、状态摘要（是否已同步/用户是否
   修改过托管字段/需要重启 Codex 的提示）。
2. **操作卡**：
   - 「立即同步到 Codex」按钮：调用 `sync_codex_proxy()`，成功后 toast + 刷新状态；
   - 「还原 Codex 配置」按钮：先确认（复用 confirmmodal），再调用 `restore_codex_proxy()`；
   - 「查看配置文件」按钮：打开只读弹窗，展示 config.toml 原文。
   - 边界说明文字：仅覆盖 Codex 读取上述环境变量的进程；内置浏览器与插件独立进程
     不受控制；变更后需要重启 Codex 生效。

### 查看弹窗（新增 modal）

- 复用全局 modal 结构与深色滚动条规范，内容区为等宽字体的只读 `<pre>`。
- 原文通过 `read_codex_config()` 获取后**在前端渲染副本**：疑似敏感键
  （值中包含 token/key/secret/password/authorization/cookie 等模式的键）默认打码，
  提供「显示敏感值 / 隐藏敏感值」切换；后端日志不记录任何配置正文。
- 文件不存在时展示占位提示，不创建文件（查看是只读操作）。

## 失败处理与日志

- 手动同步/还原遵循现有失败语义：失败返回 `{ok: False, warning}`，由 UI toast 展示，
  `run.log` 记录阶段、异常类型与耗时；不覆盖原文件。
- 手动同步不依赖代理是否启用；用户可在离线时预先写入 Codex 配置。
- 日志继续遵守脱敏规则：不记录完整 config.toml、Token、Cookie、密码、API Key；
  读取正文的行数与字节数可以记录。

   关闭恢复、用户改值保护、损坏 TOML、权限/写入中断原文件不变、中文与 UTF-8 保留

   敏感内容、`get_codex_status` 包含快照状态摘要。

   `%LOCALAPPDATA%\CXVPNTools\config.json` 保留、产物时间戳、启动新版进程。
