# 无效手动代理修复回读优化

- 日期：2026-10-10
- 功能：TUN 启用前无效 Windows 手动代理的修复与状态确认
- 分支：main

## 需求与问题

TUN 启用前发现 `ProxyEnable=1`、`ProxyServer=:`，自动修复因回读不一致而中止。
同一时刻的审计备份中 WinINet flags 已为直连，说明注册表字段与 WinINet 状态不能相互替代。
原实现先回读、通过后才刷新，且未处理 WinINet 已关闭但注册表仍残留空地址/冒号的情况。
原日志未记录修复后字段差异，无法由历史日志确定具体失败项。

## 涉及文件与设计

- `core/proxy_guard.py`：WinINet 设置显式保留 PAC/绕过；先通知设置变更并刷新再回读。
  仅在 flags 已达到目标、保留字段未变化且端点仍为空/冒号时，增加一次受保护的注册表残留清理。
  清理前复核四字段及 flags，第二字段写入前再次保护已变化的设置；清理后严格刷新和回读。
- `core/routing.py`：接入脱敏回读日志，失败日志补充执行耗时，保留原启用门控与失败返回。
- `tests/test_invalid_proxy_repair.py`：覆盖直连 flags 与注册表不一致、刷新顺序、残留清理、
  仅手动代理位、合法端点接管、保留字段变化、写权限失败、有限失败及 Unicode 输出边界。
- `doc/repository/knowledge/modules/系统代理残留清扫.md`：更新当前修复流程与日志判断边界。

## 影响与保护边界

- 仅改变已有无效手动代理修复链，包括 TUN 启用前、代理关闭后及待机核心复用前。
- 合法代理、已关闭状态、命名 RAS/VPN 连接不进入修复；不探测真实网络。
- 仍先保存原始快照；备份失败、观察到并发改动、刷新失败或回读不一致均不得报告成功。
- Windows 注册表两字段写入不具备跨软件原子性；前后检查降低覆盖风险，不能阻止检查后的外部改写。
- 日志不包含代理服务器正文、凭据、绕过列表或 PAC URL；诊断输出失败不能中断修复。
