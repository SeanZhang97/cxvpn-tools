# 打包脚本强杀重启残留托盘残影

- 日期：2026-10-14
- 分支：main
- 现象：开发迭代中 `build.py` 重新打包并自动重启新版后，托盘（含隐藏图标区）出现多个 CXVPNTools 残影图标，鼠标划过才逐个消失。
- 根因：升级安装器流程的残影此前已修复（`prepare_update_exit` 预隐藏图标），但打包脚本走的是另一条路——`build_lifecycle.stop_running_apps()` 用 PowerShell `Stop-Process -Force` 从外部强杀运行实例，进程死亡时 NotifyIcon 仍可见，托盘留残影。外部强杀进程自身无法补救，必须先让应用自己退出。
- 涉及文件：`core/windows_desktop.py`、`build_lifecycle.py`、`tests/test_windows_desktop.py`、`tests/test_build_lifecycle.py`。
- 设计：
  - **应用端优雅关闭通道**：`DesktopController.start()` 在托盘就绪后创建命名事件 `Local\CXVPNTools.Shutdown.v1`（`EventWaitHandle` AutoReset）并启动 `tray-shutdown-watch` 守护线程监听；收到信号调用新公开方法 `request_exit()`——经 `_invoke` 送上 UI 线程执行 `_begin_exit()`（从 `_on_exit` 提取的托盘"退出"同路径：置 `_exiting`、`_dispose_native()` 清理托盘图标，再起线程执行 `on_exit` 完整收尾：api.shutdown、worker join、窗口销毁）。`dispose()` 关闭事件句柄。事件创建失败只记日志不影响启动；旧版本进程没有该事件时外部信号自然失败并走强杀兜底。
  - **打包端先礼后兵**：`stop_running_apps()` 的 PowerShell 先 `EventWaitHandle.OpenExisting` 打开关闭事件并 `Set()`，轮询最多 8 秒等运行实例自行退出（输出 `CXVPN_GRACEFUL_SIGNAL=1` 供 Python 侧记录）；超时或事件不存在（旧版本）才 `Stop-Process -Force` 兜底，之后保留原 15 秒退出确认。PowerShell 总超时提高到 45 秒。`build.py`、`build_protected.py`、`build_release.py` 共用该函数，全部受益。
- 验证：`tests.test_windows_desktop` 30 通过（新增：`request_exit` 清理图标并触发 on_exit、重复调用幂等、关闭监听线程收到信号触发 `request_exit`、已退出时监听线程不再等待、`dispose` 关闭事件句柄）；`tests.test_build_lifecycle` 5 通过（新增：脚本包含事件 OpenExisting+Set 且优雅等待先于 Stop-Process、优雅信号标记解析）；`tests.run_business_offline` 223、`tests.run_proxy_lifecycle_offline` 221、`tests.run_routing_offline` 349 通过 1 预期跳过、`tests.test_build_branding` 7、`tests.test_build_release` 13 全部通过。
- 打包：`uv run --with pyinstaller python build.py` 重新打包；本次构建杀掉的是尚无监听器的旧实例（仍会留最后一个残影，鼠标划过托盘即可清除），之后的每次打包重启都会先优雅退出不再产生残影。构建后可实测：对新版进程 `Set` 关闭事件，进程应在数秒内退出且托盘图标即时消失。
