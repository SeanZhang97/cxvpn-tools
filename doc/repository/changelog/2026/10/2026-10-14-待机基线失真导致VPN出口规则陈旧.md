# 待机基线失真导致 VPN 出口规则陈旧

- 日期：2026-10-14
- 分支：main
- 现象：有序域名规则 `chaoxing.com → vpn:中经云pptp` 已启用且 VPN 已连接，浏览器请求仍从物理出口 IP 发出，超星返回「IP地址未认证」。
- 根因：`_start_standby_runtime` 用生成时的 VPN 状态把 `vpn:` 出口固化为 PHYSICAL（VPN 断开期间生成的待机配置），但安装成功后不更新 `_runtime_vpns` 基线；快切开启「复用常驻 Mihomo，不重载配置」激活该陈旧配置；VPN 在 worker 15 秒稳定窗口内重连，"当前状态 == 失真基线"使差分逻辑静默放弃，陈旧 PHYSICAL 规则永不修复。系统代理入口与排除逻辑（chaoxing.com 不在 ProxyOverride）工作正常，问题全部在配置生成基线失真。
- 涉及文件：`core/routing.py`、`core/routing_vpn.py`、`api.py`、`tests/test_vpn_routes_config.py`、`tests/test_routing_vpn.py`、`tests/test_proxycore.py`、`tests/test_routing_auto_policy.py`。
- 设计：待机核心安装成功后记录 `_runtime_vpns = _vpn_connection_signature(vpns)`，恢复"基线 == 常驻配置内嵌 VPN 状态"不变量（安装失败保留旧基线）；`apply()` 快切开启前复核目标 VPN 当前状态与基线（与自动网卡复核共用一次 fresh 快照），不一致时降级为完整应用重新生成；基线未知或无 `vpn:` 出口时不扫描，沿用 RoutingVpnWorker"基线缺失"对账兜底。
- 可观测性：服务二进制与随包运行时哈希不一致时 worker 会持续停摆、启动对账也会以"与配置一致"跳过恢复，两层均无任何日志。RoutingVpnWorker 对不兼容态限频（30 分钟）留痕停摆原因、恢复兼容后重置限频；启动对账检测 `service_compatible is False` 时输出"联动暂停、完整应用将提权升级"提示。
- 追踪：首次打包后修复未即时生效——运行中服务二进制（v1.3.4 提权安装）与随包 host 哈希不一致，`_compatible` 拒绝后 worker 静默停摆。按 `ensure_installed` 同路径提权升级服务（`--install --owner-sid`）后，worker"基线缺失"对账一次重建规则。`routing-service` 源码自 9-29 未变更，随包旧 host 与已装服务同源仅构建哈希不同，无需重编。
- 顺手修复：`test_proxycore` 快切夹具 `_verify_runtime_egress` 改为返回空列表（3ac2024 引入真实调用后裸 Mock 不可迭代，两用例自该提交起离线套件即红）；`test_routing_auto_policy` 子进程 UTF-8 用例在离线 Popen 守卫生效时跳过，编码回归仍在套件外执行。
- 影响：不改变配置 schema、系统代理写入、Go overlay 与原生服务协议；快切开启在存在 `vpn:` 出口且基线已知时增加一次环境快照（约 1–2 秒）。
- 验证：`tests.run_routing_offline` 347 通过 1 跳过、`tests.run_proxy_lifecycle_offline` 221 通过、`tests.run_business_offline` 223 通过；`tests.test_routing_auto_policy` 套件外独立运行 13 通过（真实子进程编码回归保留）。
- 打包：两次普通构建成功，主库配置与兼容 JSON 摘要核对通过（revision=324）。实测闭环：提权升级服务后 worker 对账成功，Mihomo Controller 实时规则恢复 `DOMAIN-SUFFIX,chaoxing.com → VPN-1`（授权入口 `remote.chaoxing.com` 按设计保持物理直连），经 mixed-port 实际请求 chaoxing.com 主机返回 200 且连接命中 `chains=['VPN-1']`；第二次构建的新版启动后"基线缺失 → 对账成功"自愈复现。
- 边界：未验证 TUN 模式快切（TUN 无快切路径）；未重编 `routing-service`（源码未变更）；超星业务 API 的最终返回以用户浏览器复测为准，代理侧以实时规则与连接链路命中为准。
