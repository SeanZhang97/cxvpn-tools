# 升级强杀残留托盘残影图标

- 日期：2026-10-14
- 分支：main
- 现象：自动升级重启后，Windows 托盘同时出现两个相同的 CXVPNTools 图标；鼠标划过残影或重启 Explorer 后才消失。
- 根因：升级安装器（Inno `PrepareToInstall`）用 `taskkill /F /IM "CXVPNTools.exe"` 强杀旧进程。进程死亡瞬间仍处于 `Visible=True` 的 `NotifyIcon` 会以残影形态留在托盘，直到鼠标划过才被 Explorer 清除；随后新版启动创建新图标，形成"两个图标"。`DesktopController.dispose()` 从未获得执行机会，`windows_desktop.py` 中已有的兜底注释（"避免 NotifyIcon 残留到进程退出、鼠标划过才被 Explorer 刷新移除"）说明该失败模式已知，但升级强杀路径完全绕过了它。
- 涉及文件：`core/windows_desktop.py`、`api.py`、`tests/test_windows_desktop.py`、`tests/test_api_app_update.py`。
- 设计：提交升级成功（`apply_app_update` 拿到守护结果）后立即 `DesktopController.prepare_update_exit()`——把 `NotifyIcon.Visible` 置 False 并抑制关闭到托盘。图标不可见后强杀不再产生残影；抑制关闭到托盘是因为等待安装期间托盘已无图标，用户点关闭若仍藏入托盘将无法再唤起应用，此时必须真退出（guard 是独立进程，应用提前退出不影响安装，安装器 `StopRunningApplication` 的互斥检查兼容"应用已自行退出"）。安装监控线程在 failed/timed_out/restart_required/监控超时等"旧版仍在运行"的终态调用 `restore_from_update_exit()` 恢复图标与关闭到托盘；completed 终态时旧进程已被杀，监控代码不再运行，无需恢复。
- 时效边界：残影来自"被杀的旧版本"，修复必须存在于旧版本进程内。因此从 v1.3.5（无修复）升级到带修复版本的**这一次**仍会出现两个图标；从带修复版本起的后续升级不再复现。
- 验证：`tests.test_windows_desktop` + `tests.test_api_app_update` 42 通过；`tests.run_business_offline` 223 通过；`tests.test_app_update` + `tests.test_app_update_hardening` 44 通过；`tests.run_proxy_lifecycle_offline` 221 通过；`tests.run_routing_offline` 347 通过 1 预期跳过。新增用例覆盖：提交成功隐藏托盘、提交失败不隐藏、托盘预清理异常不阻断升级、failed/超时恢复托盘、completed 不恢复、关闭到托盘抑制与恢复、图标可见性翻转。
- 打包：`uv run --with pyinstaller python build.py` 重新打包并自动启动新版；真实升级链路（旧版强杀 → 新版单图标）需在下一次版本发布时实测确认。
