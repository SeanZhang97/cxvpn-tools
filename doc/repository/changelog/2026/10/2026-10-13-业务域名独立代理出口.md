# 业务域名独立代理出口

- 日期：2026-10-13
- 分支：main（工作区，未提交）

## 需求与设计复查

原有出口按订阅或聚合池选点，同一订阅的多个业务缺少独立命名和规则绑定入口。
新增命名代理出口、ChatGPT/GitHub 初始规则集及自定义规则集，复用一个 Mihomo 核心和原有配置事务。
复查补齐规则优先级、共享第三方域名误匹配、排除后缀、节点失效、引用删除保护及旧配置兼容。

## 涉及文件

- `core/routing_business.py`：独立模块承载规范化、规则展开、精确节点组、回读校验及模板。
- `core/routing.py`、`core/config.py`、`core/routing_rules.py`、`core/config_maintenance.py`：schema 10、规则生成、命中解释、绕过校验及备份差异。
- `ui/routing_business.js`、`ui/routing.js`、`ui/index.html`、`ui/routing_rules.css`：规则页编辑器、节点搜索、动态自定义下拉和共享保存入口。
- `ui/proxy.js`、`ui/routing_activity.js`：首页默认出口语义、代理依赖判断和实际连接链名称。
- `tests/test_routing_business*.py`、`tests/run_business_offline.py`、`tests/test_ui_routing_business.js` 及既有 schema/UI 测试：直接相关验证。
- `tests/fixtures/business_preview.html`：使用虚构节点的人工视觉验收入口。

## 关键边界

- 同一订阅可以创建多个固定节点出口；不修改订阅和聚合原有选点。出口节点缺失时 REJECT，不自动改用其它节点或物理直连。
- 普通用户规则优先于业务规则集；排除域名继续匹配后续规则；全局模式跳过业务规则集。
- 模板仅主要业务域名，用户确认添加后保存为可编辑清单；不自动更新真实配置、不联网拉取模板、不承诺完整业务覆盖。
- 复用原有保存/运行事务及回滚；不新增数据库结构、依赖、代理端口或 Windows 服务能力。
- UI 使用既有自定义 select 和全局深色滚动条。新增编辑器独立文件，避免继续把完整功能堆入已有大文件。
- routing schema 升至 10，旧程序不支持新配置；SQLite schema 不变。默认未配置任何新规则，不自动替用户选择节点或改变流量。
