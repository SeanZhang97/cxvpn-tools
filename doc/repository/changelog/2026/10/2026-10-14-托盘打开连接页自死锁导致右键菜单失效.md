# 托盘打开连接页自死锁导致右键菜单失效

- 日期：2026-10-14
- 分支：main
- 现象：点击托盘右键菜单的"打开连接页"后，主窗口冻结，再右键托盘图标永远打不开菜单，只能重启应用。
- 根因：`DesktopController.open_page` 把"显示窗口 + 页面导航"整体经 `_invoke` 送上 UI 线程执行；页面导航即 `win.evaluate_js`。pywebview（edgechromium.py:136-165）的 `evaluate_js` 是同步阻塞模式：`webview.Invoke` 排队 `ExecuteScriptAsync(...).ContinueWith(回调, syncContextTaskScheduler)` 后 `semaphore.acquire()` 等待回调。`syncContextTaskScheduler` 在 UI 线程捕获（edgechromium.py:105），回调必须回到 UI 线程才能释放信号量——而调用者正阻塞着 UI 线程等这个信号量，构成自死锁。托盘菜单项 Click 处理器本就运行在 UI 线程，一旦死锁，WinForms 消息循环停摆：窗口冻结、托盘右键菜单（依赖 UI 线程泵消息）永久失效。
- 涉及文件：`core/windows_desktop.py`、`tests/test_windows_desktop.py`。
- 设计：`open_page` 拆分职责——`_show_native()` 仍留在 UI 线程（`_invoke` 投递），页面导航改由独立后台线程（`tray-open-page`）执行。`evaluate_js` 自身会经 `webview.Invoke` 回 UI 线程做实际执行，从非 UI 线程调用是它设计内的正常用法（`notify_desktop_action` 一直在后台线程这样调用）。导航失败在 `_navigate` 内捕获并记日志，不影响 UI 线程。项目内全部 `evaluate_js` 调用点仅 main.py 两处，另一处（`notify_desktop_action`）始终在托盘后台线程调用，安全。
- 验证：`tests.test_windows_desktop` 23 通过（新增：UI 线程内联执行时窗口已显示但导航不在 UI 线程运行、后台线程执行导航、导航异常记日志不抛出）；`tests.run_business_offline` 223 通过、`tests.run_proxy_lifecycle_offline` 221 通过、`tests.run_routing_offline` 347 通过 1 预期跳过、`tests.test_build_branding` 7 通过、`tests/test_ui_polish.js` 通过。
- 打包：`uv run --with pyinstaller python build.py` 重新打包并自动启动新版；死锁场景需在新版托盘实测"打开连接页"后右键菜单仍可打开。
