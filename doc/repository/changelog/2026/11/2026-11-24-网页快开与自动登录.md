## 需求概述

用户需要“带自动登录的收藏夹”：普通网址用系统默认浏览器打开；自动登录项保存账号、密码和可选的
2FA 管理账号，用 Edge 打开并自动完成登录，首个平台为亚信 AIS-iFort（`https://10.0.34.53/`，
只有 IP、证书警告由用户手动处理）。收藏夹支持多级文件夹、同层混排拖拽、跨文件夹搜索。
显示名只改展示层为 CX Toolkit，内部标识 `CXVPNTools`（数据目录、互斥量、管道、安装器升级路径）不变。

## 关键设计

- 条目分“仅打开网页”和“打开并自动登录”；`platform_for_url()` 要求 origin 与登记站点完全一致
  （协议、主机、端口），子域、伪造主机、非 https 一律退化为普通网址，登录字段只对匹配站点开放。
- 密码用 DPAPI 按“固定熵 + 条目 ID”加密后存 BLOB；列表与全局 UI 快照只返回 `has_password`。
  自动登录密码在管道领取时解密并交给同源扩展；2026-11-25 起编辑器通过 `get_web_quick_item_password`
  按条目单独读取密码并默认掩码回显，眼睛按钮可显隐，关闭弹窗即清空；该接口不返回动态口令。
  `otp_account_id` 删除 2FA 账号时 `ON DELETE SET NULL`。
- 文件夹最多 16 级、条目总数上限 2000；文件夹与条目在同一父级共用 `position`，
  禁止移动到自身或后代；级联删除前由 `web_quick_folder_summary` 返回子文件夹/网址/自动登录条数供确认。
- 任务状态机：`pending`（120 秒等待扩展领取）→ `claimed`（90 秒等待结果）→
  `success|failed|timeout|expired|cancelled`；每次打开只提交一次登录，不自动重试；
  同平台有进行中任务时拒绝重复提交；`_changes` 计数并入 `wait_ui_state` 的 `web_quick_revision`，
  界面据此增量刷新。
- 本机链路：扩展内容脚本只在匹配站点运行 → service worker 校验来源页 origin 后
  `chrome.runtime.sendNativeMessage('com.cxvpntools.web_quick', …)` → 主程序以
  `chrome-extension://<id>/` 参数进入宿主子进程，把定长帧（4 字节小端长度 + UTF-8 JSON，≤64KB）
  转发到 `\\.\pipe\CXVPNTools.WebQuick.v1` → 管道仅当前用户可访问并校验对端进程映像。
  消息仅 `hello`、`claim {platform, href, login}`、`report {run_id, state, detail}`；
  领取时服务端再次校验 `href` 属于登记站点，凭据只经此通道发放，不写日志。
- iFort 适配：登录表单稳定后领取任务，原生 setter 写入并派发 `input`/`change`；
  出现动态口令框时填入 2FA 当前码再提交；`sessionStorage token` 视为成功；
  `el-message--error`、USBKey 选择框、人工弹窗视为失败原因；滑块只提示人工处理并延长等待，
  不自动识别；已是登录状态时以 `login: false` 领取并直接结束。
- 扩展默认仅打包版可用（`extension.available` 依赖 frozen 与随包 manifest），manifest 固定 `key`
  使扩展 ID 稳定；主程序启动时把宿主清单写到用户数据目录并登记
  `HKCU\SOFTWARE\Microsoft\Edge\NativeMessagingHosts\com.cxvpntools.web_quick`，内容未变化不重写；
  卸载时删除该注册表项与清单文件，其余用户数据按卸载选项处理。
- 网页快开不参与配置 revision、不进入兼容 JSON 导出与加密备份；2FA 账号不随条目导出密码。
- 界面沿用既有自定义下拉（`RoutingWorkspace.enhanceSelect`）与深色滚动条规范；
  面包屑 `.wq-path` 显式覆盖全局 `nav`/`nav button` 规则，避免继承侧栏纵向布局与按钮尺寸。
- 2026-11-25 增量：`open_web_quick_extensions()` 固定启动 Edge 访问 `edge://extensions`；扩展在
  安装/更新、Edge 启动和每分钟 alarm 时握手，150 秒无心跳判定未连接，只有状态翻转写日志并增加 revision。
  前端用 `refreshPending` 补偿请求或排序期间的状态变化；侧栏与标题改为浏览器窗口 + 闪电图标，
  标题区、卡片、扩展安装区和编辑弹窗完成视觉整理，不改其他业务页面。
- 拖入文件夹：新增 `move_entry()` 独立事务，文件夹主体为移入区、边缘保持同层排序；移动追加目标末尾，
  同父级 no-op，保留其他顺序、子树和凭据，后端校验循环与 16 层深度。`TwoFactorOrder` 以可选 `into`
  支持该行为，2FA 和键盘路径不变；drop 重解析目标，busy 后权威刷新并恢复焦点。
  拖出复用同一事务：面包屑“全部”传 `null` 移到根目录，祖先按钮移到对应层；当前层、同父级、自身、后代及
  空白区域不接受投放。控制器以只读 `draggingKey()` 暴露鼠标会话，路径 drop 先 cancel 再移动，成功后聚焦
  目标卡片或动态面包屑按钮。
- 扩展连接与启动修正：日志证实原生宿主和 `claim/report` 可成功通信但长期没有 `hello`，因此合法业务消息
  现在也刷新连接状态，伪造 origin/平台或错误 payload 不刷新。实机对照证明当前 Edge 接受普通 HTTP
  命令行地址但忽略 `edge://` 内部地址，HTTP 跳转也被拦截，因此新增 `core/edge_window.py`：创建空白新窗口，
  按真实进程映像识别本次窗口，最大化并确认前台焦点后以 `SendInput` 输入固定内部地址；未识别或未聚焦不输入。
  普通自动登录参数不变，不使用 kiosk、独立 profile 或证书绕过。解压扩展磁盘文件更新后仍需重新加载。
- 多平台接入：扩展版本升至 1.1.0，固定 key 不变。`CXWebQuickPlatforms` 按平台注册 adapter，后台同时校验
  平台 ID 与标签页 origin，新增 `jumpserver=http://192.168.1.51` 与 `gitlab=https://10.0.26.27`，不升级 schema。
  JumpServer 使用 `#id_username/#password` 整页加密 POST，GitLab 使用 `#user_login/#user_password` 整页 POST；
  两者分别按离开登录路由和 `body[data-page]` 判定成功，支持 OTP 与错误识别。
- 整页任务续接：`claim` 可选 `run_id`，只接受同平台、同源、claimed 原任务；`login:false` 直接完成，
  继续登录只续发 OTP，不重复发放账号密码。`Store.otp_account()` 不解密密码，跨平台 report 返回 forbidden，
  未知/伪造/非 claimed 续接返回 `invalid_resume`。内容脚本以 sessionStorage 保存 run key，结束后清理。
- favicon：`web_quick_favicon.py` 以 origin 摘要缓存，解析首页 link icon 并回退 `/favicon.ico`；
  8 秒总超时、重定向/候选/字节/像素受限，Pillow 转码为 64px PNG，拒绝 SVG 与 HTTPS 降级。
  成功缓存 7 天、失败 10 分钟、最多 256 个 PNG，不升级 schema、不把 Base64 放进整表响应或增加 revision。
  编辑器 500ms 防抖并用会话/序号/URL 防竞态，卡片只读缓存且失败回退内置图标。
- favicon 证书与重试修正：实际日志证实请求在收到字节前以 `URLError` 失败并进入 10 分钟负缓存。
  经用户确认，只有 IP 字面量发生明确主机名不匹配时才以独立 SSL context 重试，设置 `check_hostname=False`
  且强制 `verify_mode=CERT_REQUIRED`，证书链仍必须有效；非 IP、证书链不受信、过期证书和其他错误不回退。
  编辑器图标改为“重新抓取网站图标”按钮，`ensure(force=True)` 仅跳过失败负缓存，已有成功图标不重复请求。
  自动登录不使用该策略，异常日志只记录分类/verify_code，不含查询或响应正文。
- favicon 缓存与展示收敛：已有有效 PNG 时只读本地，不再自动重新下载，显式重试也不刷新有效图片；
  仅无缓存、损坏或先前失败才抓取。`cacheFavicon()` 按 key 实时替换当前卡片头像，不强制整页重绘。
  无有效图片时使用 `Intl.Segmenter` 首字素渐变头像（回退 `Array.from`），支持中文、组合字符、国旗和
  非 BMP 字符，名称为空使用 `web-quick.svg`；初始、缓存 miss 与图片 error 共用默认态。
- 2026-11-26 favicon 状态持久化：schema 7 为每条记录增加 `has_favicon`，旧表只补列、不回填，重启直接读取
  SQLite，不根据缓存重新计算。同 URL 保存保留状态，改 URL 重置；保存时已有有效 PNG 或采集成功才写 `True`，
  采集失败不写。采集结果必须匹配条目当前 origin，避免旧网址的迟到响应污染新记录；状态实际变化才推进
  网页快开 UI revision。编辑器对原 URL 的 `True` 只读缓存，不自动请求；`False` 或 URL 改变时，每个编辑会话、
  每个 URL 最多自动采集一次，手动重试保留，切换登录模式不重复触发。
- 2026-11-26 favicon 抓取健壮性：JumpServer 根页与 `/favicon.ico` 均返回 HTML，真实图标声明位于
  `/core/auth/login/` 的 `/static/img/facio.ico`，原逻辑因只抓 origin 而漏掉。改为实际 URL 优先、根页补充，
  支持 `<base>`、Apple Touch Icon、`fluid-icon`、TileImage 和常见 ICO/PNG 静态路径；HTML 假图标继续尝试后续
  候选，错误 MIME 的真实栅格图片由 Pillow 实际解码，主动内容仍拒绝。最多 2 个 HTML、4 个图片候选，
  8 秒总超时及 TLS/大小/像素边界不变。旧无版本失败负缓存自动重试一次，成功缓存和 schema 不变。
- 2026-11-26 JumpServer MFA 修复：实际 MFA 路由为 `/core/auth/login/mfa/`，原 token 仅排除
  `/core/auth/(mfa|otp|captcha)`，导致页面被误判为已登录并以 `login:false` 提前结束。扩展升至 1.1.1，
  将 `login/mfa` 纳入认证路由，兼容 `code/#id_code`、虚拟 MFA 和动态口令输入框及 button/input submit；
  可见 OTP 也阻止成功判定。整页续接仍只发 OTP，直接 MFA 页即使无续接记录也进入 OTP 步骤，缺少 2FA 明确失败。

## 注意事项

- 用户手动步骤：点击网页快开中的 `edge://extensions` 按钮，打开开发人员模式并加载
  `dist\CXVPNTools\_internal\extension`；已安装旧版扩展时需先“重新加载”一次，之后连接状态自动更新。
  在网页快开新增自动登录条目后点“打开”；每次打开只尝试一次登录，出现滑块或证书警告时人工处理。
  编辑已有条目时密码默认掩码回显，可点击眼睛查看；关闭弹窗会清空界面中的密码。
  拖到文件夹主体表示移入，拖到卡片边缘表示同层排序；拖到面包屑“全部”移回根目录，拖到祖先按钮
  移到对应层。当前层、同父级与空白区域不接受投放，搜索状态仍禁止拖拽。
  新建或编辑时，只有条目 `has_favicon=false` 或 URL 已修改才自动采集一次对应 origin 的 favicon；已获取条目
  直接读取本地缓存，重启保持该状态，可点击图标手动重试。失败不影响网址保存与打开，也不访问页面子资源或执行脚本。
- 调试日志：`run.log` 的 `[web-quick]` 行与用户数据目录 `web-quick-host.log` 只记录事件与异常类型，
  不记录账号、密码、动态口令。
