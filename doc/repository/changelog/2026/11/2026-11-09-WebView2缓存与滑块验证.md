# WebView2缓存与滑块验证

- 日期：2026-11-09
- 分支：main
- 功能：内置授权页资源更新、slider_v2 自动验证
- 发布版本：v1.3.9；`core/version.py` 同步字符串和 Windows 版本元组。

## 根因与需求

普通浏览器已展示滑块，内置浏览器仍展示图标点选。两者页面均声明
`window.captchaType = "slider_v2"`，但内置浏览器缓存的
`/js/vpn/vpnLogin.js?t=102` 固定使用 `type: 'iconclick'`。
同会话绕过缓存请求得到新版 `type: window.captchaType || 'iconclick'`。
站点使用相同脚本 URL 且没有明确缓存控制头；既有缓存清理只处理主 UI，
没有覆盖内置浏览器独立的 `webview_data/embed` profile。

用户要求同时修复缓存及自动完成滑块；测试不能使用真实手机号或消耗短信次数。

## 涉及文件与设计

- `main.py`：启动 WebView2 前分别处理主 UI、embed profile 的版本化缓存清理。
- `core/ui_cache.py`：缓存清理失败不推进版本标记，下次启动仍可重试。
- `core/browser_win.py`：首次导航前串行启用 `Network.setCacheDisabled`；
  CDP 有界调用；真实输入拖动、坐标校正、取消回原点与释放；隐藏/最小化时
  先恢复窗口并导航至浏览器页。缓存策略设置失败停止导航并释放面板。
- `core/captcha_slider.py`：按实际可见控件识别类型，下载受限 CDN 图像，
  用既有 Pillow 做纹理匹配；按显示比例换算，低置信度拒绝提交；
  换题/缩放检查、有界重试和人工兜底。不调用付费视觉模型。
- `core/captcha_handler.py`：优先处理滑块；站点切成点选题后交回既有流程。
- `core/web_flow.py`：区分滑块与点选的任务日志、既有进度提示。
- 知识库：更新缓存边界、点选适用范围，新增滑块知识及索引。

缓存处理仅针对 HTTP/Code Cache，不删除 Cookie、Local Storage、IndexedDB
或用户配置。运行期策略仅作用于内置授权浏览器，不影响用户的 Edge。
没有强制修改站点验证码类型、校验响应或浏览器身份，也没有新增依赖。

## 影响与注意事项

- 自动滑块需要可见 WebView2 画布，后台触发时会恢复主窗口并切到浏览器页。
- 真实短信发送、短信登录与后续授权/续期未执行；本次真实服务验证截止于验证码通过。
- 日志不记录图片答案、Token 或完整验证请求；浏览器旧有抓包能力不在本次重构范围内。
- 用户已授权 commit、push、release；提交仅包含本次业务代码、版本信息及文档，
  用户原有测试工作区改动和本地验证文件不纳入提交。
- 发布采用 `build_release.py` 默认受保护构建，生成安装器、便携 ZIP、SHA-256
  与 manifest。保留的已跟踪测试改动会使 manifest 的 `source_dirty` 为 true，
  不以清理用户工作区或改写清单来掩盖该事实。实际发布结果以 GitHub Release 为准。
