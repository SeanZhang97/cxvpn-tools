# 内嵌浏览器画布停放

- 日期：2026-11-24
- 分支：main
- 功能：自动化授权/续期（含滑块验证）不再切换左侧菜单

## 需求与根因

用户希望停留在总览等页面时，授权/续期的全部自动化节点都在后台完成，不切换菜单。

切页的唯一来源是 `NativeBrowser.prepare_slider()`：每次滑块拖动前调用
`window.goToPage("browser")` 并把原生控件设为可见。这样做的背景是内嵌 WebView2 控件
在非浏览器页被 `Visible=False` 隐藏，而控件不可见时页面进入 `visibilityState=hidden`，
`requestAnimationFrame` 停止、定时器被限频，CDP `Input.dispatchMouseEvent` 确认超时，
滑块无法拖动。

实测表明只有“控件不可见”会让页面停摆；窗口最小化、隐藏到托盘、被其他窗口遮挡、
控件移出客户区时页面都保持可见，输入正常送达。最小化另有一个独立问题：WinForms 把
`ClientSize` 压成 0x0，原 `_layout()` 把控件钳到 320x240，导致页面重新布局。

## 涉及文件与设计

- `core/browser_win.py`
  - `NativeBrowser` 以 `parked` 取代 `initial_visible`；控件创建后不再调用 `set_Visible(False)`。
  - `_layout()`：停放时把控件移到客户区之外（`X = -(width + 40)`），`ui_view` 仍铺满窗口；
    `ClientSize` 为 0x0 时内嵌控件沿用最近一次非零客户区尺寸，没有记录时取 `RestoreBounds`。
  - `set_visible()`：状态不变直接返回；变化时在 UI 线程更新 `TabStop`、重新布局，
    归位时 `BringToFront()`，并记录请求、结果与失败类型（原实现吞掉异常）。
  - `bring_to_front()`：成为人工兜底的统一入口。恢复隐藏或最小化的窗口（沿用
    `show_form_in_place` 的窗口位置规则）、经 `goToPage("browser")` 切到浏览器页并同步
    `worker.browser_visible`、激活窗口；没有主 UI 的独立验证窗口直接归位。
  - 删除 `NativeBrowser.prepare_slider()` 与 `PageShim.prepare_slider()`。
- `core/captcha_slider.py`：`handle_slider()` 移除拖动前的 `prepare_slider()` 调用；
  自动验证失败后的 `page.bring_to_front()` 人工兜底保持不变。
- `api.py`、`ui/app.js`、`core/worker.py` 无改动：`browser_set_visible` 契约、
  阻断弹窗（`#capmodal`、`#smsmodal`）打开时停靠的逻辑都不变，实现由“隐藏”变为“停放”。
- 知识库：新增 `modules/内嵌浏览器画布停放.md` 及索引；修正 `common/超星滑块验证码.md`、
  `modules/CXVPNTools.md` 中关于 `prepare_slider` 和隐藏控件的过期描述。

## 影响与注意事项

- 用户可见变化：自动化授权/续期不再切换左侧菜单。只有自动验证失败转入人工等待，
  或登录页元素缺失时，才恢复窗口并切到浏览器页。
- 停放期间内嵌页面仍按可见状态渲染，带持续动画的页面会占用少量 GPU/CPU。
  内嵌浏览器创建后常驻，仅在 worker 退出时销毁。
- 切页时运行日志会多出“浏览器画布停放/恢复”的请求与结果各一行。
