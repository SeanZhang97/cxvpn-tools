# 修复启动器数据重定向

- 日期：2026-09-14
- 分支：main
- 需求：安装版、源码版和直接打包版始终共用当前 Windows 用户的一份数据。

## 根因

从 Codex 发起的进程实际打开了启动器 MSIX LocalCache 中的旧 CXVPNTools 副本。逻辑路径仍显示为用户 LocalAppData；仅在这个视图里比较配置摘要，无法证明安装版和打包版读到了同一个文件。

实际用户主库完整，无需恢复覆盖。已通过桌面 Shell 诊断核对真实文件位置、配置版本和账号/订阅存在状态，未输出凭据正文。包身份检测及普通 Shell.Application.ShellExecute 不能替代最终文件位置检查。

## 设计与涉及文件

- `core/desktop_runtime.py`：实际文件位置检查；重定向时使用桌面窗口的 Document.Application 启动辅助任务，复核通过后再运行。请求/领取/完成用原子 UTF-8 文件传递，15 秒领取期限，提前退出可检测；不提升权限，不复制敏感环境变量。
- `main.py`、`build.py`、`build_protected.py`：在配置/迁移/构建初始化前进入正确桌面环境；启动日志记录主数据目录、数据库路径与 revision。
- `core/app_paths.py`：主库建立后停止合并旧安装目录数据，只保留首次迁移和静态规则包补齐。
- `core/storage_probe.py`、`tests/test_shared_user_data.py`：两个 exe 目录共用临时用户主库的隔离验证，包含账号、凭据及 Unicode，不启动 GUI/worker/网络。
- `tests/test_desktop_runtime.py`、`tests/test_app_paths.py`：路径重定向、临时文件清理、无重定向不重启、辅助请求失败/超时、环境变量边界及迁移保护回归。
- `AGENTS.md`、方案及相关 knowledge：明确单一活动数据源，修正旧 dist/config.json 核对规则。

## 边界

桌面 Shell 不可用、任务未领取或实际路径仍重定向时停止启动，不以默认配置继续运行。JSON 兼容导出及历史备份不作为竞争的主数据源；数据不进入发布产物或 Git。
