# 2026-09-24 修复首次安装开启代理报错

## 日期

2026-09-24

## 功能名

修复首次安装开启代理报"读取运行配置失败：系统找不到指定的文件"

## 分支

main

## 问题根因

- 首次安装（或从未成功应用过配置）的机器上，开启代理立即失败：
  "应用失败：统一分流服务操作失败：读取运行配置失败：系统找不到指定的文件。
  (os error 2)"，且每次重试都失败，无法自愈。
- 报错文件是路由服务的 Mihomo 运行配置
  `%PROGRAMDATA%/CXVPNManager/RoutingService/config.json`，不是用户设置
  config.json（用户设置主存储已是 SQLite）。运行配置是每次应用时按当前设置
  现场生成、经 IPC 传给服务原子换入的运行时产物，首次成功应用前本就不存在。
- 回归来源：`0aab2fd`（2026-09-14）给 `RuntimeManager::status()` 增加
  `system_proxy_active` 回读时写成 `self.desired_proxy_port()?`，
  `desired_proxy_port()` 直接 `fs::read(config.json)`，文件缺失让整个 status
  指令报错；同函数其余读取均已容错，唯独这行没有。
- 失败链：`Router._install()` → `RoutingServiceClient.ensure_installed()`
  安装并启动服务后轮询 `status()`；客户端只吞 `ServiceUnavailable`
  （管道未就绪），服务返回的错误应答作为 `ServiceError` 直接上抛，首次应用
  流程在真正下发配置前中断。

## 修复动作

- `routing-service/src/manager.rs` `status()`：`system_proxy_active` 增加
  `config_path().is_file()` 短路，运行配置缺失视为"无系统代理接管"；文件存在
  时保留原有严格报错语义，不掩盖损坏配置的异常。
- 新增回归测试
  `manager::tests::status_tolerates_missing_runtime_config_on_fresh_install`：
  无 config.json 时 status 正常返回且 `system_proxy_active=false`。

## 涉及文件

- `routing-service/src/manager.rs`

## 验证情况

- `cargo test --release`（routing-service）：47 passed，含新回归用例。
- 未在真实首装机器上重放；修复后首次开启代理的完整链路（安装服务→轮询
  status→首次应用事务）以本机打包后实际运行复核。

## 注意事项

- 路由服务二进制变化后，`service_sha256` 与已安装服务不一致，
  `ensure_installed()` 会按既有升级路径触发一次 UAC 重装，属预期行为。
