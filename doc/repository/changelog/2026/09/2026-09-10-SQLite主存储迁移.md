# SQLite 主存储迁移

- 日期：2026-09-10
- 功能名：配置与节点快照可靠持久化
- 分支：main
- 需求概述：避免打包强制终止进程后配置、节点和延迟状态恢复不一致。
- 问题根因：部分订阅更新仍只更新文件，数据库优先读取时遮住新快照；订阅开关把分流对象传给整份应用配置接口，界面提示成功但分流配置未提交；空运行目录覆盖本地节点；测速 worker 未继承提交线程的版本保护。
- 涉及文件：`core/state_store.py`、`core/config.py`、`core/subscription_store.py`、`core/routing_tasks.py`、`core/routing_speedtest.py`、`core/routing_selection.py`、`core/routing.py`、`api.py`、`ui/routing.js`、`main.py`、`core/storage_probe.py`及相关测试。
- 关键设计：
  - SQLite WAL / FULL，短 `BEGIN IMMEDIATE` 事务，嵌套提交共用连接与批次，任何内层失败禁止部分提交，连接显式关闭。
  - provider 正文、定义、元数据及节点快照统一入库；配置与订阅引用及当前数据版本在同一事务绑定。运行态外部应用不在数据库写锁内。
  - 任务领取时捕获持久化配置版本，提交时比较；测速结果在任务拥有线程提交成功后才通知 UI。
  - 节点键含订阅 ID、URL/筛选指纹；同名/同 URL 的不同订阅隔离。未测速/旧探测不覆盖更新的延迟，空运行态不抹掉有效清单。
  - JSON/YAML 为提交后兼容导出，导出失败不把已提交数据库误报失败；服务使用前从数据库重新生成所需正文文件。
  - 订阅开关走分流专用应用入口，普通配置接口拒绝错误的分流载荷，内存状态仅在持久化成功后更新。
- 验证情况：84 项相关 Python 离线用例通过；14 项新增存储/恢复用例在源码和最终 exe 上均通过，其中四个强杀阶段覆盖回滚和成功提交；5 个 UI 测试脚本通过。最终产物于 2026-09-10 重新打包并启动，真实库 integrity_check=ok，配置逻辑摘要未变，2 条配置引用与配置批次匹配，44/72 条节点及对应 44/9 条测速记录均保留。未执行真实 VPN/公网完整回归。
- 注意事项：数据库损坏时拒绝静默降级旧 JSON 覆盖；既有文件和旧指纹快照保留。数据库事务不涵盖 Windows/Mihomo 外部副作用，不将局部离线验证视为实际网络完整回归。
