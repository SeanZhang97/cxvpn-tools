# 路由服务与打包重启恢复

- 日期：2026-09-14
- 功能名：路由服务与打包重启恢复
- 分支：main（工作区）

## 问题根因

- Wi-Fi 切换到网线后，旧进程的运行配置仍绑定 `WLAN`，首先触发物理接口不可用错误。
- `CXVPNRoutingService` 卡在 `START_PENDING` 后不接受正常停止；旧安装器等待超时仍覆盖服务
  EXE，因文件占用报 `os error 32`，导致代理启用和域名分流原子提交同时失败。
- 本机旧安装版与新打包版共用单实例锁。新版本启动时可能只唤醒旧进程，形成“首次配置丢失、
  完全退出后再开恢复”的假象。
- 用户主配置已经迁移到 LocalAppData SQLite，但旧便携数据合并仍允许较新的旧 `config.json`
  覆盖当前兼容导出，缺少权威存储建立后的停止边界。

## 关键设计

- 服务正常停止超时后，从 `sc queryex` 解析当前服务精确 PID；仅终止该 PID，并在覆盖文件前
  确认服务停止及服务项删除完成。状态无法确认即停止升级。
- 自动物理出口 worker 将服务 IPC 不可用和锁等待期间服务消失视为未就绪，清除候选并延后确认，
  不再因空状态触发周期性 `AttributeError`。
- `state.sqlite3` 存在后，旧目录冲突配置只备份，不再覆盖 LocalAppData 当前兼容导出。
- 已启用但路径陈旧的 `CXVPNTools` Run 项自动校正到当前 EXE。
- 标准和受保护构建统一在构建前等待新旧实例全部退出，核对 SQLite 配置摘要及兼容 JSON 摘要，
  构建后只启动新产物并确认精确子进程存活。
- 构建前保存 SQLite 一致性备份；终止进程前采集其实际安装目录，并把该目录加入旧便携数据迁移，
  防止只扫描工作区 `dist` 而遗漏正在运行的其它副本。
- 启动复核发现系统代理已指向非 CXVPN mixed-port 时，保留第三方代理并跳过快速开关、完整路由应用
  及 Codex 代理同步；仅在系统代理关闭或已指向 CXVPN 时恢复持久化状态。
- 设置页改为字段级 patch；通用保存接口拒绝携带凭据、授权和路由等专用字段的旧整包请求，避免
  过期页面快照在保存一个开关时清空其它配置。覆盖兼容 JSON 前滚动保留 20 份完整恢复快照。
- 按用户要求，本次不修改网络抓包和运行日志脱敏逻辑。

## 影响范围

- 影响 Windows 原生路由服务升级/恢复、LocalAppData 旧数据迁移、开机启动路径及本地打包重启。
- 不改变路由配置结构、SQLite schema、Named Pipe 协议、代理规则语义或业务界面。
- 不改变用户在运行中主动点击启用 CXVPN 的行为，只收紧应用启动时的自动恢复边界。

## 注意事项

- 强制终止只允许使用 SCM 当前返回的非零服务 PID，禁止按模糊进程名结束其它系统服务。
- 构建期间若用户配置摘要变化，停止启动新产物并保留现场。
