# 2026-09-20 修复 1.2.8 升级启动报错

## 日期

2026-09-20

## 功能名

1.2.8 升级后启动报错排查与用户数据修复

## 分支

main（2a48732 + 本地未提交 2FA 开发改动）

## 问题根因

- 桌面版 CXVPNTools（`D:\software\CXVPNTools`）升级到官方 1.2.8 后启动即弹
  "Unhandled exception in script"：`数据库版本高于当前程序，请使用新版程序`。
- 根因：本地未发布的 2FA 开发版（09/18 构建的 dist 1.2.3，`core/state_store.py`
  `SCHEMA_VERSION = 4`）先在真实用户库上运行，把
  `%LOCALAPPDATA%\CXVPNTools\state.sqlite3` 的 `user_version` 升到 4；
  官方 1.2.8（origin/main）`SCHEMA_VERSION = 3`，启动时 `4 > 3` 抛出 StoreError。
- schema 4 相对 3 的差异仅为新增 `otp_accounts` 表（CREATE TABLE IF NOT EXISTS 幂等增量），
  不影响 1.2.8 读写既有表。

## 修复动作

- 拉取 origin/main（v1.2.4~v1.2.8）并用 stash 合并本地 2FA 开发改动；解决
  design-qa.md、changelog README、INDEX.md、打包与分发.md、test_ui_polish.js
  五处冲突（文档取较新内容、README 合并双方条目、eye 断言按实际 UI 取值）。
- `tests/test_ui_polish.js`：eye 按钮总数断言 6→7。2FA 密钥输入的
  `otp-secret-eye` 遵循 `setSecretToggleState` 动态填充模式（静态 HTML 无内联
  SVG/aria-pressed），故带 SVG 的静态断言保持 6。
- 用户数据修复：经 SQLite backup API 备份主库至
  `%LOCALAPPDATA%\CXVPNTools\migration-backups\state-schema4-20260920-095221.sqlite3`
  后，将 `user_version` 从 4 降回 3（`build_tmp/fix_schema_downgrade.py`，含干跑模式）。
  `otp_accounts` 表与 2FA 数据保留，2FA 后续发布时升级路径幂等。

## 验证情况

- 桌面版 1.2.8 启动成功：进程存活，分流与系统代理恢复正常，
  kv_config revision=210 与订阅配置完整保留。
- `tests/test_ui_polish.js`、`tests/test_ui_routing.js`、`tests/test_ui_two_factor.js`
  全部通过。

## 注意事项

- 2FA（schema 4）正式发布前，不得再运行本地 dist 构建版（含 09/18 的
  1.2.3+2FA 产物），否则用户库 user_version 会再次升到 4，官方 1.2.8 又无法启动。
- `SCHEMA_VERSION` 提升必须与正式发布版本同步；本地开发需要新表时优先考虑
  幂等增量并评估降级兼容性。
