# VPN 未连接时物理直连

- 日期：2026-09-15
- 分支：main
- 需求：规则指定的 VPN 未开启时直连物理网络，连接后自动恢复 VPN。

## 改动

- 复用连接前原生路由检查，根据 Windows VPN 网卡实际状态选择出口，避免 UI 快照滞后。
- VPN 未连接时返回已应用的物理接口，核心显式绑定该接口，不创建额外 VPN 路由。
- VPN 已连接但地址族、路由、IPC、目标连接失败时不自动回退；每条 VPN 独立判断。
- 新连接随 VPN 状态选择出口；已有连接不迁移，UDP 新目标需要更换接口时结束旧关联。
- 保留用户规则和原有路由，更新现有未连接提示及规则解释，不新增界面控件。
- 服务 0.8.1 / IPC 8、核心 v1.19.30-cxvpn.2 / 能力 2 成对升级，防止复用旧语义。

## 文件与影响范围

- `routing-service/src/vpn_route_os.rs`、`vpn_routes.rs`、`vpn_route_ipc.rs`：原生状态查询与实际接口返回。
- `patches/mihomo/`：TCP/UDP 接口绑定、关联变化处理与回归。
- `core/routing.py`、`core/routing_service.py`、构建和运行时清单：能力门控、兼容提示、配套版本。
- `routing-service/src/vpn_routes_tests.rs`、`tests/test_vpn_routes_config.py`、`tests/test_routing.py`：相关验证。
- [实现方案](../../../plans/2026-09-15-VPN未连接时物理直连方案.md)。

## 验证

- Python 75 项、Rust 41 项、Go 5 项相关离线测试通过。
- 显式执行 Windows 原生物理选择测试通过：缺失 VPN 选择真实物理接口，无新增路由及恢复记录。
- 覆盖断开/恢复、多个 VPN、状态与路由错误、物理不可用、UDP 接口变化、取消、Unicode 和旧核心能力拒绝。
- 已自动打包并启动 `dist/CXVPNTools/CXVPNTools.exe`；真实用户主库 revision 117 核对通过，
  配置应用前后载荷一致。服务版本兼容检查、分发核心/服务/源码/清单摘要核对通过。
- 分发目录未包含用户主库、兼容配置、owner SID 或路由恢复记录。
- 当前孙河 VPN 保持 Connected，TUN 下 office 根地址返回 301、mooc1 返回 200；
  系统链路检查返回 204，服务日志确认实际 VPN 路由租约成功。
- 未主动断开当前 VPN。断开分支由离线状态切换与真实 Windows 缺失接口测试验证，
  未宣称完成断开/重连全过程的真实网络验收；根地址 HTTP 检查不等同业务表单验收。
