# Codex 代理手动开启与关闭联动

- 日期：2026-09-14
- 分支：main
- 需求：Codex 代理由用户手动开启或关闭；保留关闭软件代理时联动关闭 Codex 代理，软件启动和代理开启时不自动修改。

## 原因与变更

此前手动按钮与自动同步同时存在：启动清扫会移除字段，启动运行状态校正、原生服务事务提交和系统代理快切启用会同步，快切关闭和完整停止会移除字段。

- 删除路由层自动调用及已无调用方的 Codex 辅助方法、依赖；启动修复/对账不修改 Codex 配置。
- 软件代理关闭联动移到 API 配置事务成功提交之后，只在启用变为关闭时清理；服务失败或配置保存回滚时不清理。Codex 清理失败不会撤销软件代理关闭，通过既有 warnings 提示。
- 保留手动 sync/restore/read/status API；开启时动态读取 routing.mixed_port，关闭时继续保留用户手动修改的字段。
- Windows 注册表、系统代理快照、状态回读和用户会话刷新逻辑不变；不新增公共配置字段或依赖。
- 页面移除自动校正说明，明确手动开启与关闭联动；端口不一致时提示手动关闭再开启。
- 已有 Codex 配置不会通过本次升级自动关闭或重新写入。

## 涉及文件

- `api.py`、`core/routing.py`：移除自动开启链，关闭联动在 API 成功提交后执行。
- `ui/app.js`、`ui/index.html`：手动控制说明与端口变化提示。
- `tests/test_proxycore.py`、`tests/test_api_codex_proxy.py`、`tests/test_routing_schema.py`：新增禁自动修改断言及移除旧辅助方法模拟。
- `doc/repository/knowledge/modules/Codex代理配置同步.md`、`modules/代理控制与运行状态.md` 与知识索引：更新当前调用关系。

## 使用边界

软件代理关闭成功后联动移除 Codex 托管字段，用户手动改过的字段保留并警告；重新开启软件代理不会自动开启 Codex 代理。端口变化后需要用户到 Codex 页面手动关闭并重新开启。配置变更后，已运行的 Codex 需要用户自行重启。本工具不结束 Codex；内置浏览器、插件独立进程及不继承配置的请求仍受 Codex 自身会话机制限制。
