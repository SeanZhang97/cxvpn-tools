# 订阅独立自动测速间隔

- 日期：2026-09-16
- 功能：每个订阅独立配置自动测速周期
- 分支：main

## 需求与设计

保留现有订阅更新时间间隔，新增独立自动测速间隔。用户选择按订阅分别配置。

- “订阅 → 编辑”新增“自动测速间隔（分钟）”，默认 5 分钟，支持 1～1440 的整数分钟。
- 原“自动更新间隔（分钟）”改为“订阅更新间隔（分钟）”，明确更新对象，与自动测速间隔区分。
- `proxy_providers[].speedtest_interval` 按秒保存；缺失时兼容为 300 秒。
- 现有订阅 `interval`、`auto_update` 的含义、默认值和开关保持原样。
- 保存应用后，provider 健康检查、普通节点组、智能优选各层和下载出口故障组采用所属订阅周期。
- 聚合组检查订阅出口的周期取已启用订阅的最短值；停用订阅不参与计算。
- 保留懒检测和手动测速行为。周期变更参与运行配置签名，节点缓存与测速历史指纹不受影响。
- 非法值由后端拒绝，不能静默变成默认值或关闭检测。

## 涉及文件

- `core/routing.py`：配置归一化、校验及运行/预览配置生成。
- `core/routing_auto_policy.py`：智能优选各层测速周期。
- `ui/routing.js`、`ui/style.css`：订阅编辑表单与宽窄窗口布局。
- `tests/test_routing_speedtest_interval.py`、`tests/test_ui_routing.js`：相关回归。
- `doc/repository/knowledge/modules/Windows统一域名分流.md`：当前周期语义。

- 不修改当前用户已保存的订阅更新周期；旧数据读取时使用测速默认值，后续保存纳入主库。
- UI 仍由既有“保存并应用”提交配置；未使用的节点/组可能因懒检测跳过周期。
- 未执行真实订阅请求、长时间自动测速或外部网络集成验证。
