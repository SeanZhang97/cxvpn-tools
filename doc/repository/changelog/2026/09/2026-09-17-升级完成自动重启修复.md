# 升级完成自动重启修复

- 日期：2026-09-17
- 功能：应用内升级完成后自动重启 CXVPNTools
- 分支：main

## 问题根因

旧版升级守护只轮询安装注册表版本。安装器写入新版本注册表后仍可能继续复制文件，守护会在
安装进程完全退出前过早启动新版，启动失败后也没有二次确认或兜底。现场安装日志确认部署成功，
但应用进程未在升级链路内恢复。

## 涉及文件

- `core/app_update.py`
- `installer/CXVPNTools.iss`
- `installer/README.md`
- `tests/test_app_update_hardening.py`
- `doc/repository/knowledge/common/打包与分发.md`

## 关键设计

- 应用内升级通过专用参数要求安装器在静默部署完成后以原桌面用户启动新版。
- 非提权升级守护继续等待安装器真实退出并验证退出码、注册表和 EXE 版本。
- 守护按完整 EXE 路径识别安装器已启动的新版进程；若未找到则自行兜底启动，最终统一校验进程持续存活5秒。
- 普通静默安装未携带专用参数时保持原行为，不自动打开应用；需要系统重启时仍不提前启动。

## 影响范围

仅影响应用内静默升级完成后的启动阶段，不改变手动安装、更新检查、下载校验、用户数据目录及重启系统判定。

## 验证情况

- `uv run python -m compileall -q main.py api.py core`：通过。
- 更新器与 API 升级桥接离线回归：47项通过。
- `tests/test_installer_build.ps1`：16项构建锁校验通过。
- `uv run python -m tests.run_routing_offline`：296项通过。
- `uv run --with pyinstaller python build.py`：通过，生成 `dist/CXVPNTools/`，用户主库 revision 128
  与兼容配置核对通过，新版进程已自动启动。
- `installer/build_installer.ps1`：编译通过；最终发行产物版本为 `1.2.8`，并生成对应 SHA-256。
- 打包 EXE 的隔离用户数据探针：1项通过，覆盖中文、组合字符和非 BMP Unicode，且未在程序目录写入活动配置。

## 注意事项

未执行覆盖当前安装目录的真实升级；该操作会修改本机安装状态，仍需在后续发布版本上做跨版本实机验收。
