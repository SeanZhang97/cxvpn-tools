# Codex 模型传输一键切换

- 日期：2026-09-14
- 分支：main

## 需求概述

在 Codex 页面增加独立的 WSS 开关。开启时恢复内置 `openai` Provider 的默认传输策略；关闭时使用本工具创建的 `cxvpn_openai_http` Provider，并设置 `supports_websockets = false`，让模型 Responses 请求直接使用加密 HTTPS/SSE。

## 关键设计

- 传输开关与现有 Codex 代理开关独立，不修改 VPN、Mihomo、系统代理或代理环境变量。
- 开关仅编辑 `CODEX_HOME/config.toml` 或默认的 `%USERPROFILE%\\.codex\\config.toml`，不依赖 Codex CLI，也不读取 `auth.json` 或 Token。
- HTTP/SSE 模式写入独立 Provider：`base_url` 为 `https://chatgpt.com/backend-api/codex`，`wire_api = "responses"`、`requires_openai_auth = true`、`supports_websockets = false`。
- 使用独立的 `codex_transport_snapshot.json` 保存最小恢复记录。它只用于外部 `config.toml` 的事务恢复，不作为应用活动偏好的第二数据源。
- 配置候选写入前后使用 `tomllib` 对比结构，只允许根级 `model_provider` 和专用 Provider 变化；写入前回读原文，检测外部并发修改。
- 自定义 Provider、同名未托管 Provider、`openai_base_url`、活动 profile、复杂 quoted/dotted/inline TOML、损坏配置或恢复记录均拒绝覆盖。
- 状态只描述配置文件选择，不声称已运行 Codex 的实际传输已经变化；保存后提示用户自行重启，不结束 Codex 进程。

## 影响范围

- Codex 页面新增模型请求传输开关和状态说明。
- `get_codex_status()` 增加传输状态摘要；新增 `set_codex_websocket(enabled)`。
- 现有 Codex 代理开关与软件代理关闭联动保持不变。
