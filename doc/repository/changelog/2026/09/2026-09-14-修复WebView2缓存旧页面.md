# 修复WebView2缓存旧页面

- 日期：2026-09-14
- 分支：main
- 需求：升级到 1.2.2 后窗口不显示 Codex 菜单与新版总览，需保证升级后窗口始终加载当前版本的 UI。

## 根因

pywebview 非 private 模式用固定端口（42001）的内置 bottle 服务器提供 UI 静态资源。pywebview 在路由里设置了 no-cache 响应头，但 bottle 的 `static_file` 返回独立 `HTTPResponse`，其 `apply()` 会整体替换线程本地响应头，实测响应头为空。WebView2 对无缓存控制头的资源按启发式策略缓存；软件升级后端口与 URL 不变，缓存键相同，窗口直接命中旧版 HTML/CSS/JS。

取证链：运行实例的 HTTP 服务返回的 index.html 含 Codex 菜单与最新文案，而窗口截图显示导航无 Codex、总览为旧版布局；磁盘缓存目录中存在旧版资源副本；固定端口来自 pywebview `settings['DEFAULT_HTTP_PORT']`（`private_mode=False` 时启用）。

## 设计与涉及文件

- `core/ui_cache.py`（新增）：
  - `apply_no_cache_patch()`：包装 `bottle.static_file`，把 `Cache-Control: no-cache, no-store, must-revalidate` 与 `Pragma: no-cache` 补到返回的 `HTTPResponse` 上。pywebview 资源路由在请求时以模块属性形式调用 `bottle.static_file`，进程内持续替换该属性即可，不修改 pywebview 内部实现。幂等，响应头设置失败不影响资源返回。
  - `purge_stale_webview_cache(storage_path, version)`：在 `webview_data` 下维护 `ui-cache-version.txt` 标记；版本变化或首次运行（无标记）时删除 `EBWebView\Default\Cache` 与 `EBWebView\Default\Code Cache`，不触碰 Cookie/本地存储等登录态数据。必须在 `webview.start()` 之前调用（WebView2 启动后会锁定缓存目录）。同版本重复启动不动缓存。
- `main.py`：`_run_app()` 在创建 API 前接入两层防护，清理结果写入 startup.log。
- `tests/test_ui_cache.py`（新增）：补丁加头/幂等/内容保持/404 边界，清理的同版本跳过、版本变化只删 HTTP 缓存、首启清理、空路径、日志回调与目录缺失边界，共 10 项。

## 验证

- `tests.test_ui_cache` 10 项通过；`tests.run_routing_offline` 254 项通过；`tests.test_windows_desktop` + `tests.test_api_desktop_actions` 22 项通过。
- `uv run --with pyinstaller python build.py` 成功；产物 `dist/CXVPNTools/`，exe 更新于 2026-09-14 14:41:10，用户配置核对通过（revision=67），新版自动启动（pid 17128）。
- 实例运行中实测：`http://127.0.0.1:42001/index.html` 响应头 `Cache-Control: no-cache, no-store, must-revalidate`、`Pragma: no-cache`，内容含 Codex 菜单。
- startup.log 记录 `webview cache purge: {'purged': True, 'reason': 'first-run', 'removed': ['EBWebView\\Default\\Cache', 'EBWebView\\Default\\Code Cache'], 'errors': []}`。
- 窗口截图确认：左侧导航出现"域名分流"与"Codex"菜单，总览显示新版布局（默认 VPN 名称、网络出口信息、授权五步流程），旧版缓存页面不再复现。

## 边界

- 清理只针对 HTTP 缓存目录；Cookie、本地存储、IndexedDB 等登录态数据不删除。
- pywebview 升级后若其内部改为在 `static_file` 之外提供资源，补丁将退化为无害空操作；版本标记仍会在升级时触发一次清理兜底。
