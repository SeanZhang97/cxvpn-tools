# 2026-09-14 修复补录凭据后连接失效

- 日期：2026-09-14
- 功能名：VPN 补录凭据后继续连接
- 分支：main

## 问题根因

首次连接缺少工具凭据时，前端在连接互斥状态仍被占用期间就显示凭据弹框。用户快速完成补录后，自动续接请求可能命中同一互斥状态而被静默跳过；自动续接也没有绑定当前列表按钮，拨号期间按钮仍显示为普通“连接”，后续点击会被全局忙碌状态忽略。

## 涉及文件

- `ui/app.js`
- `tests/test_ui_state_sync.js`
- `doc/repository/knowledge/common/Windows-VPN凭据与RAS-API.md`

## 关键设计

- 缺少凭据时先记录待续接参数，在当前连接动作完成并释放互斥状态后再打开凭据弹框。
- 凭据保存成功后，从当前 VPN 表格中重新定位目标连接按钮，再执行原目标、原连接模式的续接，使拨号忙碌状态可见。
- 文本连接按钮进入忙碌状态时统一添加 `is-busy`，触发表格已预留的 88px 操作列宽度，避免“正在连接…”溢出；动作结束后恢复普通宽度。
- 主动打开“凭据”仍然只保存，不会发起拨号。

## 影响范围

- 仅影响由“连接”触发的缺少凭据补录流程。
- 不改变凭据存储格式、Windows RAS/EAP 写入方式、连接 API 或自动续期策略。
