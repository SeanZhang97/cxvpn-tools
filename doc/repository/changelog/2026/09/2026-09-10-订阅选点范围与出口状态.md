# 订阅选点范围与出口状态

- 日期：2026-09-10
- 功能名：订阅独立选点与默认出口状态
- 分支：main

## 需求与原因

“使用此节点”实际只保存订阅内偏好，“当前使用”按各订阅组判断，容易让用户误认为多个
节点同时成为默认出口。未启用订阅原先允许保存待启用节点，与按钮使用语义不一致。

## 最终变更与涉及文件

- `ui/routing.js`：改为“设为本订阅节点”，区分已选偏好、订阅运行节点与默认出口节点；
  基于已保存出口和运行组进行精确比较，兼容带中文、组合字符及非 BMP 字符的预览节点。
  未启用订阅禁用按钮并阻止提交；节点卡缓存签名包括启用状态和默认出口选中状态。
- `api.py`：手动选点在读取快照或操作运行核心前检查已保存订阅是否启用，拒绝停用订阅及
  停用预览草稿，保留原配置。自动策略编辑行为不变。
- `core/routing_aggregate.py`、`core/routing.py`、`core/routing_selection.py`：新增
  `aggregate_selection` 配置和“全部代理订阅”独立选点；手动模式按订阅 ID 与节点名精确
  固定聚合组，节点失效时使用 `REJECT` 兜底，自动模式保留原订阅间策略。
- `tests/test_ui_routing_selection.js`、`tests/test_ui_routing.js`、
  `tests/test_routing_selection.py`：增加多订阅、同名 Unicode 节点、预览、关闭代理、
  直接指定出口、非代理出口、未应用草稿以及后端防绕过回归。
- `doc/repository/knowledge/modules/Windows统一域名分流.md`：同步选点边界与状态语义。

## 设计与影响范围

- 各订阅的手动节点继续相互独立；“全部代理订阅”继续由聚合策略选择订阅组。
- 不修改默认出口、规则、自动策略、配置结构或依赖；不清空其它订阅节点。
- 停用订阅继续允许预览和测速，已有手动偏好保留；重新启用后可继续使用或重选。
- 复用现有节点卡、状态标签和自定义下拉组件，不新增布局或滚动区域。
