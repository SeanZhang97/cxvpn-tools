## 需求概述

为 CXVPNTools 增加版本号、自动检查开关、手动检查入口，以及选择安装目录、
桌面快捷方式和可选保留用户数据的安装器。本次跟进完成 Inno Setup 安装、官方离线
依赖准备与真实 setup.exe 构建；实际安装/升级及卸载的数据测试尚未执行。

- core/version.py、core/app_update.py、core/config.py、api.py、ui/index.html、ui/app.js：
  1.0.1 版本、更新设置与 GitHub Releases 检查入口，沿用本任务此前实现并包含本次修复。

- doc/repository/knowledge/common/打包与分发.md：当前分发事实。

## 关键设计与影响

- 安装器版本从已构建主 EXE 读取并与源码版本核对；AppId 固定，支持后续覆盖安装。
- 两个完整离线安装包必须齐备并匹配锁定的哈希、大小和 Microsoft Authenticode 签名，
  否则不允许编译。安装前还会核验包内文件哈希。
- WebView2 检查 HKLM32 有效 Runtime 版本，不能将安装 Edge 浏览器当作依赖满足。
  VC++ 检查 HKLM64 的 Installed 和版本，满足要求时跳过。
- 缺失依赖在复制主程序前安装，单个执行限时 600 秒。失败/超时/复检失败时停止；
  重启要求保留并禁止立即启动应用。
- 离线安装包保存在所选目录 prereqs 中；实际微软运行库位于系统共享位置。
- 用户数据继续位于 LocalAppData/CXVPNTools；只包装主 EXE 与 _internal，构建前检查
  用户数据残留。依赖本体忽略入 Git，使用锁定下载地址恢复。
- 卸载使用有效的 Inno 回调和默认未勾选的删除数据选项；移除所安装文件，不递归清空
  用户选择的整个安装目录。服务清理有明确超时和错误返回，未执行真实清理测试。
- 本次跟进生成 1.0.1 标准 PyInstaller 产物并重建安装包；构建过程中保留本机用户配置，
  当前新版应用已启动运行。
- GitHub 仓库尚无正式 Release 时，更新检查将返回可理解的“暂无正式 Release”状态，
  不再把 HTTP 404 直接显示为 HTTPError。
- Mihomo 配置预检现在记录目标、数据目录、超时、退出码、输出长度和耗时；进程无诊断输出时，
  UI 会提示查看运行日志，避免退化成无法定位的“未知错误”。
- 针对目标机 Mihomo 以 `0xC0000005` 立即退出的问题，将官方同版本核心切换为
  `windows-amd64-compatible`（GOAMD64=v1），并同步 Python 路由层、原生服务和运行时清单中的哈希。
- 自动续期、自动连接、开机自启和关闭时驻留托盘均以关闭为默认；旧配置首次升级时执行一次默认迁移。
- 本机出口探测失败时不再把 PowerShell `Command [...]` 异常对象直接展示给用户。
- 安装器固定 `AppId` 并沿用上次安装目录，支持 1.0.0 及后续版本覆盖升级；卸载检测运行中主程序，
  交互式提供强制终止并继续或取消卸载的选择。
- 修正升级前 Mutex 检测的 Windows 名称转义，避免旧程序未被识别而在替换文件阶段出现错误代码 5。
