# 自动物理出口与运行状态修复

- 日期：2026-09-13
- 功能：物理网络自动跟随及配置失败后的真实运行状态展示
- 分支：main（含工作区未提交改动）

## 问题根因

- `physical_interface` 为空原本表示自动选择，但环境校验会把当次首选网卡写回配置。
  以太网断开、WLAN 接管默认路由后，保存配置仍固定为“以太网”，后续应用被正确拒绝却无法自动恢复。
- 分流页下拉框只渲染可用网卡，保存的断开网卡无法匹配后会表现成“未找到可用物理接口”，
  混淆“指定接口失效”和“系统无可用接口”。
- 首页应用失败文案固定声称“代理未开启，系统路由已恢复”，没有以服务的 active、TUN 和系统代理
  快照状态为准；旧 TUN 仍运行时产生错误结论。

## 关键设计

- “自动选择”作为独立、可持久化的空值；应用时复制配置并解析当次物理默认接口，只把解析结果写入
  Mihomo 运行配置，返回和持久化仍保留自动语义。明确选择的接口失效时不擅自替换。
- 物理接口只接受具备 IPv4 默认路由、状态为 Up 且 `HardwareInterface=true` 的网卡，按路由与接口
  综合 metric 排序，排除 TUN、VPN 与虚拟网卡。
- 新增后台网络出口复核。仅对“已启用 + 自动选择 + 兼容服务 + 已确认运行配置”生效；每 15 秒检查，
  同一变化稳定 15 秒后，获取路由互斥锁并再次核对配置版本、服务哈希、PID、事务状态和目标接口，
  再复用现有完整应用、出口验证与失败回滚。无可用物理接口时保持当前运行态，不主动停止 TUN。
  GUI 退出会设置取消事件、在最终应用前再次检查，并有界等待 worker 退出。
- 运行配置携带保存配置签名；原生服务状态回传实际接管方式、实际物理接口及签名。首页优先展示实际
  运行状态，并标记保存配置与运行态不一致；兼容旧服务时由 `active + system_proxy_active` 推断接管方式。
- 服务升级判断同时校验版本和发行二进制哈希；版本号相同但二进制已更新时，界面会提前按需要升级
  处理，不会等应用过程中才意外出现管理员授权。
- 下拉框保留失效的指定网卡并标注“未连接或无默认路由”；配置检查分别展示自动当前接口、指定接口
  失效和确实无可用接口。应用失败只提示检查真实运行状态。

## 影响范围

只改变物理出口解析、自动网卡变化后的运行配置重应用，以及配置与运行状态不一致时的展示。
指定接口不会自动迁移，Windows VPN、代理订阅选择、规则数据和系统代理快照语义不变。

## 注意事项

- 后台自动跟随依赖 GUI 正在运行；应用会按现有事务短暂重启 TUN，失败时以原生回滚结果为准。
- 旧版已保存的明确网卡继续视为用户指定。需要自动跟随时，由用户在新版界面选择“自动选择”并应用一次。
- 自动切换、浏览器连通性和真实网卡插拔由用户手动验证，离线测试不能替代 Windows 路由行为。
