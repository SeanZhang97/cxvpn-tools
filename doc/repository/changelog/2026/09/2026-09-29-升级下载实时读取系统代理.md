# 2026-09-29 升级下载实时读取系统代理

## 日期

2026-09-29

## 功能名

下载升级包失败 URLError：进程级 urllib 全局 opener 固化代理配置，下载改为每次实时读取系统代理 + 重试直连兜底 + 失败文案带具体原因

## 分支

main

## 问题根因

- 升级包下载与检查更新的代理尝试都走 `urllib.request.urlopen`，其进程级全局
  opener 只在首次调用时构建一次，代理配置在那一刻固化：构建时系统代理未开启，
  则该 opener 直接不含 ProxyHandler，之后用户再开启系统代理，进程内所有
  urlopen 仍永久直连。应用 9:22 启动（系统代理尚未开启）→ 启动期的网络出口
  查询等请求完成首次 urlopen → 14:20 下载升级包时仍走直连。
- 直连 `github.com` 尚可慢速连通（检查更新的 API 因此成功），但安装包会 302
  跳转到 `release-assets.githubusercontent.com`，该域名直连不可达，下载在建立
  连接阶段抛出 URLError，表现为"下载升级包失败：URLError"。
- 下载路径无重试、无直连兜底（检查更新 2026-09-28 已具备），且失败文案只保留
  异常类型名，丢失具体原因。

## 修复动作

- `core/app_update.py` 新增 `_urlopen(request, timeout, direct=False)`：每次调用
  都 `build_opener(ProxyHandler())` 重建 opener，`ProxyHandler()` 构造时实时调用
  `getproxies()` 读取当前系统代理；`direct=True` 维持 `ProxyHandler({})` 显式直连。
  检查更新 `_request` 与下载 `_download_attempt` 统一改走该入口，不再触碰全局
  opener。
- 下载拆分出单次尝试 `_download_attempt`，外层 `_download_installer` 负责重试：
  网络层错误（URLError/OSError 家族）最多 3 次、间隔 1s/2s
  （`DOWNLOAD_MAX_ATTEMPTS`/`DOWNLOAD_RETRY_BACKOFF`），最后一次尝试直连兜底；
  代理隧道被拒（Tunnel connection failed）立即转入直连；退避等待支持取消事件。
  校验失败、HTTPError、单尝试总超时（`_DownloadTotalTimeout`）属确定性结果，不重试。
- 下载失败文案改用 `_describe_network_error`，UI 展示 `URLError（具体原因）`，
  与检查更新保持一致；每次尝试记录 direct 标志与重试/终态日志。
- 测试 mock 接缝从 `urllib.request.urlopen` 迁移到 `app_update._urlopen`；
  新增回归：每次调用重新读取系统代理、直连模式禁用代理、瞬时失败重试恢复、
  隧道失败转直连、退避期间取消立即停止。

## 影响范围

- 仅应用内升级的检查与下载网络路径；检查更新行为不变（代理尝试同样改为实时
  读取），订阅、出口查询等其它模块的网络请求不在本次范围内。
- 极端情况下瞬时故障最多增加约 3 秒退避耗时；单尝试 30 秒读超时、900 秒总预算、
  512MiB 上限与 SHA-256 校验规则不变。

## 验证情况

- `python -m unittest tests.test_app_update tests.test_app_update_hardening tests.test_api_app_update`：58 项全部通过。
- 本机实链路冒烟：当前系统代理 127.0.0.1:17890 下，用新 `_urlopen` 请求 v1.3.0
  安装包地址，302 跳转后返回 200 并成功读取首块数据（约 2.8 秒）。
- 机制复现验证：进程内首次 urlopen 时 `getproxies()` 为空，则全局 opener 完全
  不含 ProxyHandler，之后恢复系统代理也不会再生效（Python 3.14.7 实测）。
- 未做完整回归与实机整包升级演练。
