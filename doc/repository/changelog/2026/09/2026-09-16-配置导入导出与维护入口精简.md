# 配置导入导出与维护入口精简

- 日期：2026-09-16
- 分支：main

## 需求与根因

- 配置维护只保留导入、导出，移除低频且缺少有效差异信息的配置历史与诊断包。
- 原导出在触发浏览器 Blob 下载后立即提示成功，没有核实文件是否写入，也未返回保存路径。
- 用户要求导入、导出均明确选择路径。

## 关键设计与影响范围

- 撤掉“配置保护与诊断”卡片，改为默认收起的“配置导入与导出”；系统代理绕过卡片使用整行。
- 导出通过 pywebview 主窗口的 Windows 保存窗口选择目录和文件名，后端原子写入 UTF-8 JSON，
  落盘完成后显示实际路径；取消不写入，失败不提示成功，覆盖失败保留原文件。
- 导入通过打开文件窗口选择 JSON，限制为 2 MB，支持 UTF-8 BOM；展示文件路径和差异，确认后应用
  已读取的内容快照。保留原备份版本、订阅地址选项、本机凭据和代理启用状态保护。
- 移除历史记录写入/查询/回退接口、诊断包接口、相关 UI、事件、状态、CSS 和专用实现。
- 保留配置保存失败的事务回滚、运行日志、SQLite 恢复机制、服务内部诊断；已有历史文件不主动删除。
- 保留工作区原有代理启停、测速等未提交修改，仅同步与本次功能移除相关的测试依赖。

## 注意事项

- 导出以已保存配置为准；未勾选订阅地址的文件在另一台电脑导入时，可能需要补充订阅地址。
- 不再提供手动历史回退或诊断包；需要恢复配置时使用自行导出的 JSON，排障读取现有运行日志。
