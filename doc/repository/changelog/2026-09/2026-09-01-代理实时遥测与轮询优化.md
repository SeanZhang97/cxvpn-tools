# 代理实时遥测与轮询优化

- 日期：2026-09-01
- 功能名：后端实时遥测与版本化 UI 状态流
- 分支：非 Git 工作区

## 需求概述与问题根因

网络代理首页原先只在读取完整 `get_routing_setup` 时获得一次活动连接和规则命中摘要，无法持续
显示当前上下行速率。若简单增加高频 HTTP 轮询，会重复跨 pywebview 桥、Python 和 Mihomo
Controller，空闲时也持续耗费资源。Mihomo 已提供 `/traffic` WebSocket，适合连续速率数据；
但 `/connections` 包含目标域名、IP 等明细，不应直接送入前端。

第一阶段由浏览器直接建立 `/traffic` WebSocket 后，UI 仍需持有 Controller 端口与 secret，
并需要开放动态 WebView Origin。全局状态仍每 2 秒跨桥读取 worker、VPN、验证码和短信四组
快照，日志或浏览器页还会追加请求。第二阶段把 WebSocket 和 `/connections` 聚合收敛到后端，
并以单一“完整快照 + 单调版本号 + 阻塞订阅”替代固定跨桥轮询。

## 关键设计

- `core/mihomo_telemetry.py` 在 Python 后端通过 Authorization header 连接 Mihomo 回环
  Controller `/traffic`，读取 `up`、`down`、`upTotal`、`downTotal`；仅在网络代理首页可见且
  服务运行时保持连接，离页或隐藏后释放。断线按 1、2、4、8、15 秒退避并清零过期速率。
- `/connections` 不直送浏览器；同一后端遥测任务每 10 秒聚合活动连接数和规则命中摘要，去除
  目标 IP、域名和凭据，再与实时流量一并发布。
- `get_config`、路由 bootstrap/setup/apply 等 UI 结果递归移除 `controller_port` 和
  `controller_secret`；UI 草稿预检/应用时由后端合并当前私有字段，避免 secret 被轮换。
  浏览器不再直连 Controller，因此撤销 `external-controller-cors`。
- `core/ui_state_stream.py` 每 500ms 在后端聚合内存快照，仅在内容变化时递增版本并唤醒等待者；
  UI 使用 `get_ui_state_snapshot` 初始化、`wait_ui_state(version, 25)` 阻塞订阅，超时只返回心跳。
  断线按 1～15 秒恢复并以完整快照重同步，避免增量事件丢失导致状态漂移。
- 遥测线程维护独立页面生命周期版本。离开页面会同时使正在执行或尚未开始等待的旧退避失效，
  快速返回页面不会继续等待上一轮最长 15 秒的重连延迟。
- 日志正文只在日志页且 `logs_version` 变化时读取，浏览器状态复用同一快照；代理页通过布尔
  生命周期意图启停后端遥测，不再掌握 Controller 连接信息。
- 修复全局轮询移除后，修复 VPN、授权处理和连接完成三个回调仍调用旧 `poll` 标识的问题；这些
  用户动作改为调度一次 `refreshUiStateOnce`，保留立即反馈但不恢复周期轮询。
- WebSocket/状态流异步改变“服务检查”“代理启停”和“遥测连接”状态时，通过节制的
  `aria-live="polite"` 状态区向辅助技术播报；实时上下行速率保持静默，避免每个流量帧重复播报。
- 真实启用失败时除保留短时 toast，还在代理首页连接卡片固定展示失败原因；开启事务失败使用
  “代理未开启，系统路由已恢复”标题并以 `role="alert"` 播报，可由用户手动关闭。后续重试会先
  清除旧提示，避免过期错误与新操作状态并存。

## 影响范围

- 改变运行时 Mihomo 配置生成结果，既有用户下次应用/开启代理后移除不再需要的 WebSocket CORS；
  不修改 `config.json.routing` 公共持久化字段或订阅缓存格式。
- 不替换配置保存、启停事务、Windows 服务健康检查和节点选择等命令式请求；只替换持续状态
  同步链路，操作类接口仍按用户动作调用并返回明确结果。
