# 节点智能优选与地区故障转移

- 日期：2026-09-01
- 功能名：节点智能优选策略
- 分支：main

## 需求概述

原“自动优选”只能把一个订阅内的全部节点交给单一 `url-test` 或 `fallback`
策略，无法表达“日本优先、日本高速专线优先、日本全部不可用后再转美国”的
多级选择关系。节点名称可能混合多个国家，也需要通过地区与线路关键词识别，不能
依赖订阅预先分组。

## 关键设计

- `routing schema` 升级到 v6；每个订阅新增可选 `auto_policy`，保存有序地区、
  地区补充关键词、线路优先关键词、延迟切换容差和最终回退方式。旧配置默认关闭
  智能策略，继续沿用原自动优选语义。
- 地区规则按顺序编译为隐藏的 Mihomo `url-test` 与 `fallback` 组。每个地区先使用
  “地区 + 线路关键词”组，全部不可用后才进入该地区所有节点；整个地区不可用后
  才进入下一地区。
- 默认最终行为是 `REJECT` 并由上层表现为无可用节点；用户也可选择在全部地区规则
  失败后从订阅全部节点兜底。线路关键词只决定候选层级，组内仍以实测延迟选择。
- 节点工作台增加内联策略面板，支持地区添加、删除、上下调整、每地区独立关键词、
  延迟容差、最终回退方式及可读流程预览。动态地区下拉复用
  `enhanceRoutingSelect`，保留键盘和 ARIA 行为。
- 每个地区新增“低延迟优化 / 仅故障切换”。仅故障模式必须从该地区节点下拉框选择
  首选节点；首选节点健康时保持不动，故障后才按“优先线路 → 地区其他节点 → 下一地区”
  回退。保存时校验节点仍存在且属于所选地区，订阅后续移除节点时运行配置自然跳过空组。
- 延迟容差支持 `ms` 和百分比；Mihomo 原生只接收毫秒，因此百分比按最近安全节点快照中
  对应候选组的最低有效延迟换算，候选组没有有效测速时回退订阅最低延迟，再无数据时使用
  100 ms 基准。界面显示当前近似换算值，并说明重新应用时更新。
- 线路和地区关键词改成独立标签编辑器，一次只添加一个值；界面拒绝逗号、中文逗号、
  竖线和换行批量输入，避免关键词边界不清和误拆分。
- 策略步骤卡覆盖全局 `.field` 的固定 170px 宽度，顶部按“优先级、地区、组内切换、
  首选节点、排序”连续排布，第二行关键词编辑器等宽铺满；增加步骤编号、轻量左侧强调线和
  `focus-within` 状态，减少大块空白与零散控件感。
- Controller 返回嵌套策略组时，后端沿 `now` 解析到最终真实节点，并从 provider
  目录恢复真实节点列表，避免 UI 展示内部组名或使逐节点测速失效。
- 保存策略仅变更节点偏好，不隐式修改默认出口；运行中改变策略会先提示连接可能短暂
  中断，确认后通过原有应用事务重新加载并立即生效，保存或运行失败会保持原配置。

## 影响范围

- 仅启用某订阅的智能优选时生成额外隐藏策略组；普通自动优选和手动选点保持兼容。
- 订阅级 `proxy:<id>` 出口执行该订阅的智能策略；聚合 `proxy` 出口仍沿用聚合代理池
  自身的策略语义。
- 地区和线路识别基于节点名称及用户补充关键词，不修改订阅缓存正文或节点连接参数。
- v5 及更早智能策略缺少新增字段时自动迁移为“低延迟优化 + ms”，原行为不变。

## 注意事项

- “高速专线”等名称只作为候选优先级，不证明线路真实性；最终可用性与延迟仍由
  Mihomo 健康检查决定。
- 运行中保存会重新加载策略组，现有代理连接可能短暂中断；代理未开启时只保存配置，
  下次开启时直接使用新策略。
