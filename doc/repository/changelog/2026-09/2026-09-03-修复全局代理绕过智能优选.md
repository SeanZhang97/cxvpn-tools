# 修复全局代理绕过智能优选

- 日期：2026-09-03
- 功能名：全局代理聚合链路修复
- 分支：main

## 问题根因

订阅的智能优选会生成公开组 `PROXY-<id>`，但“全部代理订阅”对应的全局 `PROXY`
组直接通过 `use` 展开原始 provider 节点。命中 `proxy` 出口的连接因此跳过订阅公开组，
即使订阅界面显示“日本 → 美国”且最终选择“停止并提示”，仍可能从完整订阅节点池选中
台湾或新加坡节点。显式使用 `proxy:<id>` 的规则不受该问题影响。

## 涉及文件

- `core/routing.py`
- `tests/test_routing.py`
- `tests/test_routing_auto_policy.py`
- `doc/repository/knowledge/modules/Windows统一域名分流.md`

## 关键设计

- 全局 `PROXY` 改为通过 `proxies` 引用每个订阅的公开 `PROXY-<id>` 组，不再直接引用
  原始 provider。
- 全局策略仍负责在订阅公开组之间执行 `url-test`、`fallback` 或 `select`；订阅公开组内部
  继续执行该订阅的智能优选、普通自动优选或手动节点策略。
- 代理组生成辅助函数显式区分 provider 来源与嵌套代理组来源，并拒绝同时指定或全部缺失，
  防止后续再次混淆层级。

## 影响范围

- 使用“全部代理订阅”作为默认出口或规则出口的连接会遵守每个订阅自己的节点策略。
- 直接选择具体订阅、订阅更新链路、节点缓存、配置字段和 UI 交互保持不变。
- 重新应用配置会重建代理核心，既有代理连接可能短暂中断。

## 注意事项

- 全局 `url-test` 的候选现在是各订阅公开组；每个公开组的最终真实节点仍由其订阅级策略决定。
- 若已存在通过旧配置建立的连接，需重新应用或重启代理后才能使用新链路。
