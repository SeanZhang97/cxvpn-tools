# 本地规则包文件化

- 日期：2026-09-01
- 功能名：可编辑本地直连规则包
- 分支：main

## 需求概述

- 将 `local-direct-v1` 与 `cn-direct-v1` 从 Python 常量迁移为程序目录中的 UTF-8 文本文件，
  便于用户按行补充域名，不需要修改代码或重新打包。
- 扩充一组归属明确且长期稳定的国内站点主域名，同时保持规则离线、可审计和不后台下载。
- 按业务归属补充超星相关域名 `wisweb.com` 与 `cldisk.com`。
- 补充用户确认的中转站域名 `llm-api.net`，以及官方文档明确使用的国内 AI 模型/API 平台
  域名后缀；已有的 `aliyuncs.com` 继续覆盖阿里云百炼接入域名，无需重复配置子域名。

## 关键设计

- `local-direct-v1.txt` 每行使用 `TYPE,value[,no-resolve]`，出口固定为 `PHYSICAL`；
  `cn-direct-v1.txt` 每行只写一个域名后缀，并自动叠加本地直连规则。
- 两个文件支持 UTF-8 BOM、空行和整行 `#` 注释。软件启动时一次性读取并保存在内存中，运行期间
  不监听文件、不重复读取；外部修改在下次启动后参与配置生成。
- 加载器限制文件大小和条目数，校验规则类型、IPv4/IPv6、`no-resolve`、域名长度与 IDNA，
  对组合字符先执行 NFC 规范化，拒绝 URL、端口、路径、控制性分隔符和非 BMP 字符。
- 文件缺失或内容无效时，规则目录返回带行号的错误而不破坏页面加载；预检或应用当前规则包时
  转换为统一 `RoutingError` 并阻止错误配置进入原生服务。
- 标准与受保护打包都会把规则文件放在 exe 同级 `rule-packs/`，重打包前读取现有文件并在完成后
  原样恢复，避免覆盖用户手工增加的域名。
- 国内 AI 模型/API 平台新增 `baidubce.com`、`tencentcloudapi.com`、`volces.com`、
  `deepseek.com`、`stepfun.com`、`baichuan-ai.com` 与 `xf-yun.com`；以主域名后缀覆盖各平台
  当前及后续同后缀接口子域名。`.cn` 平台仍由通用 `cn` 规则覆盖，不重复添加。

## 影响范围

- `builtin_rule_pack` 的配置 ID、规则顺序和出口语义不变，不需要提升 routing schema 版本。
- `cn-direct-v1` 仍先包含 `local-direct-v1`，随后追加国内域名后缀；全局模式继续忽略规则包。
- 规则明细在界面中只读，但会说明对应文件位置；文件内容由用户在程序目录中维护。

## 注意事项

- 修改规则文件不会自动重载当前数据面，需重启软件；已运行的数据面在下次配置应用时使用启动时
  加载的规则快照。
- 规则包固定直连 `PHYSICAL`；需要代理、VPN 或阻止的域名继续使用界面中的有序用户规则。
