# 节点工作台筛选排序优化

- 日期：2026-09-01
- 功能名：节点地区筛选、质量排序与当前节点定位
- 分支：非 Git 工作区

## 需求概述与问题根因

节点工作台原先只支持订阅组、文本搜索和“仅显示可用”，69 个以上节点混排时需要逐卡浏览；
测速完成后也不能按延迟或倍率重排，已选择节点被搜索或筛选隐藏后缺少快速返回入口。对比
Clash Verge 的代理组筛选、排序和快速定位能力，当前工作台在大量节点场景下操作成本偏高。

## 关键设计

- 从节点国旗和中英文地区关键词推导地区，动态展示当前代理组实际存在的前七个地区及数量；
  未识别节点归入“其他”，地区筛选只影响展示，不修改订阅或节点数据。
- 新增订阅原始顺序、当前节点优先、延迟、倍率和名称五种排序。延迟排序依次展示可用且有延迟、
  可用但无延迟、未测速和不可用节点；所有排序保持稳定且不改变持久化顺序。
- “定位当前节点”会清除搜索、可用状态和地区筛选，切换为当前节点优先，滚动并聚焦当前卡片；
  没有手动目标或运行节点时按钮禁用。
- 将地区识别和排序抽到纯前端工具 `routing_nodes.js`，避免继续扩大已有 `routing.js`，并允许
  离线覆盖中文、组合字符和国旗非 BMP Unicode。

## 影响范围

- 只改变节点工作台的前端展示和交互，不改变测速任务、订阅缓存、手动选点持久化、Mihomo、
  system-proxy 或 TUN 行为。
- 地区与排序状态为当前页面会话状态，不写入 `config.json`。
