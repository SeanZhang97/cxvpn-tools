# 系统代理域名入口绕过

- 日期：2026-09-02
- 功能名：Windows 系统代理域名入口绕过
- 分支：main

## 需求概述

- 在软件中按每行一个域名维护 Windows 系统代理例外，使指定域名不经过本机 `mixed-port`。
- 保留 TUN 模式与按进程直连的 Mihomo 规则语义，并确保启停、快切、重启和事务回滚行为一致。
- 排查百炼 VLM 的 `SSL: UNEXPECTED_EOF_WHILE_READING` 是否由软件代理路径引起。

## 问题根因

- 原有 `system_proxy_bypass.domains[]` 只生成 Mihomo 内部 `DOMAIN-SUFFIX,PHYSICAL`，浏览器和
  Python `urllib` 仍先连接 `127.0.0.1:17890`；Windows `ProxyOverride` 只有固定的回环和私有
  地址规则。
- 百炼接口不带凭据的握手对比中，显式直连约 0.13 秒得到 HTTP 400，显式经过
  `127.0.0.1:17890` 约 3 秒复现 SSL EOF；`Api.test_vlm` 与验证码 VLM 都使用会继承 Windows
  系统代理的默认 `urllib.request.urlopen`，故障发生在软件代理路径。

## 关键设计

- Python 在完整配置事务中把规范化后的 `system_proxy_bypass.domains[]` 传给原生服务；IPC 协议
  升级为 5，服务版本升级为 0.5.0。
- 原生服务将域名保存到 `system-proxy-bypass.json`，并与配置、provider 数据、运行模式和快切
  标记一起备份、换入和回滚。快速开关与服务启动对账都从该文件恢复入口绕过。
- 每个域名生成 `domain;*.domain`，覆盖主域名和子域名。Rust 服务再次校验最多 100 条、ASCII
  域名标签和长度，拒绝分号、星号等 `ProxyOverride` 注入字符，并在写入后回读确认。
- UI 使用多行输入，每行一个域名或进程，不把逗号作为多个值分隔符。系统代理模式的域名从
  Windows 入口绕过；TUN 模式仍生成 `DOMAIN-SUFFIX,PHYSICAL`；进程始终由 Mihomo 识别。
- 不自动把整个国内规则包写入 Windows 入口绕过，避免具体国内域名的代理、VPN 或阻止规则被
  Windows 抢先绕过。

## 影响范围

- 保存了入口绕过域名的系统代理配置需要升级原生服务；首次升级会沿用既有 UAC 安装流程。
- 未配置自定义域名时生成的 `ProxyOverride` 与旧版本一致。
- 关闭代理、回滚或服务停止仍恢复接管前的 `ProxyEnable`、`ProxyServer`、`ProxyOverride` 和
  `AutoConfigURL` 原值。
