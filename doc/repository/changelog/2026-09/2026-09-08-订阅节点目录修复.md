# 订阅节点目录修复

- 日期：2026-09-08
- 分支：main
- 类型：订阅与节点运行逻辑修复

## 问题

订阅更新成功后，节点工作台偶尔只显示一个 `AUTO-…-FALLBACK`。订阅正文和 Mihomo provider 目录仍包含真实节点，但旧的自动策略组未及时重载时，展示快照把内部策略组误当成节点。

## 修复

- `proxy_overview` 递归展开运行态策略组，只保留真实叶子节点。
- provider 目录可用时按 provider key 或名称前缀补齐真实节点，兼容手动模式、自动模式及旧 Controller。
- 过滤 `/providers/proxies` 中返回的策略组对象，聚合“全部代理”时不再混入 `AUTO-*` / `PROXY-*` 内部组。
- 内部策略组不会再作为当前节点返回；节点快照只接收真实节点列表。

## 影响范围

影响订阅更新后的节点展示、节点测速、手动选点校验和代理首页当前节点状态；不改变订阅下载出口、代理组策略或系统网络接管行为。

## 验证

- `python -m unittest tests.test_routing_auto_policy tests.test_routing`：61 项通过。
- 覆盖手动模式残留 AUTO 组、provider 目录补齐、嵌套策略组展开和聚合目录过滤。
