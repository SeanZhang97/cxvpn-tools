# 代理工作区与连接日志

- 日期：2026-09-01
- 分支：main
- 功能：代理一级工作区、连接观测与 Mihomo 核心日志

## 需求概述

参考 Clash Verge Rev v2.5.2 的信息架构，把订阅、节点、规则、连接和日志从复合页面拆为一级入口；
在不暴露 Mihomo Controller 凭据的前提下查看活动连接和核心日志，并避免以固定轮询持续拉取大列表。

## 问题根因

- 订阅、规则和节点集中在域名分流复合页，网络代理首页快捷入口与配置入口层级不一致。
- 原日志页只包含程序后台日志，不能区分代理核心请求和应用任务日志。
- 全局状态流适合小型聚合快照，不适合高频传输完整连接与日志数组。

## 涉及文件

- 后端：`api.py`、`core/routing.py`、`core/mihomo_telemetry.py`、`core/mihomo_activity.py`
- 规则目录：`core/routing_rules.py`
- 界面：`ui/index.html`、`ui/app.js`、`ui/proxy.js`、`ui/routing.js`、
  `ui/routing_workspace.js`、`ui/routing_activity.js`、`ui/routing_activity.css`、`ui/routing_rules.css`
- 测试：`tests/test_mihomo_activity.py`、`tests/test_mihomo_telemetry.py`、
  `tests/test_ui_routing.js`、`tests/test_ui_routing_activity.js`

## 关键设计

- 侧栏新增订阅、节点、规则、连接入口，日志改为代理核心日志与程序运行日志双来源；网络代理保留
  启停、状态和高级分流入口。
- 订阅、规则、高级设置继续共享 `RoutingWorkspace` 的唯一草稿、已应用配置、dirty 状态和保存栏；
  页面重组只移动既有 DOM，不复制配置状态。
- `MihomoActivityRelay` 在后端连接 `/connections` 或 `/logs?level=debug`，同一时刻只订阅当前可见
  工作区。窗口隐藏、离开页面或切换到程序日志后转为 `idle`。
- 前端以版本游标阻塞等待变化；连接和日志不进入全局 0.5 秒 UI 快照。活动连接、关闭历史和核心日志
  均使用有界内存。
- Controller 端口和 secret 只由 Python 持有；核心日志进入 UI 前脱敏订阅 URL、URL 凭据、敏感查询
  参数和 Bearer token。连接页只保留排障所需字段，并把进程路径降为文件名。
- 关闭单个或全部连接统一经 `RoutingManager.close_connections` 调用 Controller DELETE 接口，API 日志
  覆盖提交、领取、执行和终态。
- 规则页展开当前离线内置包的完整只读规则，显示顺序、匹配类型、域名/网段、实际出口和附加选项，
  支持搜索及域名/IP 筛选；全局模式明确提示内置规则当前不参与匹配。所有包目录随 bootstrap/setup
  一次返回，切换未保存草稿时无需额外网络请求。
- 规则配置、内置规则筛选、连接排序和日志筛选统一复用分流工作区既有自定义下拉组件，不再展示
  浏览器/系统原生菜单；跨脚本通过 `RoutingWorkspace.enhanceSelect` 复用组件，并在禁用状态变化后
  刷新触发器。仓库 `AGENTS.md` 新增 UI 组件一致性规则，静态测试维护全部业务下拉框清单，新增裸
  `<select>` 会直接失败。
- 全局滚动条改为适配深色界面的统一轨道与圆角滑块，覆盖 `hover`、`active`、横向滚动和滚动角，
  隐藏 WebView2 默认箭头按钮，并为主内容、侧栏、规则列表、连接表格、日志和下拉浮层保留稳定
  布局占位。仓库规则与 UI 静态测试同步加入滚动区域约束。

## 影响范围

- 只调整本地 UI 导航、Mihomo Controller 观测和连接控制，不改变订阅缓存格式、节点测速逻辑、
  系统代理/TUN 启停事务或路由配置 schema。
- 核心日志和最近关闭连接默认不持久化，关闭应用后清空。

## 注意事项

- “连接”页展示的是当前 Mihomo 核心看到的连接；代理未运行时为空是正常状态。
- 核心日志为内存诊断视图，需要长期审计的程序任务日志仍查看“程序运行日志”。
