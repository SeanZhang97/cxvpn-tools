# 续期流程短信捕获与验证判定修复

- 日期: 2026-08-26
- 功能名: 授权/续期流程可靠性（短信捕获、691 自愈、精准判定）
- 分支: 非 Git 工作区

## 需求与根因

1. 手机已收到短信验证码，流程未继续（日志只见验证码重试）。
2. 691 认证被拒实际可能是授权到期，需续期后才能连接，但旧逻辑只会退避重试。
3. 「执行授权/续期流程」后长时间无输出，像卡死。
4. 需精准判定: 图标验证码通过 → 站点才发短信 → 短信码通过 → 才进续期页。

根因: 旧实现在图标验证码处理完才开始查通知库，期间到达/被清掉的短信丢失；
691 无续期联动；流程步骤无过程日志；验证码通过仅以弹窗消失为信号，短信码
提交后也不确认是否真正进入续期页。

## 涉及文件

- `core/sms_receiver.py`、`core/web_flow.py`、`core/captcha_handler.py`
- `core/worker.py`、`core/vpn_service.py`、`ui/index.html`

## 关键设计

- sms_receiver 新增 `Catcher`: 点击「获取验证码」前启动的后台线程，
  轮询 wpndatabase 入队暂存认证码（通知被清也不丢），`wait(timeout)`
  阻塞取码；捕获即打 `[sms]` 日志。
- worker: 连接失败含 691 时自动 `renew_requested.set()` 触发续期
  （10 分钟冷却 `_renew_trigger_after`）；续期成功后 `reset_backoff()`
  立即恢复重连节奏。
- 精准判定（站点行为: 图标验证码通过才发短信）:
  - `_wait_result`: 弹窗(#eject)关闭 且「获取验证码」按钮进入倒计时/
    变"重新获取"（正则 `\d+\s*[sS秒]|重新获取|重新发送|获取中|已发送|发送中`）
    = 确定通过且短信已发送；弹窗仍在 = 未通过刷新重试；弹窗关但文案
    未匹配 = 按通过处理（兼容文案差异，短信超时由整体重试兜底）。
  - 短信码提交后轮询 15s 等待「批量续期」文本出现，出现才认定进入
    VPN 续期页；未出现明确报"短信验证码未通过"。
- 全流程步骤日志（导航/已加载/登录流/点击获取/等弹窗/等短信/捕获/填码/
  提交/进入续期页）；VLM 调用超时 180s → 60s；日志措辞去"VLM 求解"化。
- vpn_service 691 提示与帮助页文案更新为"密码错误或授权到期"。

## 影响范围与验证

- `python -m py_compile` 三文件语法通过；已打包交付。
- 端到端（真实手机号 + 短信 + VLM 链路）待用户在 GUI 内实测确认。

## 注意事项

- Catcher 为 daemon 线程，流程结束 `stop()`；wait 返回后自动停止。
- 691 触发续期的冷却与续期失败 10 分钟重试相互独立，避免循环冲击。
