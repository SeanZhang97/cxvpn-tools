# 验证码 AI 坐标双帧仲裁与墨迹验证

- 日期: 2026-08-27
- 功能名: 图标点选验证码 AI 答案双帧仲裁 + 页面内墨迹验证 + 顺序源优先级修正
- 分支: 非 Git 工作区

## 需求与根因

1. 需求: 用户日志 10 次 AI 识别全部「点击位置不对」, 两次触发站点
   「失败过多, 点此重试」锁态, 最终转人工。需优化验证码识别链路。
2. 根因 (10 张失败样本像素级回放实锤, 三层):
   - **AI 坐标参考系漂移**: qwen-vl-max 同一提示词下时而输出 0-1000
     归一化、时而按送图 (2x 放大 640x480) 像素坐标作答、时而输出近乎
     重复的空想坐标 (如 [15,340]/[78,340]/[139,340] 与
     [48,335]/[79,360]/[132,335] 跨图雷同)。代码固定按归一化换算,
     像素帧答案被系统性压向原点 (x 误差达 36%, 图标半径级) —
     第 1 次尝试的答案在像素帧下三点墨迹分 245/70/17 落在真实图标上,
     却因换算错误而点空。
   - **无答案质量校验**: 空想坐标 (墨迹分全 0~5) 或三点挤在同一小块
     (最小间距 12px) 也照点不误, 白白消耗 attempt 并触发锁态。
   - **顺序源优先级颠倒**: `vlm_solve` 内先取 sprite 行1 裁剪 (图标
     仅 12~20px 2x 后 24~40px), 页面指令条截图 (单图标 2x 放大, 清晰
     得多, 为用户所见权威目标) 永远作为弃用的兜底, 语义匹配质量受损。

## 涉及文件

- `core/captcha_handler.py`:
  - 新增 `VALIDATE_JS`: 页面内墨迹评分 (点周围 17x17 patch 内
    |灰度 - patch 中位| >= 60 的像素数; 图标上 40~245, 背景 0~20)。
    阈值选局部对比度而非纯白/纯黑掩码的原因: 照片区图标是半透明
    压印 (混色), 纯阈值连通块 10 张样本 0 命中。
  - 新增 `_frame_candidates`: 同一答案按像素帧 (x/2, y/2) 与归一化帧
    (x*320/1000, y*240/1000) 双轨换算, 全点须落在 320x160 主图区。
  - 新增 `_pick_frame`: 双帧墨迹仲裁, 验收最弱分>=12 且中位>=25 且
    最小点间距>=18px, 双过取总分高者; 全不过视为空想弃用。
  - `vlm_solve` 重构: 顺序源按 页面指令条截图 > 行1 裁剪 > 整图自读
    逐级换源重问 (temperature 0 下重问同源必复现, 空想答案 break
    换源); `page=None` (probe 脚本) 保留归一化帧旧路径。
  - `PROMPT` / `PROMPT_FALLBACK`: 追加「看不清就回
    {"clicks": []}, 不许猜测或重复」反空想约束。
  - `get_tip_icons`: 选择器链追加 `.cx_tips__answer` (SDK load.min.js
    实测 class)。

## 关键设计

- 双帧仲裁把「模型用哪种参考系」从提示词承诺变成像素证据裁决,
  不依赖模型守约; 墨迹验证把「点没点在图标上」变成确定可判量,
  空想答案不再消耗站点容错额度。
- 阈值由 10 张失败样本回放校准: 模拟仲裁 4/10 答案 (像素帧真定位)
  被正确接受并换算到真实图标位置, 6/10 空想被拒 (其中含三点挤
  一块 12px 的答案)。

## 当日修复补充 (17:52 运行复盘)

上线后一轮 10 次尝试全部被判「空想」拒绝, 回放新样本发现两个实现缺陷:

1. **VALIDATE_JS 画布压扁 (全假阴性根因)**: `g.drawImage(img, 0, 0, W, H)`
   是 5 参形式, 把整张 320x240 sprite 压进 320x160 画布, 照片区被纵向
   压缩 2/3, 墨迹分与真实图标全对不上。修正为 1:1 全图解码
   (canvas 320x240, `drawImage(img, 0, 0)`) 后只取 y<160 建灰度。
   修正后用正确指标回放 17:52 的 10 份答案: 5 份实际为有效定位
   (PIX 帧 3 份 / NORM 帧 1 份 / 双帧皆可 1 份), 生产却全部被误杀,
   证实是假阴性而非模型退化。
2. **get_tip_icons 容器早停 (顺序源退化根因)**: 选择器链「命中第一个
   存在的容器即停止」, 而 SDK 模板常驻 `.cx_click-tip` (display:none,
   内部无 img), 永远取 0 图 -> 顺序源只剩行1 裁剪 (日志
   「AI 顺序源1/1: sprite 行1 裁剪」)。修正为逐容器收集 img 集齐 >=3
   张才收敛, 并加 6 次 x 0.5s 重试抵御 SDK 异步填充; 下载兼容
   data: URL 与协议相对/根相对路径。
3. 补充可观测性: 指令条提取失败时记日志「未提取到页面指令条…」。
