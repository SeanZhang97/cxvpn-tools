# 验证码识别四层方案

- 日期: 2026-08-26
- 功能名: 图标点选验证码识别升级（本地模板匹配 → 混合方案 → 端到端 VLM → 人工兜底）
- 分支: 非 Git 工作区

## 背景

原有 VLM 端到端方案（sprite 原图直发 AI 返回点击坐标）存在结构性缺陷:
AI 空间定位精度差（±8~15px）、顺序依赖 AI 读底部候选行（含反序陷阱）、
图标同色伪装导致语义混淆，整图通过率不理想且单次失败成本高（几十秒推理）。

## 关键设计

- 四级策略（`core/captcha_handler.py`）:
  1. 本地模板匹配（SOLVE_JS + `local_solve`）: 页面内 canvas 解码 sprite，
     指令行图标分割/填洞/归一化 28x28 做模板，主图候选同流程 IoU 贪心
     分配（min_iou 0.45）。命中即亚秒级出坐标、零成本；失败立即降级。
     debug 标注图存 `captcha_cache/solve_*.png`。
  2. 混合方案（SEG_JS + `hybrid_solve`）: 本地连通块分割取各图标精确
     质心（±1px），主图叠加红色编号导出 PNG；AI 仅做语义命名与排序
     （HYBRID_PROMPT，回 `names`/`order`），坐标全程不经 AI。
     顺序源优先页面指令条截图 `get_tip_bytes`（与用户所见一致）；
     无截图时回退完整 sprite 底部区域。
  3. 端到端 VLM 回退（`vlm_solve`）: 原有方案保留。
  4. 失败刷新重试（默认 3 次，每次刷新为新 sprite）: 先本地再混合再
     端到端依次尝试；最后人工兜底（工具内点击 / 有头 beep）。

## 关键取舍

- 早期 PoC 结论"纯本地 CV 不可行"针对的是"形状先验模板库"思路;
  本方案用当次 sprite 指令行图标做模板（同渲染批次、风格一致），
  规避了形状先验问题，故作为免费第一顺位先试，失败成本仅亚秒级。
- 本地模板匹配的指令行取的是底部第一行（minCy 行），若站点真顺序为
  中间行则顺序会错——因此主顺序判定必须落在混合方案的页面指令条
  截图（与用户所见一致），本地匹配链不做直通保证。

## 影响范围与验证

- `core/captcha_handler.py` 重构调度; 编译与导入通过。
- 待端到端实测（test_captcha.py 框架可复用）: 记录各层命中分布与
  整图通过率，确认四层调度收益。
