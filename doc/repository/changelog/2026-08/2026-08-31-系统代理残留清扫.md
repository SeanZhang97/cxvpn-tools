# 系统代理残留清扫

- 日期：2026-08-31
- 功能名：系统代理残留清扫（proxy_guard）
- 分支：非 Git 工作区

## 需求概述

第三方代理工具退出不干净时，Windows 手动系统代理仍指向 127.0.0.1 本地端口；
重启后端口无人监听，走 WinINET/WinHTTP 的流量全部失效。CXVPN管理器 承担
"清道夫"角色：正常关机前同步关闭这类代理；异常关机后（断电/蓝屏/强杀）在
下次启动时自检修复。不新增系统计划任务，不修改、不监视第三方工具。

## 问题根因

- 系统代理设置持久化在 HKCU 注册表，与代理进程生命周期无关：进程退出后
  设置仍在，重启后生效的代理指向无人监听的本地端口。
- 第三方工具的退出钩子无法覆盖断电、蓝屏、`taskkill /F`、快速启动等
  异常结束路径，只能靠其他进程在开机侧兜底。
- 本管理器自身不写系统代理（内嵌 Mihomo 使用随机 mixed-port + TUN），
  只能以保守条件判定"残留"，避免误伤仍在运行的第三方代理或公司代理。

## 涉及文件

- 新增 `core/proxy_guard.py`：注册表读写、条目解析、端口探测、
  脏标记与快照、启动自检 `startup_check`、关机清扫 `shutdown_cleanup`。
- `api.py`：`start()` 首位调用启动自检并登记待投递提示；新增
  `_os_shutdown_cleanup` 与 `flush_pending_desktop_notice`；
  `shutdown()` 末尾清除脏标记。
- `core/windows_desktop.py`：`DesktopController` 新增 `on_os_shutdown`
  回调，`_on_form_closing` 在 `WindowsShutDown`/`TaskManagerClosing`
  时同步清扫后再放行；新增仅气泡的 `notify`（`request_attention` 复用）。
- `main.py`：接线 `on_os_shutdown=api._os_shutdown_cleanup`，
  托盘就绪后投递启动自检结果。
- 测试：新增 `tests/test_proxy_guard.py`；扩展
  `tests/test_windows_desktop.py` 关机回调用例；
  `tests/test_vpn_creation_flow.py` 为 `Api.start()` 用例补齐
  `startup_check` 补丁与 `routing_updates` 桩。

## 关键设计

- 启动自检三重条件：脏标记存在（上次管理器异常结束）+ 代理已开启且全部
  条目指向回环地址 + 回环端口 TCP 探测无人监听；全满足才关闭手动代理。
- 关机清扫不检查端口监听状态：关机时第三方工具进程同样即将结束，只要
  代理开启且仅回环条目即先关闭再放行退出；该路径只做注册表级操作。
- 清扫前把现场（ProxyEnable/ProxyServer/ProxyOverride/AutoConfigURL）
  写入 `proxy_guard_snapshot.json` 供人工恢复与审计，不做自动回滚——
  管理器无法得知被残留覆盖之前的原始设置。
- 存在任何非回环条目（公司/运营商代理）时一律不动，避免误伤。
- 脏标记 `proxy_guard.json`：启动自检后写入 running；优雅退出清除。
  普通点击退出（系统仍在运行）只清标记、不碰代理，第三方工具若仍在
  运行不受影响。
- 修复结果通过托盘气泡（`DesktopController.notify`，不弹主窗口）提示。

## 影响范围

- 仅影响 HKCU 手动系统代理，勿需管理员权限；单实例互斥保证自检只跑一次。
- 覆盖场景：正常关机/重启/注销/快速启动（退出钩子），断电/蓝屏/强杀
  （下次启动自检）；第三方代理存活时（端口有人监听）自动跳过。
- 已知边界：管理器未运行时第三方工具遗留的代理不归管理器清扫，
  待下次异常的"管理器启动"触发；PAC/WPAD 型代理不在清扫范围。

## 验证情况

- 离线单测 250 个全部通过（新增 15 个 proxy_guard 用例与 4 个
  windows_desktop 关机用例）。
- `main.py`/`api.py`/相关模块 py_compile 通过。
- build.py 打包成功，dist 用户配置完整保留；新版启动后
  `proxy_guard.json` 脏标记生成、无 `[proxy]` 修复日志（首次运行无脏
  标记，符合预期），真实系统代理未被误伤。

## 注意事项

- `tests/test_vpn_creation_flow.py` 的 `make_api` 测试骨架此前缺少
  `routing_updates` 桩，两个 `Api.start()` 用例原本就会在
  `start()` 末尾报 AttributeError；本次补齐并要求将
  `startup_check` 打补丁，防止单测触碰真实注册表与仓库根目录标记文件。
- 若未来管理器自身需要写系统代理，应复用本模块的脏标记/快照语义，
  由"纯清扫"扩展为"谁写谁负责"。
