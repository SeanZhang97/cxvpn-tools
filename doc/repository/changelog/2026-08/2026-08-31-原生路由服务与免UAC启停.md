# 原生路由服务与免 UAC 启停

- 日期：2026-08-31
- 功能名：CXVPN 原生路由服务、配置事务与免 UAC 日常启停
- 分支：非 Git 工作区

## 需求概述

参考 Clash Verge 的控制面与高权限服务分层，但不集成其应用或源码。保留现有 Python UI、
订阅、节点和域名分流逻辑，自研精简 Windows Service，替换日常 WinSW/长 PowerShell 服务事务，
根治 `WinError 206`、重复 UAC 和配置应用失败后状态难恢复的问题。

## 问题根因

- 旧实现把服务安装、文件复制、ACL、Controller 等待和手动节点选择拼成大型提权 PowerShell；
  业务增长后即使压缩仍受 Windows 命令行上限和 PowerShell 编码行为约束。
- WinSW 直接托管 Mihomo，关闭代理等同于注销 Service，日常启停和规则更新都必须重新 UAC。
- GUI、SCM、Mihomo 和配置文件之间缺少稳定 IPC 协议，提权事务同时承担系统权限和业务就绪
  判断，维护成本与失败面持续扩大。
- TUN 同时启用 `strict-route` 和 DNS 劫持时，旧配置却关闭 `auto-detect-interface`。虽然 provider
  节点显式绑定物理接口，Mihomo 自身的 DNS 和控制连接仍可能被 TUN 再次捕获，形成出口递归；
  表现为同一节点在 Clash Verge 可用，而本软件显示启动成功后所有网站均无法访问。
- 失败诊断包含国旗节点名时，`Api.log()` 的裸 `print()` 依赖 Windows GBK 控制台，非 BMP
  Unicode 触发 `UnicodeEncodeError`；该旁路日志异常又发生在 rollback 前，遮蔽原始 TUN
  自检错误并延迟到服务端事务超时后才恢复路由。

## 关键设计

- 新增第一方 Rust `CXVPNRoutingHost.exe`，作为自动启动的 LocalSystem Windows Service；
  Service 常驻，Mihomo 根据 `enabled.marker` 独立启停和崩溃重启。
- Python 通过 `\\.\pipe\CXVPNRoutingService.v1` 发送定长 JSON 消息；管道 DACL 限制为
  LocalSystem、Administrators 和安装用户 SID，并拒绝远程客户端。
- UAC 只执行固定参数的原生安装程序。安装程序从 Windows Known Folder 获取 ProgramData，
  校验复制前后 Mihomo SHA-256、收紧 ACL、注册 SCM；失败时尝试恢复旧原生服务或 WinSW。
- 服务应用采用 `apply → commit/rollback`：候选配置和 provider 缓存经过大小、文件名与摘要
  校验，并在服务端再次执行 `mihomo -t`。Python 等待真实 provider、手动节点选中并回读后
  提交；失败、客户端崩溃或 90 秒超时均恢复旧配置、数据和运行标记。
- TUN 保持 `strict-route=true`，同时启用 `auto-detect-interface=true`，让 Mihomo 的 DNS、
  Controller 和其他内部连接从真实默认出口发出；业务 `PHYSICAL` 与 provider 节点仍显式绑定
  用户选择的物理接口，二者职责不冲突。
- 配置事务在 commit 前新增两层真实可用性门控：先通过 Controller 对当前承载流量的节点执行
  healthcheck，再从 Windows 系统网络栈执行 DNS 与 HTTPS 探测。任何一层失败都会自动 rollback，
  不再把“进程已启动”误报为“代理可用”。服务同时提供脱敏的最近日志诊断，便于定位启动失败。
- 日志文件继续以 UTF-8 保存完整节点名；控制台无法编码时按当前代码页转义降级且不再抛错。
  事务失败路径对日志和诊断统一采用 best-effort 隔离，任何日志读取、格式化或输出异常都不能
  阻断 rollback。Mihomo 与 PowerShell 文本子进程也显式声明 UTF-8 和替换策略。
- 服务状态同时返回协议版本、服务版本和自身二进制 SHA-256；包内摘要变化时自动进入一次 UAC
  升级，摘要一致时日常启停、规则更新和模式切换不再提权。
- `WinSW-x64.exe` 与旧 PowerShell 事务保留为迁移回退，不再承担新版日常生命周期。
- 构建脚本按源码时间戳增量编译 Rust release 产物并放入 `runtime/routing`，随后由普通或受保护
  PyInstaller 流程统一打包。

## 影响范围

- 不改变 `config.json.routing`、订阅缓存、节点快照和 Controller API 契约。
- 首次使用或原生 Service 二进制升级会出现一次 UAC；以后关闭只停 Mihomo，不注销 Service。
- 已安装旧 WinSW 服务在下一次启用时迁移；旧服务关闭仍可走原注销路径。
- 当前仅支持 Windows x64，目标机不需要 Rust 或 .NET 运行时。

## 注意事项

- 原生服务源码或依赖变化后会触发一次服务摘要升级和 UAC，属于预期行为。
- `routing-service/target/` 是本机构建缓存，不进入源码或 PyInstaller 产物。
- 服务与 Mihomo 日志位于管理员 ACL 保护的 ProgramData 服务目录。
