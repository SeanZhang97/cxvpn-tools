# 2026-08-28 浏览器刷新卡死修复

- 日期: 2026-08-28
- 功能名: 内置浏览器刷新卡死修复
- 分支: 非 Git 工作区
- 类型: Bug 修复

## 问题现象

用户在内置浏览器点击“刷新”后，页面已经重新加载并继续产生网络请求，但主界面
右上角按钮始终停留在“刷新中…”，无法恢复为可点击状态。

## 问题根因

- 通过 Computer Use 截图确认：超星 VPN 页面、原生进度浮层和网络请求列表均已
  正常显示，只有主 UI 刷新按钮卡在忙碌态，说明页面刷新成功但 JS 桥调用未返回。
- `PageShim.reload()` 通过 `eval_js('() => location.reload()')` 刷新。`eval_js` 会把
  异步结果写入当前文档的全局结果槽，再轮询读取；`location.reload()` 导航后旧文档
  及结果槽立即销毁，因此永远无法读到完成结果。
- `eval_js` 只在单次 `ExecuteScriptAsync` 等待超时时检查截止时间；当新页面持续快速
  返回 `undefined` 时，轮询分支没有总截止判断，会无限循环，导致前端 `runBusy`
  的 `finally` 永远无法恢复按钮。

## 涉及文件

- `core/browser_win.py`
- `api.py`
- `ui/app.js`
- `tests/test_browser_reload.py`
- `doc/repository/knowledge/modules/CXVPN管理器.md`

## 关键设计

- `PageShim.reload()` 改为调用 `NativeBrowser.reload()`；后者通过 WebView2 原生
  `CoreWebView2.Reload()` 发起刷新，并使用已有 `_loaded` 事件等待
  `NavigationCompleted`，默认上限 20 秒。
- `eval_js` 轮询入口增加总截止检查。即使页面导航销毁结果槽、异步表达式永久不
  返回或新文档一直返回空值，也会按调用超时退出，不再永久占用桥接线程。
- `Api.browser_reload()` 返回 `{ok, msg}`，区分成功、刷新超时和浏览器未启动。
- 前端刷新调用增加 25 秒 `Promise.race` 保护；即使后端发生未知阻塞，`runBusy`
  仍会执行 `finally`，按钮恢复并给出可读错误。

## 影响范围

- 影响内置浏览器右上角手动刷新，以及所有通过 `eval_js` 执行后页面发生导航的异常
  边界。
- 不改变授权流程、验证码处理、浏览器持久化目录、网络请求采集或外部页面逻辑。

## 注意事项

- 发起页面导航的动作不能依赖旧文档中的 JS 全局变量回传完成状态，应使用 WebView2
  导航事件或浏览器原生 API 判定。
- 前端超时只负责恢复交互，后端仍必须有独立超时，避免桥接线程泄漏。
