# 内嵌浏览器面板与续期流程接口化

- 日期: 2026-08-27（第二版，继「内置浏览器原生化」之后）
- 功能名: 主窗口内嵌 WebView2 面板 + 登录/续期改调接口
- 分支: 非 Git 工作区

## 需求与根因

1. 用户要求把内置浏览器真正嵌入工具窗口（而非独立窗口）。
2. 用户手动走流程抓包完成, 站点接口链已明: 除图形验证码外全部步骤
   可改调接口, 自动化更稳更快。
3. 授权/续期点击后站点 `window.open` 新页 (VPNLoginSuccess), 旧默认配置
   会甩到系统浏览器, 需在内置浏览器内导航。

## 涉及文件

- `core/browser_win.py` (重写: 主表单内第二 WebView2 控件)
- `core/web_flow.py` (重写: 接口化登录/续期, DOM 兜底)
- `core/worker.py`、`main.py` (传入主窗口/存储路径)
- `ui/index.html` 文案

## 关键设计

- **真内嵌**: 主窗口 WinForms 表单内 `Controls.Add` 第二个 WebView2 控件,
  主窗口 +900 宽, Resize 时按 42%/剩余分栏。实验结论: 同表单第二控件与
  主窗口**共用 UserDataFolder 报 0x8007139F** (独立窗口+同目录则可行),
  故内嵌面板用独立子目录 `webview_data/embed/` (磁盘持久化, 首次需登录
  一次, 之后保留登录态)。
- 新窗口请求: `NewWindowRequested` → Handled + 同控件 Navigate (授权成功页
  留在面板内)。
- 抓包/选择器/标记钩子改 `AddScriptToExecuteOnDocumentCreatedAsync` 注入
  (每次导航自动生效, 不再依赖 loaded 重注入)。
- **接口化流程** (页内同源 fetch, cookie 自动携带):
  - 登录: 填手机号+点获取验证码 (DOM, 触发验证码弹窗) → 验证码模拟点击 →
    页面自动 getSmsCode → 等短信 → `POST /vpn/checkCode`
    (phoneNumber&code) 得 VPN 列表 (vpnId/名称/过期)。
  - 续期: `POST /vpn/batchReLoginVpn/addTime` (phoneNumber&vpnIdsSel=id)。
  - 已登录态: 尝试 DOM 读 checkbox value=id 匹配目标; 失败/授权场景回退
    页面点击 续期/授权, 成功以面板内导航到 VPNLoginSuccess 判定。
- 接口清单 (抓包实测): `GET /vpn/getSmsCode/{phone}?validate=...`、
  `POST /vpn/checkCode`、`POST /vpn/batchReLoginVpn/addTime`、
  验证码 JSONP `captcha.chaoxing.com/captcha/{get/verification/image,
  check/verification/result}` (textClickArr 为点击坐标)。

## 影响范围与验证

- 冒烟实测: 双栏布局 (707+977) ✔、document-created 钩子自动注入 ✔、
  抓包 ✔、eval_js Promise ✔。
- 待端到端: 内嵌面板内完整登录 (embed 目录首次需短信登录) + 接口续期。
- 授权接口未抓 (授权按钮当前由 DOM 兜底覆盖); 方便时下线→授权补抓。

## 注意事项

- WebView2 同进程多环境: 独立窗口可同 UserDataFolder, 同表单多控件不可
  (0x8007139F) —— 后续如需多面板各用独立子目录。
