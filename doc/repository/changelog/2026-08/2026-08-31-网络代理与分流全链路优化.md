# 网络代理与分流全链路优化

- 日期：2026-08-31
- 功能名：网络代理与域名分流全链路可靠性、交互和视觉优化
- 分支：非 Git 工作区

## 需求概述

从网络代理首页、节点工作台、域名分流规则和订阅管理一路审查到配置提交、订阅缓存、
Mihomo 预检与 WinSW 服务安装，修复状态不同步、错误恢复不完整、节点统计混乱和操作反馈
不可见等问题，并统一页面语义、键盘交互和异常状态处理。

## 问题根因

- 分流初始化期间 `busy` 状态阻止网络代理首页完成最终同步，导致“开启代理”可能一直禁用；
  页面也混用了草稿、已应用配置和运行状态。
- 节点工作台被伪装成分流页签，返回路径和 ARIA 关系不完整；订阅说明伪节点混入可选节点、
  测速和统计。
- “全部测速”使用同步整组请求并占用交互锁，任务结束前既没有进度，也不能逐节点回显或停止；
  大量节点时用户会误以为按钮失效。
- 订阅只持久化 provider YAML 和节点数量，重启 GUI 后没有可直接展示、校验或选中的安全节点
  清单；运行态节点名又带订阅前缀，无法直接作为稳定偏好保存。
- 节点策略、即时 Controller 切换和“开启代理”之间缺少持久化目标与启动应用步骤，用户无法明确
  指定下次开启代理实际使用哪个节点。
- 服务状态读取异常被折叠成“未安装”，关闭时可能给出错误成功语义；服务更新缺少完整性复核、
  就绪门控和失败回滚。
- 服务变更与 `config.json` 保存不是一个可补偿提交；订阅正文和元数据也可能只更新一半。
- Mihomo 原始错误可能包含订阅 URL 或凭据，预览配置使用固定目录保存了不必要的敏感草稿。
- Mihomo v1.19.30 不再把 proxy-provider 节点放入通用 `/proxies` 目录，但节点测速和运行态
  详情仍只调用旧接口，导致每个节点都返回 `404 Resource not found` 并被误判为不可用。
- 停止并发测速时已开始的任务仍会回显，但结果收集循环提前退出，可能让最终快照少于界面
  已完成数；未保存的预览订阅则无法直接保存目标节点，选点流程在“订阅不存在”处中断。
- 服务安装事务过早删除回滚备份，Controller 就绪但 provider 尚未加载或手动选点失败时会丢失
  原服务；未承载流量的手动订阅也会被无条件校验和应用。
- 取消运行态测速会用部分结果覆盖完整快照；快照只绑定 URL 而未绑定筛选条件；更新失败回退
  旧缓存仍刷新时间戳；YAML 导入的缓存与节点快照不在同一事务。
- 运行态更新在后续读取失败时仍返回成功并清空前端组；保存节点偏好会隐式修改默认出口；短暂
  轮询失败会遗留后台测速；前后端订阅信息分类不一致；单节点测速结果不持久化。
- provider 组配置了 `empty-fallback: REJECT`。服务刚启动、真实节点尚未加载时，Controller
  会暂时返回只包含 `REJECT` 的组；安装事务仅以成员数非零判断就绪，随后过早切换手动节点并
  触发回滚。提权子进程的异常又没有回传到普通权限进程，因此界面只能笼统提示检查 UAC。
- 修正上述就绪条件后，Windows PowerShell 5.1 的 `Invoke-RestMethod` 又把 Mihomo 未声明
  `charset` 的 UTF-8 JSON 响应按系统代码页解码，中文订阅名、国旗和节点名全部成为乱码；
  provider 实际已加载 72 个节点，但字符串精确比较永远失败，手动节点仍无法提交。
- UTF-8 原始流处理使提权事务脚本增长，继续以完整 UTF-16 Base64 放进外层 `-Command` 时超过
  Windows 约 32K 的进程命令行限制，Python 在弹出 UAC 前直接返回 `WinError 206`。

## 关键设计

- 分流加载改为单例 in-flight Promise，并增加短时 TTL；网络代理首页只读取已应用配置和运行
  状态，高级页保留独立草稿，刷新时可显式选择保留或放弃草稿。
- 网络代理首页按 `off`、`running`、`degraded`、`unknown` 四态渲染；异常态提供重试启动与
  仅关闭配置，未知态只允许重新检查，避免重复启动或误判关闭。
- 分流主导航保留三个真实 `tab`，节点作为独立工作台动作；工作台记住来源并返回原页签，
  节点操作反馈放在当前可见页面的 `aria-live` 区域。
- 订阅信息伪节点单独展示，不参与可选节点、测速、可用数和节点卡片；国旗字符转换为稳定的
  ISO 双字母徽标，未测速、已测速不可用和可用状态分开表达。
- 订阅预览支持“临时全部测速”：复用无 TUN、无代理监听端口的临时 Mihomo 和本地 Controller，
  只读取 URL 指纹匹配的本地缓存作为 `file` provider，不安装 Windows 服务、不刷新订阅、
  不接管系统流量；测速结束后回填节点延迟/可用状态并强制回收进程。
- 全部测速改为后台任务：最多 8 路调用节点测速接口，前端每 250ms 轮询总数、完成数、
  可用数和失败数；每个结果完成后立即更新对应卡片，并支持停止。订阅说明伪节点不进入任务。
- 节点测速按来源选择 Controller 接口：provider 节点调用 provider 专用 `healthcheck`，普通
  内联代理保留 `/proxies/<name>/delay`；运行态代理组从 `/proxies` 读取组结构并合并
  `/providers/proxies` 的节点详情，兼容 Mihomo v1.19.30 的 API 行为。
- 取消测速只取消尚未启动的 future，已经运行的节点继续收集并与完整节点列表合并进入最终
  快照。预览草稿中点击“使用此节点”时，后端在节点快照校验通过后保存订阅草稿和手动节点，
  但不隐式启用订阅或修改默认出口。
- 新增按 URL 或“URL + 筛选条件”签名隔离的 `.nodes.json` 安全快照，只保存节点展示和测速
  白名单字段并原子替换；
  GUI 重启后可恢复节点列表和延迟，不持久化服务器、UUID、订阅 URL 或连接参数。
- 订阅新增 `selection_mode`、`selected_node`、`auto_update`。节点卡“使用此节点”直接保存原始
  节点名且不改变默认出口；开启服务前验证实际被引用订阅的节点仍存在，Controller 就绪后应用带订阅
  前缀的运行态节点名。节点被订阅移除时立即告警并阻止下次开启，直到重新选择。
- 自动更新默认关闭；开启后，服务关闭且 GUI 运行时由后台线程按周期更新，服务运行时由 Mihomo
  provider 负责。用户始终可以手动更新订阅。
- 规则启用状态可在列表中独立切换并完整持久化；新订阅默认是未验证且停用的草稿。
- `config.json` 采用同目录临时文件、`fsync` 和 `os.replace` 原子提交。服务先变更、配置后提交；
  若配置保存失败，自动重新应用原分流状态，同时保留期间发生的非 routing 配置更新。
- 订阅 YAML 与元数据采用成对提交和旧版本快照回滚；YAML 导入把正文、元数据、节点快照作为
  三文件事务提交；在线更新失败不刷新旧缓存时间戳。损坏元数据整数被安全限界，导入候选只有
  在 Mihomo 解析成功后才替换 last-known-good。
- Windows 服务状态无法确认时使用 `Unknown`，关闭和保存关闭状态均安全失败。服务更新复制后
  重验 Mihomo、WinSW 和配置摘要，检查 ACL 命令退出码；在同一回滚事务内等待 Controller、
  实际引用 provider 和手动节点全部就绪后才提交，失败时恢复旧服务文件、数据和注册状态。
  就绪判断排除 `empty-fallback` 的 `REJECT`；手动模式必须等目标运行态节点名实际出现在组中，
  避免 provider 异步加载窗口造成误回滚。
- 运行态订阅更新必须确认目标组非空；单节点测速写回安全快照；前端轮询使用指数退避并在持续
  失败时显式取消；前后端统一订阅说明节点识别规则。
- Mihomo 错误统一移除 URL、token、Authorization 等敏感字段；预检与导入使用系统临时目录。
- UAC 子进程通过随机临时结果文件回传事务异常；普通权限进程读取后立即删除、统一脱敏，并将
  已知服务就绪错误转换为可操作中文提示，不再把业务回滚误报成 UAC 或服务注册故障。
- 提权脚本不再使用 `Invoke-RestMethod` 读写 Controller。统一通过 `HttpWebRequest` 设置超时、
  以 UTF-8 字节发送 JSON，并用 `StreamReader(UTF8)` 解码原始响应流；就绪判断、手动节点 PUT
  和回读确认使用同一编码路径，避免系统代码页参与节点名比较。
- 完整提权事务先以 GZip 压缩，再把短小解压启动器作为 `-EncodedCommand` 传给管理员
  PowerShell；脚本不落地为可被普通权限进程替换的 `.ps1` 文件。执行前检查外层命令长度，超过
  30,000 字符时安全失败并保持分流配置不变。

## 影响范围

- `config.json.routing.proxy_providers[]` 以兼容方式新增 `selection_mode`、`selected_node` 和
  `auto_update`；旧配置按原策略自动迁移。`rules[].enabled=false` 仍会保留并在生成运行配置时跳过。
- 聚合 `proxy` 出口必须至少引用一个已启用订阅，具体 `proxy:<id>` 必须指向已启用订阅。
- 网络代理和域名分流共享同一运行状态，但草稿不再覆盖首页的已应用状态。
- 预览订阅选点会把该订阅作为已启用配置提交；其他尚未保存的页面草稿仍保留并继续显示未保存状态。
- 服务更新失败会多一次旧版本恢复尝试，耗时可能略增，但不会把未就绪的新服务当作成功。

## 注意事项

- 服务安装和补偿回滚仍依赖 Windows SCM、UAC、ProgramData 权限及本机运行时；应在允许短暂
  网络中断的维护窗口做一次真实启停回归。
- 缓存中只保存历史 `node_count` 时，该数字表示缓存记录数；完成订阅解析后界面会按可选节点
  与订阅信息重新分类。
