# VPN 配置、凭据与授权状态联动修复

- 日期：2026-08-28
- 分支：非 Git 工作区

## 需求概述

修复按钮执行后样式错乱、新增 VPN 后总览不刷新、无法在软件内创建 Windows VPN、
授权成功后页面状态滞后，以及软件连接与 Windows 手动连接结果不一致的问题。最终
要求是在软件中保存 VPN 账号密码后同步到 Windows，点击连接直接无界面拨号；保存
凭据不主动连接、不打开网页，也不再维护“待授权验证”步骤。

## 问题根因

- 通用忙碌态覆盖按钮 `innerHTML`，结束时只恢复 `textContent`，破坏了原按钮结构。
- VPN 列表强制刷新可能被启动阶段的普通请求吞掉；总览仅渲染活动连接，新增但未连接
  的 Windows VPN 不会出现。
- 原新增流程缺少协议参数、L2TP 密钥和账号密码的一体化录入。
- 授权接口成功后没有同步当前远端页面 DOM，列表继续显示旧状态；完成提示又作为
  常驻内容插入表格，破坏了布局。
- 旧凭据流程把保存和远端授权混为一次“先连接验证”，导致尚未授权的新 VPN 无法
  正常保存，并产生没有必要的待授权状态机。
- 旧软件连接使用 `RasGetCredentialsW` 返回的星号密码句柄。本机 RasClient 事件显示
  PPTP 实际提交的拨号用户为 `*\\` 并报 628，而 Windows 设置页手动连接提交真实
  用户名后成功，因此不能继续依赖该包装路径。
- IKEv2/EAP-MSCHAPv2 用普通用户名密码调用 `RasDialW` 会返回 703。旧逻辑随后调用
  `RasDialDlgW`，而该 API 的职责就是显示系统拨号界面，所以无论 PBK 预览开关如何
  设置，都可能出现用户看到的旧式账号密码弹框。
- `Get-VpnConnection.ConnectionStatus` 在连接完成后可能短暂滞后；旧 `rasdial`
  解析器也遗漏了“标题一行、名称后续一行”的本机输出格式，造成系统已连接而软件
  仍显示未连接。
- 连接结束后前端已拿到后端刷新完成的 `profiles`，却再次执行完整列表查询，并在查询
  前清空表格显示“正在读取”，造成每次连上或断开都像整页刷新。
- VPN 操作区使用内容宽度自适应的 flex；默认行缺少“设为默认”按钮，导致不同行的
  按钮数量、起始位置和列间距不同，视觉上无法纵向对齐。
- 表单控件同时命中 `input:focus` 的紫色三像素 `box-shadow` 和全局
  `input:focus-visible` 的青色两像素外扩 `outline`，叠加成明显的双层粗焦点框。
- 前端只在进入“VPN 配置”页时调用 `list_vpns`，首次点击必然等待 PowerShell 系统查询；
  总览轮询虽持有连接状态，却没有可复用的完整配置缓存。

## 关键设计

- 忙碌态完整保存和恢复按钮 DOM；强制刷新采用排队合并，并在新增、连接和断开完成后
  刷新 Windows 配置列表、总览和连接快照。
- 软件可直接创建或修改 Automatic、PPTP、L2TP、SSTP、IKEv2 Windows VPN；L2TP
  支持预共享密钥，新建时可同时录入登录凭据。
- 保存账号密码立即写入软件配置和普通 RAS 凭据槽。若条目使用 EAP-MSCHAPv2，读取
  `EapConfigXmlStream`，通过 `EapHostPeerConfigXml2Blob` 与
  `EapHostPeerCredentialsXml2Blob` 生成凭据数据，再调用 `RasSetEapUserData` 写入。
- EAP 写入后通过 `RasGetEapUserIdentity(RASEAPF_NonInteractive)` 校验 Windows 能
  无界面取得身份；连接时将返回的 `RASEAPINFO` 交给 `RasDialW`。代码不再调用
  `RasDialDlgW`，因此点击连接不会打开系统账号密码弹框。
- PPTP 等普通连接直接将软件保存的真实用户名和密码传给 `RasDialW`，避免星号密码
  句柄导致的错误拨号用户。密码不再出现在 `rasdial.exe` 命令行参数中。
- 软件缺少完整凭据时不调用任何可能弹框的系统连接路径，直接引导用户在软件内补录。
- 保存凭据只做本机同步，不拨号、不打开网页、不触发授权；移除待授权验证队列、授权
  后自动复验和对应前端标签。启动时迁移清理旧的 `pending_authorization`、
  `validated`、`validation_failed`，只保留 `windows_sync_failed` 本机异常提示。
- 应用启动时对每条完整工具凭据重新执行普通 RAS 与 EAP 同步，修复旧版本漏写；该
  动作不连接 VPN。实际连接返回 691 时仍由既有授权续期流程处理。
- Worker 状态刷新合并 `Get-VpnConnection` 配置与 `rasdial` 实时会话，并按完整名称
  `casefold` 精确匹配，避免连接成功后页面仍显示未连接。
- 连接和断开完成后直接使用返回的 `profiles` 快照，按 VPN 名称及渲染键原位更新发生
  变化的表格行，不再进入列表加载态或重复查询 Windows。已有列表上的手动/业务刷新
  会保留当前内容直至新快照到达；刷新失败也保留旧列表并仅显示错误提示。
- 操作区改为固定五槽栅格：连接状态、默认状态、凭据、编辑、删除。默认行使用低强调
  的“已默认”只读状态占据相同槽位，所有行的按钮宽度和间距保持一致；操作按钮放入
  表格单元格内的独立容器，避免把 `td` 本身改成 flex/grid 影响表格布局。
- 文本、密码、数字、原生选择框、文本域及自定义下拉统一使用 `1px` 青色聚焦边框，
  移除阴影和外扩 outline；checkbox/switch 不套用该规则，普通按钮仍保留键盘焦点
  提示，兼顾统一视觉和可访问性。
- 软件启动完成配置读取后立即后台预取 VPN 列表；Worker 持有带检查时间的配置快照，
  `list_vpns(false)` 优先复用后台缓存。进入配置页复用前端已完成的 Promise/列表，不再
  重复查询；仅“刷新”以及新增、编辑、删除等明确变更使用 `force_refresh=true`。
- 普通预取与强制刷新分别去重；强制刷新不会被正在执行的普通预取吞掉。已有内容刷新失败
  时保留旧列表并提示错误，不重新切回整页加载态。
- 授权接口成功后同步更新远端页面行状态；完成提示改为顶部瞬时浮层，不再挤压表格。

## 注意事项

- 新增或保存 VPN 凭据不会自动打开授权页；用户仍通过“立即处理授权”主动发起。
- `config.json` 的 `creds` 仍包含明文密码副本，分发前必须按既有规则清理敏感配置。
- 当前 EAP 无界面凭据实现面向 EAP type 26（EAP-MSCHAPv2）；其它 EAP 方法会返回
  明确的不支持提示，不会降级弹出系统连接窗口。
