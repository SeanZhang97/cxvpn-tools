# 启动首屏与 VPN 配置预展示

- 日期: 2026-08-29
- 功能名: 启动空白窗口消除与活动连接渐进加载
- 分支: 非 Git 工作区

## 问题根因

普通启动以 `hidden=False` 创建 pywebview 窗口，Windows 原生窗口会早于 HTML、CSS 和
前端配置初始化显示，因此短暂出现整块空白深色画布。活动连接首次渲染又直接采用 Worker
尚未完成 Windows 查询时返回的空 `profiles`，把“尚未查完”错误展示成五个新增槽位。

## 涉及文件

- `main.py`
- `api.py`
- `ui/app.js`
- `tests/test_ui_polish.js`
- `doc/repository/knowledge/modules/CXVPN管理器.md`

## 关键设计

- 主窗口统一以 `hidden=True` 创建；普通启动在前端完成本地配置预展示并调用
  `ui_ready` 后才显示，开机自启仍保持静默托盘模式。
- 页面加载后启动托盘；普通启动若 5 秒内未收到首屏就绪通知，自动显示窗口作为异常兜底，
  避免脚本初始化失败时窗口永久不可见。
- 首屏从 `config.json` 的 `vpn_name` 和 `creds` 键名去重生成临时 VPN 行，只展示名称并
  标记“正在核对 Windows VPN 状态”，不把未知连接状态伪装为“未连接”。
- Worker 或 `list_vpns` 完成查询后，临时行由 Windows 返回的协议、服务器、连接状态及
  路由信息原位替换；真实查询为空时仍以 Windows 结果为准。

## 影响范围

- 普通启动窗口显示时机、开机自启托盘初始化、总览活动连接首次渲染。
- 不改变 `config.json` 结构，不持久化额外系统 VPN 信息，不改变自动连接和拨号逻辑。

- `config.json` 只具备默认 VPN 名称和工具保存过凭据的 VPN 名称，不含完整的服务器、协议、
  路由或实时状态；这些字段在 Windows 查询完成前统一显示为“读取中/正在核对”。
