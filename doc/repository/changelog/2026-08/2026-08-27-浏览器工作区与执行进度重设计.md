# 浏览器工作区与执行进度重设计

- 日期: 2026-08-27
- 功能名: 内置浏览器工作区重设计
- 分支: 非 Git 工作区

## 需求概述

原生 WebView2 通过扩大主窗口并在右侧横向拼接，导致窗口过宽、主 UI 被压缩，
浏览器与工具界面缺少统一层级。改为 16:10 桌面工作区，并在浏览器画布内展示
真实自动化进度和可收起的网络请求抽屉。

## 关键设计

- 默认窗口调整为 1440×900，原生 WebView2 只覆盖浏览器页预留画布，不再修改
  窗口宽度或分割主 UI；切换到其它导航页时隐藏原生控件。
- 浏览器页收敛为顶部命令栏和单一浏览器画布，启动前显示空状态，启动后显示
  URL、运行状态和刷新操作。
- `web_flow.ensure_authorized` 通过回调上报五个真实阶段：启动浏览器、打开授权
  页、登录与短信验证、验证授权状态、完成授权/续期；失败和完成状态由 worker
  统一收口。
- 进度卡与网络请求抽屉通过 document-created 脚本注入原生浏览器页面，并使用
  Shadow DOM 隔离站点样式。点击进度卡标题收起/展开；“网络请求 N”打开抽屉，
  行点击继续查看请求体和响应体详情。
- 手动打开浏览器但未执行自动续期时显示“等待自动化任务”，不伪造执行进度。
- 修复真实运行中浮层偶发完全缺失：WebView2 的
  `AddScriptToExecuteOnDocumentCreatedAsync` 注册是异步的，首次导航可能早于
  注册完成，旧逻辑又会丢弃浮层不存在时的状态推送。现改为导航完成后补注入并
  恢复缓存状态、状态推送发现浮层缺失时立即自愈、worker 每秒心跳复核；浮层
  z-index 同时提升到浏览器允许的最大值。
- 修复验证码或手动短信弹窗出现时主界面变暗、左侧菜单无法操作但看不到弹窗：
  原因是 pywebview HTML 遮罩层覆盖主界面，而弹窗卡片被同窗体上的原生
  WebView2 控件压在下层。阻断型弹窗现在会先隐藏原生浏览器再显示；提交、
  关闭或后台状态消失时，再根据当前页面以及是否仍有其它阻断型弹窗恢复浏览器。

## 影响范围

- 影响主窗口初始尺寸、浏览器页布局、原生 WebView2 可见性与授权/续期状态展示。
- 不改变 VPN 连接、验证码识别、短信捕获、授权/续期接口及抓包落盘契约。

## 注意事项

- 原生 WebView2 与主 UI 是同一 WinForms 表单上的两个控件，浮动进度与网络抽屉
  必须注入原生浏览器页面，不能依赖底层 HTML 跨原生控件叠放。
- 浏览器仍使用 `webview_data/embed/` 独立持久化目录，首次使用可能需要重新登录。
