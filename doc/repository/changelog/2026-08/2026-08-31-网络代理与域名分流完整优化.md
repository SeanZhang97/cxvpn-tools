# 网络代理与域名分流完整优化

- 日期：2026-08-31
- 功能名：网络接管、规则分层、系统代理事务与 DNS 全链路优化
- 分支：非 Git 工作区

## 需求概述与根因

旧配置把“启用”固定等同 TUN，网络接管、流量策略和默认出口没有独立契约；首页启停和模式
切换会隐式改写默认出口。运行配置只有用户规则和单层 DNS，系统代理仅用于订阅恢复，缺少
完整四字段快照、服务级 Guard 与崩溃熔断。健康检查也无法分别证明显式本地代理链路和实际
Windows 系统代理链路。

## 关键设计

- 引入 routing schema v2。新安装默认 `system-proxy + local-direct-v1`；缺少 schema 的旧配置
  强制迁移为 `tun + off`，保留原流量路径。
- `capture_mode`、`traffic_mode`、`default_outbound` 独立。系统代理与 TUN 互斥；首页启停、
  规则/全局切换和节点偏好均不再改写默认出口。
- 固定生成顺序为启用用户规则、版本化只读内置规则、`MATCH`；global 只生成 `MATCH`。
  `local-direct-v1` 与 `cn-direct-v1` 全部随包离线交付，不依赖在线规则集。
- 系统代理模式启用 Mihomo `mixed-port`。Rust 服务以当前用户 SID 操作注册表，完整保存并恢复
  `ProxyEnable`、`ProxyServer`、`ProxyOverride`、`AutoConfigURL`，写入安全 bypass；启用位最后
  写入/恢复，避免中间态指向错误端口。
- 系统代理激活属于 apply/commit/rollback 候选事务；健康失败、事务超时、rollback、停止、
  Service 关闭和运行时崩溃均恢复快照。Mihomo 60 秒内连续崩溃三次后熔断并删除运行标记。
- 健康门控覆盖 Mihomo 语法、Controller、provider、手动节点、节点 healthcheck、显式本地
  mixed-port 和 Windows 系统链路；公网链路采用三个端点、有限超时和错误分类。
- DNS 增加 `default-nameserver`、`proxy-server-nameserver`、`direct-nameserver`；fake-IP 同时
  配置 IPv4/IPv6。启用 `unified-delay`、`tcp-concurrent`，运行配置继续由白名单字段生成。
- Controller `/connections` 只输出去标识化连接数与 `user/builtin/default` 规则命中聚合。
- UI 同时展示接管方式、流量策略、默认出口，以及用户/内置/实际规则数；手动节点增加明确确认。
- UI 启动改为两阶段：`get_routing_bootstrap` 只读本地 routing 配置、节点快照与
  原生服务 IPC，不等待 VPN/网卡/TUN 扫描；真实订阅和节点先回显，完整
  `get_routing_setup` 在后台补齐环境状态。
- 首页“开启代理”先基于已读取快照立即展示中性“网络接管确认”，用户确认后才
  执行慢状态复核，期间按钮分别显示“正在检查配置”和“正在启动代理”。
- 节点健康状态严格分为“未检测 / 检测通过 / 本次检测未通过”；
  `alive=None` 不再被渲染为不可用。启动提交前仍会对实际当前节点最多实时检测
  2 次，失败提示明确说明“并非未测速状态”并回滚系统路由。

## 影响范围与兼容性

- `config.json.routing` 新增 schema、接管、内置规则包、mixed-port 和 DNS 分层字段。
- 原生服务协议/版本升级为 `2 / 0.2.0`，旧服务会按摘要和版本触发一次 UAC 升级。
- 系统代理只在用户明确应用 `capture_mode=system-proxy` 时替换；预览和离线测试不修改注册表。
- 当前配置中未知的 Merge/Script/核心控制字段不会进入生成配置。
