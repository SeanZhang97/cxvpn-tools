# 开机自启托盘与人工验证码降级

- 日期: 2026-08-28
- 功能名: Windows 开机自启、系统托盘和无模型人工验证码流程
- 分支: 非 Git 工作区

## 需求概述

支持当前用户登录 Windows 后自动启动并静默驻留系统托盘；关闭主窗口时允许后台
自动化继续运行，并提供明确的彻底退出入口。托盘图标改为左键单击恢复，关闭到托盘
不再发送重复的驻留通知，并通过命名互斥禁止同时运行多个实例。同时优化图形验证码
流程：没有完整配置视觉模型时不再尝试调用 AI，直接通知用户完成工具内人工点击。

## 问题根因

- 主窗口关闭后 pywebview 消息循环直接结束，没有托盘宿主和显式退出路径。
- 项目没有管理当前用户 `Run` 注册表项，帮助页仍要求用户手工创建计划任务。
- `config['vlm']` 即使三项值均为空仍是非空字典，旧逻辑会误认为模型已配置，进入
  多轮无效 AI 重试后才转人工。
- 自动任务在窗口隐藏时进入人工验证码等待，缺少恢复窗口和桌面提醒机制。
- 入口没有进程级互斥，重复启动会创建多个 worker、托盘图标和主窗口。

## 关键设计

- 使用项目现有 pythonnet/WinForms 创建 `NotifyIcon`，不新增第三方依赖。托盘支持
  左键单击恢复窗口，以及“打开主窗口”“退出 CX VPN 管理器”菜单；右键单击仍只
  打开菜单。关闭到托盘不再显示“仍在运行”气泡，需要人工验证码时的功能提醒保留。
- 入口通过 `Local\CXVPNManager.Singleton.v1` 命名互斥保证单实例。重复启动时不创建
  Api 或 worker，而是查找标题为“CX VPN 管理器”的现有窗口，恢复并置前后立即退出。
- `close_to_tray` 默认开启；仅拦截 `CloseReason.UserClosing`。Windows 注销、关机和
  托盘显式退出不会被拦截，退出前解除人工等待并停止 worker。
- worker 的停止事件使用 `_stop_event`，避免覆盖 `threading.Thread._stop()` 后导致
  托盘退出阶段 `join()` 抛出类型错误；退出路径最多等待后台线程 5 秒。
- 开机自启写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，注册表值
  包含当前程序绝对路径和 `--startup`；移动目录后旧路径不会显示为已启用。启动参数
  使用 pywebview `hidden=True`，避免登录时窗口闪现。
- 模型配置仅在 Base URL、API Key、模型名称三项均非空时有效；不完整配置直接跳过
  `vlm_solve`，更新进度为“等待人工完成图形验证”并进入既有人工弹框。
- 人工验证码出现时，无论是未配置模型还是 AI 失败兜底，都会恢复主窗口并发送托盘
  提醒，避免后台任务静默等待。

## 影响范围

- 新增当前用户级注册表设置和托盘生命周期；不需要管理员权限，不创建计划任务。
- 配置新增 `close_to_tray`，旧配置通过默认值兼容；开机自启状态以注册表为事实来源，
  不重复持久化到 `config.json`。
- 不改变验证码图片、坐标协议、授权接口参数、短信捕获或 VPN 连接契约。

## 注意事项

- 移动整个分发目录后需要重新关闭再开启“开机自启”，以刷新注册表中的绝对路径。
- 未配置模型时，自动授权会等待用户人工完成图形验证，不能在完全无人值守状态下
  通过该验证码。
- 点击窗口关闭按钮只是隐藏到托盘；左键单击托盘图标可恢复窗口，需要彻底结束后台
  任务时使用托盘菜单“退出”。
