# 总览网络出口信息

- 日期：2026-08-29
- 功能名：总览网络出口信息
- 分支：非 Git 工作区

## 需求概述

- 在总览默认 VPN 右侧加入「网络出口」卡片，展示内网、公网出口和国外出口的 IP、位置及运营商。
- 支持后台刷新、手动刷新和逐项复制 IP。
- 网络出口卡片与下方活动连接行共用内容边界，解决右边框不对齐问题。
- 不展示「当前国内外出口不同」说明行。
- 根据实际窄窗口截图继续压缩网络出口区与自动化区之间的空带，保证公网和国外 IP 完整显示。
- 国外出口必须反映真实网卡/VPN 路由，不能被 Windows 中残留的本地系统代理改写为代理出口。
- 公网出口与国外出口分别反映不同路径：公网出口始终跟随 Windows 默认 IPv4 路由，超星 VPN
  开启远程默认网关时应显示其北京出口，关闭默认网关或断开后恢复成都出口；国外出口独立反映
  第三方日本、美国等节点出口。

## 关键设计

- `core/ip_info.py` 并发读取默认 IPv4 路由对应的本机物理网卡、国内探测点和海外探测点，单个探测失败不影响其余数据。
- 海外出口改用 Cloudflare 官方 `/cdn-cgi/trace`，以 `cloudflare.com` 为主入口、
  `www.cloudflare.com` 为备用入口。探测前通用识别活跃的 WireGuard、Wintun、TUN、TAP、
  VPN 等虚拟隧道：存在活跃隧道且系统配置了代理时走代理出口；没有活跃隧道时绕过断开后
  残留的本地代理。判定不依赖具体 VPN 工具或进程名称。
- 海外出口 IP 与位置元数据解耦：先以 Cloudflare trace 确定权威 IP，再通过带明确 IP 参数的
  `ipapi.co/{ip}/json/` 补充地区和运营商；元数据失败只降级位置，不清空已取得的出口 IP。
- `Api.get_ip_info()` 立即返回缓存，首次读取、缓存超过五分钟、手动刷新或 VPN 路由变化时启动后台刷新，避免阻塞 WebView UI。
- 刷新失败时保留上一份成功数据并标记为旧数据；前端明确显示「旧数据」和「部分为旧数据」，
  不再把历史出口误报为刚刚更新。路由变化发生在刷新过程中时排队执行一次强制刷新，避免请求被吞掉。
- `.connection-hero` 与 `.connection-collection` 使用相同的左 8px、右 4px 内边距；网络出口卡片占据网格右轨并限制在共享容器内，使右边框与连接行保持同一坐标。
- 主工作区列间距由 28px 收紧到 12px，窄窗口收紧到 8px；左侧内容右边距同步减小，卡片到自动化分隔线的可见空带从约 40px 降到 16px（最小窗口 12px）。
- IP 双栏水平内边距、复制按钮和图标间距同步收紧，IP 字号按视口在 13～16px 自适应；完整值同时写入 `title`，不牺牲复制和悬停查看能力。

## 注意事项

- 国内出口依赖直连 `myip.ipip.net`；国外出口 IP 依赖 Cloudflare trace 双入口，
  根据活跃虚拟隧道自动选择系统代理或直连路径，
  `ipapi.co` 仅用于指定 IP 的位置元数据。网络不可达时显示旧数据、部分可用或暂不可用，
  不影响 VPN 管理功能。
- 自动化测试使用替身数据，不访问真实外部服务。
