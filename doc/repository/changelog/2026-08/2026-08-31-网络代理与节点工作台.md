# 网络代理与节点工作台

- 日期：2026-08-31
- 功能名：网络代理首页与独立节点工作台
- 分支：非 Git 工作区

## 需求概述

将常用翻墙代理操作从复杂的域名分流配置中拆出，在侧栏提供独立“网络代理”入口；采用已选
方案 1 的工作台布局，并补齐可搜索、筛选、测速和选点的完整节点列表页。

## 关键设计

- 新增侧栏“网络代理”首页，集中显示代理启停、当前订阅、当前节点、真实缓存摘要、连接模式、
  当前连接和订阅/节点/高级分流快捷入口。
- 新增网络代理二级节点工作台，复用既有代理组与独立订阅预览，提供订阅筛选、节点搜索、
  仅看可用、整组测速和手动策略选点；原分流节点页签兼容跳转到新工作台。
- 新增 `routing.traffic_mode`：规则模式执行现有域名规则；全局模式仅在生成运行配置和解释
  路由时忽略规则，规则本身继续保存，切回规则模式可恢复。
- 一键启停通过既有 `apply_routing`、WinSW 和内置 Mihomo 完成，不读取或依赖 Clash Verge。
  页面不会伪造订阅流量、到期日、实时速率或连接时长；无可靠来源的数据明确显示占位值。
- 大屏使用更舒展的纵向布局，小窗口沿用紧凑密度；节点页保持三列高信息密度。

## 影响范围

- 新入口改变侧栏导航数量和节点页访问路径，但不改变既有分流配置、订阅格式或 Windows 服务
  生命周期。
- 旧配置缺少 `traffic_mode` 时自动按 `rule` 处理，不修改或丢弃既有域名规则。
- 全局模式会使所有流量使用当前默认出口；启用或切换运行模式仍需要 Windows UAC。

## 注意事项

- 未实际点击“开启代理”，避免在开发验证中改变当前 Windows 路由；真实 UAC、TUN 和出口切换
  仍需在用户确认可中断网络的环境下做端到端验证。
- 实时上下行和连接时长仍需后端增加稳定的 Mihomo 流量数据采集后才能显示真实值。
