# 验证码点击层与识别精度深挖

- 日期: 2026-08-27
- 功能名: 点击层机制逆向 + 识别链路降噪 + 模型对比（未达稳过, 记录瓶颈）
- 分支: 非 Git 工作区

## 背景

预检门控+AI 主力链路上线后假号实测仍 0 通过, 本轮做点击层与识别层
责任分离实验, 定位失败根因。

## 关键发现（经现场实验确认）

- **站点点击机制**: 只有点击命中 3 个目标图标才生成标记
  （decoy/空白点击被静默忽略）。证据: 点击分割出的图标中心 3 次,
  仅命中目标的那次生成标记。点击层本身正常（canvas 与 #cx_imgBg
  完全对齐 320x160 1:1, offsetX 直用）。
- **照片噪声混入候选**: 白毛/阴影等照片区域过纯白/纯黑掩码成为假候选,
  导致 AI 编号匹配映射到噪声。修复: SEG_JS/SOLVE_JS 候选分割加对比度
  过滤（图标灰度 vs 背景环灰度中位数差 >= 60, 同 ASSESS_JS 校准阈值）。
- **填洞毁判别力**: SOLVE_JS 旧 fillRect 填洞把蝴蝶/洗衣机/提包都变
  实心方块; 且指令行 close(dilate) 会填掉小模板镂空。修复: 签名改为
  bbox 子掩码直接重采样（保留镂空）, 指令行分割不做 close。
- **识别精度瓶颈（未解决）**: ground truth 标定显示 qwen3-vl-plus
  逐图标匹配单图标准确率约 2/3, 站点要求 3 全对 → 整图通过率约 20-30%。
  模型对比: qwen-vl-max-latest 403（key 未开通）; qwen3.8-max 过慢超时;
  qwen3-vl-plus 快但精度不足。

## 代码变更

  逐图标 4 图模式（crop_row1_icons 列投影切分 4x 放大）+ 整条指令行

## 追加发现（本轮后半，活体人工标定确认）

- **sprite 行1 有时是诱饵**: 多张 sprite 的行1 含主图不存在的图标
  （rocket/bag/armchair），不等于提示条；故行1 不可作目标源。
  页面提示条 `.cx_click-tip`（请依次点击 [3 图标]）才是权威目标+顺序源。
  管线已改: get_tip_bytes 截 .cx_click-tip 右图标区 3x、crop_tip_icons
  列投影切 3 图标作 hybrid 首要 guide; handle_captcha 停用 local_solve
  （行1 模板会自信错点）。
- **marks() 不可靠**: .cx_imgBtn 为单个复用模板元素，计数恒≈1；
  唯一可信成功信号是 #eject 弹窗关闭；失败后站点自动刷新新题。
- **校验规则未完全逆向**: 即使人工高置信标定（目标对、按提示序）
  点击仍不关闭弹窗 → 顺序/判定规则另有玄机，叠加小图标判别超模型能力，
  “稳过”未达成。纯 CV 多尺度剪影 IoU gap 仅 0~0.16（probe_match2），不可行。
- 模型可用性: qwen-vl-max/235b/32b/plus/flash 200; qwen-vl-max-latest 与
  qwen2.5-vl-72b-instruct 403; qvq-max 400。默认改 qwen-vl-max;
  max_attempts 默认 5。已重打包 dist。
