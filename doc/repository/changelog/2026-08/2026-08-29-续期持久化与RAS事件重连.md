# 续期持久化与 RAS 事件重连

- 日期: 2026-08-29
- 功能名: 授权到期持久化与连接状态机优化
- 分支: 非 Git 工作区

## 需求概述

超星 VPN 单次授权最多 8 小时且可能受次日 02:00 上限约束。旧实现只在内存保存
`last_renew`，软件重启后会把已有授权误判为立即到期；连接状态只按 30 秒轮询，频繁切换
或服务端踢线时缺少期望目标、快速感知和重连熔断。

## 关键设计

- 从授权与续期接口成功响应提取 `data.expTime`，持久化成功时间、最早到期时间、触发来源和
  每条 VPN 到期时间；接口无到期字段时才按 8 小时/次日 02:00 上限兜底。
- 自动续期按“上次成功时间 + 用户间隔”与“服务端到期前 15 分钟”中较早者触发；没有
  本地基准时显示待同步且不在启动时盲目续期，691 恢复链可建立新基准。
- `authorization` 由后端独占写入，前端保存旧配置快照时不得覆盖 Worker 最新授权记录。
- 使用 `RasConnectionNotificationW` 监听 RAS 建连与断开，1 秒合并事件，30 秒轮询继续作为
  兜底；普通断线只重连，不直接触发授权。
- 会话内维护期望 VPN：切换时不拉回旧连接，软件内主动断开会暂停自动连接，用户再次手动
  连接后恢复。外部/服务端断开按 5、15、30、60 秒退避，10 分钟内连续 5 次断开后熔断。
- 总览“授权有效期”改为显示真实到期时间；无基准时明确显示“待同步”。
- 修复拨号成功后 Windows 仍处于过渡态时重复拨号：成功请求进入 30 秒 `verifying` 窗口，
  窗口内禁止重入；超时未确认才按统一退避重试。成功路径不再调用会把连接检查时间清零的
  `reset_backoff()`。
- 将手动连接、自动连接和授权后重连统一到同一个确认门控：API 重复点击、Windows 已处于
  `Connecting` / `Disconnecting`、授权在连接确认期间完成，均不会重复提交拨号。配置保存
  与重新开启自动连接不会意外清除在途确认。
- 确认超时、RAS 刷新和拨号操作通过同一操作锁串行化；RAS 事件风暴以首个事件设定刷新
  截止时间，连续事件不会无限推迟状态刷新。

## 影响范围

- 自动续期、手动授权、691 授权恢复、软件重启后的续期调度。
- 默认 VPN 自动连接、手动切换/断开、Windows 外部断开及服务端踢线后的恢复。
- 不改变超星验证码流程、VPN 配置结构和 Windows 凭据写入机制。

## 注意事项

- Windows RAS 事件只能说明连接状态变化，无法可靠区分用户从 Windows 手动断开、网络故障
  或服务端踢线；软件内主动操作可通过自身状态标记准确区分。
- 外部网页授权未经过软件，且当前没有无需短信验证的到期查询 API，因此到期时间未知时无法
  同时做到“不主动授权”和“准确提前续期”；需要一次软件内授权建立基准。
