# VPN 拨号隔离与超时日志

- 日期：2026-08-31
- 分支：非 Git 工作区
- 类型：Bug 修复、首次使用体验、可观测性规则

## 问题根因

普通凭据路径以无回调方式同步调用 `RasDialW`，`connect(timeout=90)` 的超时没有覆盖
该路径。目标机器的 PPP 协商若因网络黑洞、认证重试或路由变化停滞，worker 主循环会
被无限阻塞，导致浏览器请求、授权任务和 RAS 事件均无法领取；独立 IP 刷新线程仍正常，
因此界面表现为“请求成功但浏览器未启动，日志只剩 IP 节拍”。

同时，首次接管 Windows 已有 VPN 时，代码要求用户补录软件凭据，但帮助页仍描述为可
直接使用 Windows 已保存密码连接，与实际流程不一致。

## 关键设计

- 普通 `RasDialW` 改用 `RasDialFunc1` 异步回调，记录关键连接状态；90 秒无终态时使用
  本次 `HRASCONN` 调用 `RasHangUpW`，等待状态机释放并返回 1460。
- worker 的周期连接检查与自动拨号移入单一独立守护线程；主循环对 VPN 操作锁只做
  非阻塞探测，拨号期间仍可领取浏览器、授权与 RAS 事件任务。
- 增加浏览器请求“API 已提交 / worker 已领取”、后台拨号来源、RAS 阶段、终态、耗时、
  超时和取消日志；1460 归类为可退避的网络错误，缺少工具凭据归类为不可重试的凭据错误。
- 首次点击连接但缺少工具凭据时仍自动打开凭据弹框；保存成功后仅在该弹框由连接动作
  触发时自动续接原目标与连接模式。主动维护凭据或新建 VPN 时不自动拨号。
- 项目 `AGENTS.md` 新增可观测性与运行日志规则，约束异步任务、阻塞调用、异常信息、
  超时取消和敏感信息边界。

## 影响范围

- 普通 PPTP/L2TP 等软件凭据拨号获得硬超时保护；703 后的 EAP 路径仍使用已有的
  PowerShell 子进程超时。
- 自动连接与授权后重连不再阻塞 worker 主循环；手动连接仍同步等待结果，但最长受
  90 秒 RAS 超时约束。
- 首次已有 VPN 的凭据补录流程从“保存后再次手动点击连接”变为“由连接触发时自动续接”。
