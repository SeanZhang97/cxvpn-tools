# VPN 认证错误归因优化

- 日期: 2026-08-29
- 功能名: 628 内层认证错误识别与 756 拨号占用分类
- 分支: 非 Git 工作区

## 问题根因

本机两种 VPN 拨号失败时，`RasDialW` 对外返回 `628`，但同一次拨号的
`Microsoft-Windows-EapMethods-RasChap/Operational` 事件 101 在 `int1` 中记录了
真实错误 `691`。原逻辑仅依据表层返回码，把它归类为普通网络断线，因此不会触发已有
的授权恢复。用户随后重试又可能收到 `756`，该错误只是前一次拨号状态尚未释放。

## 关键设计

- 记录本次拨号开始时间；仅当表层返回 `628` 时，读取开始时间之后的 EAP-MSCHAPv2
  失败事件，并要求事件用户名与本次凭据匹配。
- 事件 101 的 `int1=691` 才把结果提升为认证失败，复用既有单次授权/续期恢复；没有
  匹配事件时仍保留 `628` 网络错误，避免普通断线误触发授权。
- Windows PowerShell 子进程显式导入 `Microsoft.PowerShell.Diagnostics` 模块，避免
  宿主 `PSModulePath` 环境导致 `Get-WinEvent` 自动加载失败。
- `756` 单独归类为拨号占用，不触发授权，后台等待 30 秒后再试；其它网络错误继续按
  5～30 分钟递增退避。

## 影响范围

- 手动连接和自动连接的错误提示、错误分类、授权恢复触发及重试节奏。
- 不改变正常连接、凭据同步、默认网关或授权流程内部行为。

## 注意事项

- `691` 同时可能表示密码错误或授权到期；工具按现有策略触发授权恢复，若授权后仍失败，
  需要更新 VPN 密码。
- EAP 事件日志不可用、无权限或没有匹配本次拨号的记录时，`628` 仍按网络错误处理。
