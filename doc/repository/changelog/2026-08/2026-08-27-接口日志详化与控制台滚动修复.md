# 2026-08-27 接口日志详化与控制台滚动修复

- 日期: 2026-08-27
- 功能名: 接口日志详化、eval 桥两阶段等待、日志/抓包滚动修复
- 分支: 非 Git 工作区

## 问题概述与根因

1. **接口调用日志缺失**: 授权/续期接口 (`_api_post`) 不打印地址/参数/返回,
   UI 看到的只有「授权接口失败：None」; VLM(NLP) 接口回复被截断到 400 字符;
   抓包摘要行只有 方法/状态/URL, 请求体/响应体需手动点行查看。
2. **授权接口实际恒失败 (截图「授权接口失败：None」的真因)**: `_api_post`
   的页内脚本是 async 函数, 而嵌入式 WebView2 的 ExecuteScriptAsync
   不等待 JS Promise (async 脚本返回 '{}'), `page.evaluate` 恒得 `{}`,
   `code` 恒 None —— 全靠 DOM 点击兜底完成流程, 接口路径从未生效。
3. **滚动条自动滚底**: 运行日志每 2 秒、抓包列表每 1 秒强制
   `scrollTop = scrollHeight`, 用户上翻查看时被不断拉回底部。

## 涉及文件

## 关键设计

- **eval 桥两阶段等待 (browser_win.eval_js/_exec_raw)**: 表达式包进
  async IIFE, 结果写入页内唯一全局槽 `['ok', value]`/`['err', msg]`,
  由同步脚本轮询读回 (页内三态: null=未落槽/['bad']=值不可 JSON 编码/
  ['v', json] 再解一层, 避开 ExecuteScriptAsync 双重转义)。同步表达式
  同样适用 (await 立即完成), 语义与旧版一致 (异常仍返回 None 并日志)。
- **接口日志**: _api_post 打印 `POST url 参数 {...}` 与 `返回 {...}`
  (仅业务字段, 无凭据); VLM 请求打印 端点/model/图尺寸, HTTPError 打印
  状态码+响应体, AI 回复改完整输出 (思考过程截断 800); 抓包 xhr 摘要行
  追加 参数=/返回= (各截断 120/160 字符, 全文仍在抓包详情与 netlog.jsonl)。
- **滚动**: 两处渲染前记录"是否贴底", 贴底才跟随滚底, 否则恢复原
  scrollTop (用户上翻时位置保持)。

## 注意事项

- eval 桥对"返回值不可 JSON 编码"的脚本会快速返回 None (与旧行为一致),
  对长期悬空的 async 脚本最多等 eval 超时 (默认 30s) 后返回 None。
- 抓包摘要中 参数/返回 字段可能包含手机号/短信验证码 (业务字段,
  无密码/Token), 与既有日志口径一致。
