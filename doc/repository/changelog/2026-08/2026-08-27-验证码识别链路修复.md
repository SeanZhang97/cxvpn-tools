# 2026-08-27 验证码识别链路修复 (墨迹验证 PIL 化/指令条雪碧图/指令区预拦)

## 问题根因 (三处叠加, 10 次 AI 识别全部被弃用的直接原因)

1. **嵌入式 WebView2 不等待 JS Promise (致命)**: `ExecuteScriptAsync` 对
   async 脚本返回 Promise 对象的序列化 `'{}'` (同步脚本正常)。墨迹验证
   `VALIDATE_JS` 为 async 函数, 在工具内永远拿不到分数, `_pick_frame`
   静默跳过所有帧 → 所有 AI 答案 (含离线回放中墨迹分可达标的答案) 被判
   "未过墨迹验证 (空想)" 直接弃用。Playwright probe 环境会正常 await,
   历史校准察觉不到。
2. **页面指令条提取恒失败**: 线上模板为"窗口雪碧图" — 单张
   `.cx_tips__answer_img` (width:340%, top:-144px) 透过
   `.cx_tips__answer_div` 84x17 overflow:hidden 窗口显示 3 个指令图标;
   采集逻辑要求容器内集齐 >=3 张 `<img>`, 单 img 恒不满足 → 双图
   PROMPT 从未启用, 全程走行1 裁剪单图兜底。
3. **单图模式下模型报指令行图标自身坐标**: qwen-vl-max 把 2x 送图中
   行1 图标的像素位置 (y≈330-350) 当答案, 归一化帧将其"洗白"进主图区
   顶部 (y≈80), 帧换算前无拦截。

## 关键设计

- **墨迹验证 PIL 本地化**: `_ink_scores` 用 PIL 1:1 复刻 VALIDATE_JS 公式
  (17x17 patch 内 |灰度-中位|>=60 计数, sprite 1:1 解码取 y<160), 等价性
  经离线回放实证; `_pick_frame` 改为纯 Python 双帧仲裁 (点 int 截断与旧
  JS 路径传参一致), 未通过时逐帧打墨迹分/间距日志, 便于区分真空想与
  阈值误杀。`VALIDATE_JS` 常量保留仅供 probe/回放参考。
- **指令条雪碧图模板支持**: `get_tip_icons` 同步 JS 返回 `{urls, geom}`
  (img/容器渲染矩形 + natural 尺寸); 3-img 模板路径不变; 单 img 时
  `_tip_icons_from_geom` 按"窗口 ∩ img 渲染框 → natural 坐标"映射裁切,
  `_slice_strip` 中部 70% 高度列投影切 3 段 (背景亮暗自动探测, 段宽
  相近校验), 失败仍退化行1 裁剪。
- **指令区预拦**: `_strip_answer` 在双帧换算前按原始坐标双参考系检测
  "全点落在指令行带 y[158,240)" 的空想形态, 直接弃用 (probe 兼容路径
  保持旧行为)。
