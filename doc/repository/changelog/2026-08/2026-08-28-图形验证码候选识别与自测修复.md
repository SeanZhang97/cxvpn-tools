# 图形验证码候选识别与自测修复

- 日期: 2026-08-28
- 功能名: 图形验证码多尺度候选、语义/形状双门控与 Playwright 自测点击修复
- 分支: 非 Git 工作区

## 需求概述

针对黑白反色、水平镜像和照片背景干扰下的图形验证码低通过率，优化自动识别
输入与拒错机制，并使用假手机号访问真实站点做有限轮次验证。

## 问题根因

- 整图端到端 VLM 同时承担读指令、匹配形状和猜坐标，`qwen-vl-max` 会混用
  像素/归一化坐标、照抄候选顺序或把背景纹理当图标。
- 旧候选分割只有单一阈值和 3x3 close，容易漏掉地球网格、电视、工具等
  镂空或多部件图标；全图二值化则会把毛发、眼鼻和阴影粘入候选。
- VLM 即使给出目标名，也可能把候选背景块错误命名成目标，单纯校验 JSON 编号
  无法拦截语义自相矛盾或形状明显不符的答案。
- 真实站点自测使用原生 Playwright `Page`，但 `_click_sprite` 无条件传入内嵌
  `PageShim` 专用的 `mark=` 参数；Playwright 在实际点击前抛 `TypeError`，导致
  早期所有自测轮次只刷新、没有真正点击。
- 严格纯 CV 通道在真实样本中两次高置信命中均点错，证明它不能独立提交答案。

## 关键设计

- 主图候选改为 Python/PIL 多尺度提取：黑/白极性分开，对 3x3、5x5、7x7
  close 的候选按对比度、位置和 bbox 重叠去重，最多保留 16 个；复杂图标召回
  优先于纯模板直接判定。
- VLM 输入由整图猜坐标改为“完整主图框选 + 候选图册”。每格同时提供原始 RGB
  裁图和颜色归一化剪影；候选编号按空间位置生成，不代表目标顺序。
- 指令图标逐个读取，提示词要求先为三个目标及候选使用相同的 canonical noun，
  再返回三个互斥编号；目标名与所选候选名不完全相同、数量异常、重复或越界编号
  均直接拒绝。
- 语义通过后追加黑白双行、水平镜像不变的剪影 IoU 排名门控：所选候选形状分
  至少 0.15，且达到该目标最佳候选的 85%，否则刷新。二值化只作为候选辅助视图，
  不替代原始照片。
- 纯模板求解保留为诊断能力但不再进入主点击流程；混合方案无结果时继续使用已有
  端到端 VLM 双帧坐标与墨迹验证兜底。
- `_click_sprite` 区分内嵌 `PageShim` 与原生 Playwright：仅前者传 `mark`，
  后者使用标准 `position` 参数。
- `test_captcha.py` 新增 `--config` 和 `--attempts`，可只读加载打包配置并限制真实
  自测次数，不复制或改写用户密钥。
- 用户授权后将运行时模型由 `qwen-vl-max` 先切换为 `qwen3.7-plus`，随后按
  官方高能力视觉档位和真实对照结果升级为 `qwen3.8-max`。对 Qwen3 请求关闭
  思考模式、启用 JSON Object 结构化输出，
  并分别限制坐标回答为 256 token、候选命名为 1024 token；模型正文日志最多
  保留 1200 字符，避免异常长回复拖慢验证码流程或污染控制台。

## 影响范围

- 只影响图形验证码自动识别、自测工具和离线探针；人工点击、短信捕获、授权接口、
  VPN 连接和用户配置结构不变。
- 增加单次混合识别的 PIL 计算和较大的候选图输入；无新增第三方依赖。
- `dist/CXVPN管理器/config.json` 的 `vlm.model` 已按用户授权改为
  `qwen3.8-max`；Base URL 和 API Key 未改变。

## 注意事项

- 官方视觉理解文档将 `qwen3.8-max` 列为高能力档、`qwen3.7-plus` 列为平衡档；
  两者有限样本均为 3/3，3.8 的平均尝试次数略低，但样本量仍小，不能视为长期
  通过率承诺。
- 混合方案采用宁缺毋滥门控，候选缺失或语义/形状不一致时会增加刷新次数，最终仍由
  工具内人工点击兜底。
