# 2026-08-26 连接逻辑与凭据机制修复

- 日期: 2026-08-26
- 分支: 非 Git 工作区
- 类型: Bug 修复 / 机制重构

## 问题现象

用户反馈"手动点连接没反应"。排查发现三层叠加问题：

1. `vpn_connect.connect` 给 rasdial 传了不存在的 `/savecredentials` 开关——
   本机 rasdial 无此开关，收到非法参数时打印 USAGE 且**退出码为 0**，
   被误判为连接成功（日志表现为 `rasdial → True: 用法:`）。
2. `status()` 解析写反：已连接条目输出行 "Connected to <名称>"/"已连接到 <名称>"
   恰好是被排除的行 → `is_connected` 恒为 False → 后台每 30 秒空转重连。
3. 前端 `toast()` 是空函数 no-op，连接失败无任何 UI 反馈。

## 根因：Windows 设置保存的 VPN 密码 rasdial 用不了

RasClient 事件日志：设置界面连接 → 20225 认证成功（Dial-in User=15823060240）；
工具 rasdial → 20227 错误 691。电话本条目 AutoLogon=0 且无 UserName 行，
说明设置界面存的密码位于 RAS 专属保险库：RasGetCredentials 只回星号掩码，
CredEnumerate 枚举不到，rasdial 无法使用 → 必须"工具存一份 + 显式拨号 +
成功后同步写回 Windows"。

## 修复内容

- `core/vpn_connect.py` 重写：USAGE 检测防假成功；status() 中英文解析；
  is_connected 5s 缓存 + Get-VpnConnection.ConnectionStatus 兜底（枚举值与语言无关）；
  connect 仅在有用户名+密码时显式传参（删除 /savecredentials）。
- `core/ras_cred.py` 新增 `set()`：RasSetCredentialsW dwMask=0x3 写入成功
  （含 0x8 DefaultCreds 会返回错误 5）。
- 新增 `core/vpn_service.py`：连接编排（显式拨号 → 成功后同步 Windows）、
  friendly() 错误码转可读引导文案（691 → 提示到凭据弹窗输入）。
- `api.py`：save_cred 先验证后落盘（失败不保存）；get_cred 回显工具侧已存凭据
  （密码明文回显，前端眼睛切换）；connect_now/disconnect_now 返回可读 msg。
- `core/worker.py`：连接失败退避（5min 起步、上限 30min），
  成功/更新凭据后 `reset_backoff()` 立即恢复；移除 on_connected 回调。
- `ui/`：右上角 toast 轻提示（ok/bad 边框）；连接/断开按钮加载态；
  凭据弹窗回显已存密码（留空提交=保持不变）；帮助页凭据章节改新机制说明。

## 验证

- 后端单测：裸拨返回 691 引导文案；get_cred 存/未存两种回显正确。
- 端到端：用户按新方案在工具中配置凭据后连接成功；
  重打包后 config.json 的 creds 随包保留。

## 注意事项

- rasdial 退出码语义：成功 0；失败 = RAS 错误码（691 等）；非法参数 USAGE 但退出码
  也是 0——判定成功必须同时查退出码与输出首行。
- 修改 ui/* 或 core/* 后需重打包才进 EXE；build.py 自动保留 dist 的 config.json。
- 源码位于 Qoder 工作区外（C:\develop\workspace\cxvpn-manager），
  文件编辑走 ".staging 暂存 + Copy-Item" 流程。
