# 日志完整显示与请求面板拖拽

- 日期: 2026-08-28
- 功能名: 运行日志与内嵌网络请求面板交互修复
- 分支: 非 Git 工作区

## 需求概述与问题根因

- `[net]` 运行日志在写入前会对 URL、请求体和响应体做二次截断，
  用省略号替代尾部内容，导致运行日志无法展示已抓取的完整数据。
- 页内 fetch/XHR 钩子原样保存调用时的 URL，站点使用相对路径时，
  运行日志只显示 `/vpn/checkCode` 而没有协议与域名。
- worker 每秒向浮层重推数据时，请求列表会清空后重建，详情的
  `.open` 状态随 DOM 销毁，导致用户点击展开后很快自动收起。
- 网络请求抽屉高度固定为 186px，长请求内容的查看空间不足。

## 涉及文件

- `core/worker.py`

## 关键设计

- 页内钩子完整采集文本、JSON、XML 和表单请求/响应体；URL、
  请求体和响应体在日志层也不再二次截断或压缩空白。
- fetch 和 XHR 钩子均以当前页面为基准将相对路径解析成绝对 URL，
  日志和请求详情因此显示完整协议、域名、路径和 query 参数。
- 浮层以时间、来源、方法、状态和 URL 组合为请求标识，在列表重绘前后
  保留展开集合与滚动位置，不再被周期状态推送重置。
- 在抽屉顶部增加垂直拖拽柄：186px 为最低高度，当前视口高度的
  70% 为最高高度；支持鼠标/指针拖拽及键盘方向键调整。
- 将抽屉高度暴露为 Shadow DOM CSS 变量，进度卡依该变量动态避让，
  防止拖高后两个浮层重叠。

## 影响范围

- 影响运行日志中的 fetch/XHR 记录和内嵌浏览器的网络请求抽屉。
- 不改变 `netlog.jsonl` 轮转规则、授权续期流程或
  对外数据结构。
