# 纯净版分发 zip 打包脚本

- 日期: 2026-08-29
- 功能名: 纯净版分发压缩包打包脚本
- 分支: 非 Git 工作区

## 需求概述

直接分发 `dist/CXVPN管理器` 目录会泄露个人数据：`config.json` 内含明文手机号、
VPN 凭据、IMAP 授权码与视觉模型 API Key，`_internal/webview_data` 含门户登录会话。
新增项目根目录脚本 `打包纯净版.bat`，一键产出剔除全部个人数据的分发 zip 包。

## 关键设计

- 使用 Windows 10+ 自带 tar（bsdtar）压缩，无第三方依赖；产物
  `dist/CXVPN管理器-纯净版.zip`，结构为 `CXVPN管理器/...` 与源目录一致。
- 排除清单：`config.json`、`run.log`、`startup.log`（根目录与 `_internal` 两处）、
  `_internal/webview_data` 整个目录（登录会话缓存）。
- 打包前若程序正在运行，按项目规则直接 `taskkill` 强制关闭，避免个人数据在
  压缩过程中被改写。
- 打包后自校验：`tar -tf` 输出经 findstr 检查上述模式，有残留即警告禁止分发；
  无残留则输出产物大小与分发环境说明。

## 踩坑记录（脚本编码与运行环境）

- 脚本必须按 GBK 编码 + CRLF 换行保存（Write 工具默认 LF，需转换），LF 换行会
  导致 cmd 批处理解析错乱（部分行被合并、命令执行错位）。
- 两级 tar 兼容性问题，均已在用户实机双击运行时暴露：
  - 不同机器 PATH 里 tar 版本不一致：开发机 Git 自带的 tar 支持
    `--force-local`，而双击 cmd 环境下 Windows 自带
    `C:\Windows\System32\tar.exe`（bsdtar 3.8.4）不支持该参数，报
    `tar: Option --force-local is not supported`。修复：去掉该参数（仅作保险），
    并把脚本调用的 tar 固定为系统自带路径。
  - bsdtar 会把绝对路径中的盘符 `C:` 误认为远程主机地址（报
    `Cannot connect to C`），脚本先 `cd` 到 dist 目录、全部使用相对路径。
- zip 内中文文件名默认按本机 GBK 字节写入且不带 Unicode 标志，换到非中文
  系统的电脑解压会变成乱码。修复：创建时加 `--options hdrcharset=UTF-8`，
  经 zipfile 验证任何语言 Windows 解压均得到正确中文名。
- echo 文本内的半角括号会提前闭合 if 代码块（if/else 两分支同时执行），
  脚本内 echo 文本一律使用全角括号。

- 最终版（固定系统 tar + hdrcharset=UTF-8）在 cmd 双击等价环境实测：退出码 0，
  各步骤日志完整，产出 35,067,366 字节的 zip。
- 独立复核（Python zipfile）：PK 头正确，337 个条目，testzip 完整性无损，
  无 config.json / webview_data / .log 残留；exe、python314.dll、

  `CXVPN管理器/` 解码正常；抽解压 index.html 冒烟通过。

  RAS 连接未断开，VPN 中经云pptp 保持已连接状态（rasdial 核验）。
