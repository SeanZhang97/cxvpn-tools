# 总览重设计与续期中断

- 日期: 2026-08-27
- 功能名: 总览工作台重设计与续期中断
- 分支: 非 Git 工作区

## 需求概述

原总览页以四张等权状态卡和一排操作按钮平铺，连接、续期、自动化设置与维修操作
缺少主次关系；“立即续期”只能发起后台流程，执行期间无法从界面中断，也缺少
明确的阶段和结果反馈。

## 问题根因

- 页面只展示连接结果和上次续期时间，没有消费后台已有的五阶段进度。
- `renew_now` 仅设置 `renew_requested`，worker 没有任务领取锁、中断信号或取消状态。
- 续期失败通过改写 `last_renew` 实现 10 分钟延迟重试，导致“上次续期”不再代表
  真实成功时间。

## 关键设计

- 总览改为两列工作台：左侧集中连接与授权续期，右侧集中自动化策略和维修入口；
  保留原深色品牌、侧栏和按钮体系，增加最小窗口宽度下的紧凑布局。
- 续期卡直接展示真实五阶段标题、详情和进度；执行期间“立即续期”原位切换为
  “中断续期”，并区分进行中、正在中断、已中断、已完成和失败状态。
- worker 使用 `_renew_lock` 原子处理排队、领取和取消，避免发起/取消竞态；手动
  请求可覆盖失败冷却，自动重试在中断或失败后延迟 10 分钟重新评估。
- `web_flow.ensure_authorized` 接收取消回调，在各等待和业务阶段检查；验证码处理
  同步接收取消信号，API 在人工验证码等待期间主动解除挂起并隐藏短信弹窗。
- 失败和中断改用 `_renew_retry_after` 调度，不再伪造 `last_renew`。

## 影响范围

- 影响总览页布局、续期状态桥接、续期调度和验证码等待退出路径。
- 不改变 VPN 配置、授权/续期接口参数、自动续期间隔配置、连接与断开契约。
- 中断是协作式的；若正在执行单次页面脚本或模型 HTTP 请求，会在该调用返回后的
  下一个检查点停止，不会强制销毁浏览器进程。

## 注意事项

- 续期中断不会关闭内嵌浏览器，用户仍可在“浏览器”页继续手动操作。
- 页面脚本或模型请求本身无法被线程安全地强制终止，中断延迟取决于当前单次调用
  的返回时间；其余轮询等待以 0.1 秒粒度响应。
