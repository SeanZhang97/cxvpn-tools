# 弹框统一右上角关闭叉号

- 日期: 2026-08-27
- 分支: 非 Git 工作区
- 类型: UI 规则强制化 / 缺陷修复

## 需求概述与问题根因

人工安全验证弹窗 (#capmodal) 无关闭途径, 只能「重置/提交」; 且历史上多次出现
"新写一个弹框就无法关闭" 的重复问题——根因是关闭按钮依赖每个弹框手写, 缺乏
统一强制机制。用户要求: 所有弹框右上角必须有关闭叉号, 并作为项目规则强制执行。

## 涉及文件

- ui/app.js: 新增通用关闭机制 `injectModalClose()` / `closeModal()`
- ui/style.css: `.modal-card` 增加 `position: relative`, 新增 `.modal-x` 样式
- api.py: 新增 `dismiss_manual_captcha()`

## 关键设计

- **自动注入强制规则**: app.js 启动时为所有 `.modal-card` 自动 prepend
  `.modal-x` 叉号按钮, 并以 MutationObserver 监听动态新增节点——未来新写的
  弹框无需手写任何关闭代码即自带右上角叉号, 从机制上杜绝"弹框无法关闭"。
- **委托点击关闭**: document 级 click 委托命中 `.modal-x` → `closeModal()`,
  默认隐藏弹框; 带后台状态的弹框在 closeModal 内同步通知后端:
  - #smsmodal → `dismiss_sms_ui()` (与「关闭」按钮一致, 后台捕获不受影响);
  - #capmodal → `dismiss_manual_captcha()` 解除 worker 挂起 (以 None 按失败
    处理), 避免关闭后后端空等超时。
- 样式: `.modal-x` 绝对定位右上角 14px, 30×30 圆角透明底, hover 提亮;
  `.modal-card h3` 增加 `padding-right: 34px` 防标题与叉号重叠。

## 影响范围

- 现有 4 个弹框 (#modal / #credmodal / #capmodal / #smsmodal) 均获得右上角
  叉号; 原「取消/关闭」按钮行为不变。
- 人工验证码弹窗关闭后本次验证按失败处理, 续期流程后续自动重试, 不再挂起等待。

## 验证情况

- 静态检查: app.js / style.css / api.py 语法与既有委托逻辑无冲突。
- 仅改 ui/ 时可 Copy-Item 覆盖 dist 内嵌 UI 免打包; api.py 改动需
  `python build.py` 重打包后真机验证叉号关闭与后端解除挂起。

## 注意事项

- 该规则已沉淀为项目强制规则 (知识库 modules/CXVPN管理器.md): 新弹框一律走
  `.modal > .modal-card` 结构, 关闭叉号由 app.js 自动注入, 禁止再手写缺失
  关闭途径的弹框。
