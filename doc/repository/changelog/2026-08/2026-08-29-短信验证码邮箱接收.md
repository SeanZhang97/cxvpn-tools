# 短信验证码邮箱接收

- 日期: 2026-08-29
- 功能名: iPhone 快捷指令邮箱中转与多来源验证码接收
- 分支: 非 Git 工作区

## 需求概述

在原 Windows“手机连接”通知捕获之外，新增 iPhone 快捷指令发送邮件、程序通过 IMAP
拉取正文并解析验证码的接收方式。用户可以在软件中明确选择本次授权流程使用哪种来源；
原“AI 模型”菜单扩展为统一的“自动化配置”，帮助页补充两种方式的完整操作指引。

## 问题根因

- 原验证码接收器固定读取 Windows 通知中心数据库，无法覆盖 iPhone 不便通过 Phone Link
  稳定同步、或手机不在电脑蓝牙范围内的场景。
- 模型设置与短信接收都属于自动授权的前置能力，但原界面分散在“超星账号”和“AI 模型”
  页面，没有统一入口，也无法选择验证码来源。
- 参考方案依赖 `UNSEEN` 并主动标记已读，邮件若先被其它客户端打开就会漏收，也会改变
  用户邮箱状态，不适合作为程序内接收契约。

## 关键设计

- 新增 `sms.method` 配置，支持 `phone_link` 与 `email`，每次流程仅启动用户所选自动来源；
  手动输入仍与自动来源并行，先得到有效验证码的一方生效。
- IMAP 统一使用 SSL，只读打开邮箱目录，以 `BODY.PEEK[]` 读取新邮件，不使用未读标记、
  不修改邮箱状态。监听在站点请求短信前初始化并建立 UID 基线，避免取到历史验证码。
- 邮件正文兼容纯文本、HTML、multipart 和常见字符编码；主题为包含匹配，发件人为可选
  限制。示例“【超星学习通】您的验证码为：730507,有效期为5分钟。”可提取 `730507`。
- 自动化配置页提供 QQ、163、Gmail、iCloud 和自定义 IMAP 服务器预设、SSL 端口、账号、
  授权码、邮箱目录、主题与发件人字段，以及只登录并只读打开目录的连接测试。
- 接收方式和邮箱服务商不使用 Windows 原生下拉框，统一改为深色浮层菜单，提供来源说明、
  服务商标记、选中勾选、箭头旋转以及 hover/focus 状态，并支持点击外部或 Escape 收起。
- 自动化配置中的邮箱接收名称统一为“邮箱转发（IMAP）”，不与特定手机平台绑定；平台名称
  仅出现在帮助页的对应配置步骤中。
- 帮助页吸收参考 HTML 中可靠的快捷指令步骤：信息触发、立即运行、固定“超星验证码”
  主题、正文使用“快捷指令输入”、关闭“显示撰写表单”；未采用其未读扫描和标记已读逻辑。
- 帮助页新增 Android `pppscn/SmsForwarder` 邮箱转发方案，说明 QQ SMTP 465/SSL、
  授权码、固定主题、短信正文占位符、规则过滤、系统自启动与电池优化设置；电脑端继续
  复用同一 IMAP 接收配置，不增加新的程序分支。

## 影响范围

- 旧配置缺少 `sms` 时继续默认使用 Windows 手机连接；配置加载改为递归合并，新增嵌套字段
  不会覆盖已有用户配置。
- 邮箱授权码保存在便携 `config.json`，未引入系统凭据迁移；帮助页明确提示专用邮箱与
  分发前清理敏感配置。
- 不改变图形验证码识别、网页登录按钮事件、VPN 授权接口和人工短信输入契约。
