# 总览启动边框与布局优化

- 日期：2026-08-29
- 功能名：总览初始焦点与首屏布局优化
- 分支：非 Git 工作区

## 需求概述

- 消除软件初始打开时「总览」导航同时显示 active 边框与焦点外框的双边框视觉。
- 总览首屏不再因底部独立「修复 VPN 服务」区域产生竖向滚动条。
- 将「修复 VPN 服务」移至右侧「关闭到托盘」下方空白区域，与自动化设置的图标、间距和分割线保持一致。

## 问题根因

- WebView2 初始焦点会让已经具有 active 样式的首个导航按钮同时命中全局 `button:focus-visible`，叠加成双层边框。
- 底部 `.overview-maintenance` 在窗口高度不超过 920px 时仍额外占用 38px，使总览内容超出主区可视高度。

## 涉及文件

- `ui/index.html`
- `ui/style.css`
- `ui/app.js`
- `tests/test_ui_polish.js`
- `doc/repository/knowledge/modules/CXVPN管理器.md`

## 关键设计

- `bindInputModality()` 只在用户按 Tab 进入键盘导航时启用 `.keyboard-navigation`，指针操作时移除；启动时不显示额外导航焦点框，但键盘可访问性保持。
- `#btn-repair` 从授权条下方移入 `.automation-matrix`，位于 `#ov-tray` 之后，继续复用 `.maintenance-link` 的三列布局和维护状态交互。
- 移除「关闭到托盘」行的底边框，只保留维护入口顶部的单条分隔线，避免双线叠加。
- 删除 `.overview-maintenance` 及其矮窗口高度补丁，授权条成为总览页底部内容。

## 影响范围

仅影响总览导航焦点呈现和总览布局；VPN 修复的点击处理、UAC 流程及状态文案保持不变。

## 验证情况

- `node --check ui/app.js`
- `node tests/test_ui_polish.js`
- `node tests/test_ui_state_sync.js`
- `uv run --with pyinstaller python build.py`：打包成功，产物中 `app.js` / `style.css` / `index.html` 与源码一致，`config.json` 打包前后未变。
- 打包产物启动界面检查（1426 × 893）：「总览」只显示单层 active 边框，主区无竖向滚动条，「修复 VPN 服务」位于「关闭到托盘」下方且只保留一条分隔线。

## 注意事项

本次不执行「修复 VPN 服务」，避免触发 Windows UAC 和系统服务变更。
