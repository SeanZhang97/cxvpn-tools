# VPN 状态全局同步与总览高度

- 日期：2026-08-29
- 功能名：VPN 状态跨页面共享与总览默认高度优化
- 分支：非 Git 工作区

## 需求概述

- 在总览连接或断开 VPN 后，「VPN 配置」页面必须立即显示同一连接状态。
- 软件以默认高度打开时，总览页面不应出现竖向滚动条。
- 高 DPI 等效窗口和最小窗口下继续保证网络出口 IP 完整显示。

## 问题根因

- `finishConnectionAction()` 虽然取得了 Worker 的最新 `profiles`，但只有当前页面已经是
  `vpns` 时才更新 `VPN_LIST`；从总览完成连接后再切页会复用旧缓存。
- 总览在较矮 CSS 视口中仍使用常规高度的 IP 卡片、连接行和授权条，内容高度会超过
  `main` 的可视高度。1152px 宽度刚好未命中原 1120px 响应式断点，还会压缩左侧卡片宽度。
- Windows 真实 WebView2 中，主内容这个 flex 子项没有声明 `min-width: 0`，轻微横向溢出会
  生成横向溢出。更主要的是默认桌面窗口扣除原生标题栏后，WebView2 的 CSS 视口高度约为
  862px，只命中 920px 高度断点而未命中 820px 断点；920px 档位仍保留 `main` 默认 30px
  底部内边距，授权状态下方最终多出约 7px 的实际可滚动距离。

## 关键设计

- 新增 `setVpnProfiles()` 作为 VPN 配置全局快照的唯一前端写入入口；Worker 轮询快照、连接完成
  快照和 `list_vpns` 结果都更新同一个 `VPN_LIST`。
- 隐藏页面只更新全局快照；「VPN 配置」当前可见时立即局部渲染，切入页面时也从最新快照
  渲染，避免重复系统查询和旧状态回显。
- 高度不超过 920px 时先把主区底部内边距收紧到 20px；不超过 820px 时压缩总览标题、状态带、
  连接主区、自动化区和授权条的竖向节奏，并把底部内边距收紧到 8px；不超过 700px 时再收紧
  到 4px。保持 `main` 的正常滚动能力，内容确实超出时仍可滚动。
- 主内容 flex 子项显式设置 `min-width: 0` 和 `overflow-x: hidden`，消除顶层横向滚动条；表格等
  确实需要横向滚动的区域继续由内部 `.table-card` 自己承载，不影响其它页面的可用性。
- 总览宽度响应断点扩大到 1240px，并收紧内网行列宽，避免高 DPI 等效宽度下 IP 再次被裁切。

## 影响范围

影响总览与 VPN 配置页面的状态同步、总览短窗口布局；不改变后端 VPN 连接流程、Worker
快照结构、自动重连策略或 Windows VPN 配置。

## 验证情况

- `node --check ui/app.js`
- `node tests/test_ui_polish.js`
- `node tests/test_ui_state_sync.js`
- 浏览器流程：总览点击连接后切换至 VPN 配置，目标行显示「已连接」，操作按钮显示「断开」，
  汇总显示「1 个已连接」。

  `main.clientHeight`，无竖向滚动条。
- 1152 × 720 下内网、公网和国外 IP 的 `scrollWidth` 均不大于 `clientWidth`，无裁切；
  浏览器控制台无错误或警告。
- Windows 真实桌面窗口复测：默认高度下右侧和底部滚动条均消失；对总览执行大幅向下滚动后，
  标题、状态带、连接区和授权区位置均未发生变化，确认页面不存在残余竖向位移。
- `uv run --with pyinstaller python build.py`：打包成功；产物包含全局快照与短窗口布局修正，
  `config.json` 长度和 SHA-256 均与打包前一致。
- 新版 `dist/CXVPN管理器/CXVPN管理器.exe` 已启动，进程正常响应。

## 注意事项

状态同步测试使用本地 Worker 替身，不发起真实 VPN 连接；真实连接仍由既有后端流程负责。
