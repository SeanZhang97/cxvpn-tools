# 验证码识别可观测与手动短信输入

- 日期: 2026-08-26
- 功能名: AI 识别过程日志化 + 短信验证码手动/自动并行
- 分支: 非 Git 工作区

## 需求

1. 发给 AI 的验证码图与 AI 思考过程要体现在日志中（流式若影响速度可不做）。
2. 电脑可能无法连蓝牙（手机连接不可用），需支持手动填短信验证码，
   与程序自动获取并行，谁先取到用哪个。

## 涉及文件

- `core/captcha_handler.py`、`core/web_flow.py`、`core/sms_receiver.py`
- `core/worker.py`、`api.py`
- `ui/index.html`、`ui/app.js`

## 关键设计

- 验证码图落盘: 每次 attempt 存 `BASE/captcha_cache/captcha_时间戳.jpg`
  （保留最近 10 张），日志给出完整路径供人工查看。
- AI 过程日志: 非流式（不影响推理速度），回复后记录
  `reasoning_content`（思考过程，模型支持时）与 `content` 原文，
  各截断 400 字符；接口异常也记日志。
- 短信并行获取: web_flow 等码循环每 0.5s 先 `catcher.poll()`（自动）
  再 `sms_poll()`（手动），谁先取到用哪个，日志标注来源；
  超时提示同时说明自动/手动两种途径。
- 手动通道（与人工验证码 provider 同模式）:
  - Api: `sms_show(show)` 控制 UI 弹窗显隐（带自增 id 防重复弹出）、
    `get_sms_ui()` UI 轮询、`submit_sms_code(code)` UI 提交、
    `poll_manual_sms()` worker 轮询取码（取后即清）。
  - worker 构造注入 `sms_poll/sms_show` 传入 ensure_authorized。
  - UI: `#smsmodal` 弹窗（2s poll 检测弹出/关闭，自动取到码或超时
    由后端关闭）；浏览器页全局点击抢焦点逻辑排除 `.modal` 内点击，
    避免短信输入框被隐藏键盘输入框抢焦点。

## 影响范围与验证

- `python -m py_compile` 五文件通过；已打包交付。
- AI 思考/回复日志与并行取码待用户端到端实测。

## 注意事项

- smsmodal 无取消按钮: 不输入可放置等待自动捕获; 自动先到自动关窗。
- reasoning_content 为 OpenAI 兼容扩展字段（DeepSeek/QwQ 等），
  模型不返回时仅记 content。
