# VPN 修复静默化与卡死兜底

- 日期: 2026-08-29
- 功能名: VPN 服务修复体验与 RasMan 卡死恢复
- 分支: 非 Git 工作区

## 需求概述

Windows VPN 在拨号后未取得隧道地址，系统面板长期停在“正在断开连接”。原修复流程提权后
会显示空白 PowerShell 窗口，且 RasMan 收到停止请求后重新回到 `Running` 时会安全退出，
无法清理该类残留状态。

## 涉及文件

- `core/vpn_repair.py`
- `tests/test_vpn_creation_flow.py`
- `doc/repository/knowledge/modules/CXVPN管理器.md`

## 关键设计

- 非管理员修复仍保留 Windows UAC 授权，但提权后的 PowerShell 使用
  `-WindowStyle Hidden` 启动，不再显示控制台窗口。
- 原生命令非零退出码不再被当作成功，错误会进入状态检查与安全兜底。
- RasMan 无法正常停止且仍为 `Running` / `Stop Pending` 时，仅在确认其进程是
  `System32\\svchost.exe`、该进程只托管 RasMan 一个服务后才终止旧进程。
- 兜底后以服务进入 `Stopped` 或 SCM 用新 PID 拉起为成功条件，继续确保
  PolicyAgent、IKEEXT 和 RasMan 均为运行状态；共享 svchost 不会被终止。

## 影响范围

- 总览“修复 VPN 服务”入口及直接调用 `core.vpn_repair.repair` 的修复流程。
- 不改变普通连接、断开、授权与续期流程；UAC 是系统权限边界，仍会正常显示。

## 注意事项

- 修复会断开全部 RAS VPN 并重启相关系统服务，只应在连接/断开状态机卡死时使用。
- UAC 提示无法且不应隐藏；隐藏的只是用户确认授权后执行修复的 PowerShell 窗口。
