# 订阅节点独立预览

- 日期：2026-08-31
- 功能名：代理订阅独立获取与节点预览
- 分支：非 Git 工作区

## 需求概述

解决添加代理订阅后必须先启用统一分流服务才能查看节点的问题。允许在未保存、未启用
TUN 的情况下验证订阅并查看解析结果，同时检查并修正订阅和节点页面的状态、保存、错误
恢复及视觉一致性问题。

## 关键设计

- 新增订阅独立预览：临时启动 Mihomo 下载和解析当前草稿订阅，不配置 TUN、mixed-port
  或健康检查，不安装服务，也不修改系统路由。
- 预览绑定页面选中的物理接口和 DNS，降低公司 VPN 接管默认路由后订阅下载走错出口的风险。
- 临时 Controller 仅监听 `127.0.0.1` 并使用随机 secret；读取节点前先验证 `/version`。
  临时进程加入 Kill-on-close Windows Job，主程序异常退出时由系统自动终止。
- proxy-provider 增加 Clash 兼容 `User-Agent` 和 10 MB 下载上限。前端只接收节点名称和
  类型，不接收节点服务器、密码等敏感字段；未知异常不会回显或记录订阅 URL。
- 新增每个订阅独立的下载出口：`auto`、`physical`、`system-proxy`、`custom-proxy`。
  `auto` 是不依赖 Clash Verge 的内置引擎：Mihomo 先加载该订阅上次成功缓存，用缓存节点
  更新同一订阅；首次无缓存时通过 `empty-fallback: PHYSICAL` 完成物理网络获取。
- 预览成功后把 Mihomo provider YAML 原子持久化到当前用户 LocalAppData。文件名包含订阅
  ID 和 URL SHA-256 指纹，修改 URL 后不会误用旧节点；更新失败不覆盖 last-known-good。
- 应用服务配置时通过 UAC 把匹配缓存部署到 ProgramData，保留服务自身更新出的较新缓存，
  并清理已删除、停用或 URL 已变化的服务缓存。GUI 退出后 Windows 服务仍能独立代理。
- Windows 系统代理只读取当前用户的手动 HTTP/HTTPS 代理，不执行 PAC/WPAD；自定义代理
  仅允许无账号密码的本机 HTTP 地址。两者只用于首次迁移或故障恢复，不是自动模式依赖。
- 支持导入最大 10 MB 的 Clash/Mihomo YAML。文件先经内置 Mihomo 配置预检，再作为初始
  节点缓存；导入和运行过程不要求 Clash Verge 已安装或启动。
- 每个订阅可配置 `User-Agent`，默认 `Clash-Verge`，兼容依赖客户端标识返回 Clash YAML
  的订阅服务器。订阅节点连接继续绑定物理接口，回环下载代理不错误绑定物理网卡。
- 订阅卡根据状态显示“预览节点、验证修改、查看节点、更新服务节点”。节点页明确区分预览
  和运行态；预览节点标为未测速，禁止切换和测速，刷新按钮改为重新获取订阅。
- 修正预览节点计数、搜索无结果空态、请求期间编辑竞态、最多 16 个订阅、最后一个订阅的
  聚合代理引用检查，以及修改后运行服务仍使用旧配置的提示。
- 统一分流从未安装且引擎关闭时，底部动作显示“保存配置”，直接持久化而不弹 UAC；只有
  启用、更新或注销服务时才显示系统变更确认。
- 配置检查成功后重新读取环境与运行状态；运行状态读取失败不再把已经成功的应用误报为失败。
- 配置检查的成功图标和下拉选中图标改用与现有 Toast 成功提示一致的 SVG 勾形、圆角矩形
  容器和成功色，不再使用旧的小号青色圆底勾。
- 自定义下拉在预览、保存等忙碌状态下同步原生 `select.disabled`，避免操作期间仍能打开或
  修改选项；关闭引擎时仅保存配置会保留签名仍有效的节点预览。
- 禁用订阅不再降低整张编辑卡片的透明度；节点页无数据时隐藏无效筛选工具并提供直达
  “订阅管理”的操作，`仅显示可用` 使用与 Toast 成功提示一致的圆角方框勾选样式。

## 影响范围

- 只影响“统一域名分流”的订阅管理、代理节点、配置保存与预览链路。
- 订阅预览会访问用户填写的订阅服务器；已有缓存时会使用内置缓存节点更新，但不会创建
  TUN、代理监听端口或接管业务流量。
- 已保存的旧配置保持兼容；缺少新增字段的订阅自动使用 `auto` 下载出口和
  `Clash-Verge` User-Agent。

## 注意事项

- 节点预览状态只保存在当前界面会话，但已验证 provider YAML 持久保存在 LocalAppData；
  重新打开软件可从缓存再次加载节点。
- 首次无缓存且订阅地址无法物理直连时，必须导入 Clash/Mihomo YAML，或临时选择 Windows
  系统代理/自定义本地代理完成一次迁移；成功后应切回内置代理引擎。
