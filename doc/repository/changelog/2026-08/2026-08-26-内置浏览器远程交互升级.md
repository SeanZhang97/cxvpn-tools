# 内置浏览器远程交互升级

- 日期: 2026-08-26
- 功能名: 浏览器页白板修复 + 远程实时交互
- 分支: 非 Git 工作区

## 需求与根因

1. 点「打开浏览器」画面全白。
2. 期望页面可自由点击/输入/滚动（无地址栏），且手感接近真实浏览器。

根因: 浏览器启动后停留在 about:blank，仅续期流程触发才导航；
交互仅有点击转发 + 1.5~2s 一帧的截图轮询，无悬停/光标/键盘/滚轮。

## 涉及文件

- `core/worker.py`、`api.py`
- `ui/app.js`、`ui/index.html`、`ui/style.css`

## 关键设计

- 手动打开浏览器且页面为 about:blank 时自动 goto 超星门户
  （manual_open 信号，续期流程行为不变）。
- Api 新增转发接口: `browser_key`(特殊键)、`browser_text`(insert_text，
  支持中文输入法)、`browser_wheel`(滚轮)、`browser_move`(悬停，返回
  elementFromPoint 的 cursor 样式)。
- Worker 主循环 tick 1s → 0.2s，降低转发命令延迟。
- 画面流: UI 观看中（_ui_watch 3s 内）worker 每 tick 截 jpeg(q60) 入
  `_shot_cache`，`get_browser` 直接取缓存；UI 300ms 轮询，约 3~5fps。
- 前端: 隐藏输入框 `#br-kbd` 承接键盘/输入法（compositionend 后
  flush）；点击涟漪本地即时反馈；mousemove 90ms 节流转发同步光标。

## 影响范围与验证

- worker tick 加快后空转开销可忽略（每拍仅查询事件与队列）。
- 截图流仅在浏览器页观看时激活，离开页面 3s 后自动停止。
- 已打包，用户实测点击/输入/滚动/悬停均生效。

## 注意事项

- 画面为"远程流"式真浏览器（同一 Playwright 上下文，共享登录态），
  帧率受截图链路限制在个位数 fps，与原生内嵌 60fps 有差距。
- `browser_move` 每次带一次 evaluate，mousemove 节流不可过低以免
  命令队列堆积。
