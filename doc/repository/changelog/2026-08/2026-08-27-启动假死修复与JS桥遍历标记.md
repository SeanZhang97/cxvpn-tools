# 2026-08-27 启动假死修复（JS 桥属性遍历标记）

- 日期: 2026-08-27
- 分支: 非 Git 工作区
- 涉及文件: api.py

## 问题与根因

工具启动后窗口约 20 秒「未响应」。startup.log 实测: 窗口 shown 0.4s、
页面 loaded 21s。根因: pywebview 在导航完成后 `inject_pywebview`
(webview/util.py `get_functions`) 递归遍历 js_api (Api) 的全部公开属性
生成 JS 桥; `Api.worker` 为公开属性, 其内持有 `main_window`
(pywebview Window), `.native` 是 WinForms Form —— 遍历进入 .NET 对象图,
pythonnet 结构体自引用属性 (`Bounds.Empty.Empty…`) 触发无限递归
(maximum recursion depth exceeded), 叠加逐属性 .NET 反射开销, 桥接注入
线程空转 20s (恰为 window.py `_api_call` 的 `event.wait(20)` 超时节奏),
期间页内 JS 桥无法建立, UI 假死。

## 关键设计

- `Api.__init__` 中 `self.worker._serializable = False`: pywebview 遍历
  逐属性检查 `getattr(attr, '_serializable', True)`, 标记后整棵子树跳过。
  UI 只调 Api 自身方法, 从不经桥接用 worker, 功能无影响。

## 影响范围

- 启动 loaded 由 ~21s 降至 ~0.9s; JS 桥暴露面仅减少 worker (UI 未使用)。

## 验证

- build_tmp/diag_boot.py (main.py 同流程 + WebView2 事件打点 + pywebview
  DEBUG 日志): 修复前 navigation 0.92s / loaded 21.20s 且日志含递归报错;
  修复后 loaded 0.89s、无报错, worker 与 UI 轮询输出无异常。
- `python build.py` 重打包, 打包版同效。

## 注意事项

- 今后 js_api 上任何持有 pywebview Window / WinForms 原生对象的公开属性
  都必须同样标 `_serializable = False`, 否则假死复现
  (每次导航完成都会重新遍历)。
