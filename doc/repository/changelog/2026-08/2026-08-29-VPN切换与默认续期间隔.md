# VPN 切换与默认续期间隔

- 日期: 2026-08-29
- 功能名: 自动连接避让手动切换与默认续期间隔调整
- 分支: 非 Git 工作区

## 问题根因

手动连接成功会调用 `Worker.reset_backoff()`，把下一次自动检查时间归零；手动切换与 Worker
自动拨号也没有共享互斥边界。开启自动连接后，从默认 VPN A 切换到 VPN B 的断开/连接间隙，
后台可能重新拨号 A；即使 B 已连接，原自动连接判定也只检查 A 是否在线，不会避让其它活动
VPN。默认续期间隔在配置、Worker 兜底和前端静态值中均为 7.5 小时。

## 关键设计

- Worker 使用可重入的 VPN 操作锁串行化后台自动拨号和 API 手动连接/断开；手动操作结束后
  重新计算 30 秒检查周期，禁止 `reset_backoff()` 造成紧邻的自动拨号。
- 自动连接只在“当前没有任何 VPN 在线”时补连默认 VPN；已有 VPN B 在线时不再拉起默认
  VPN A。授权完成触发重连时若发现 B 在线，将动作置为 `skipped`，避免界面永久显示排队中。
- 默认及前端兜底续期间隔统一由 7.5 小时调整为 7 小时，并把当前打包目录用户配置同步为 7。
- 连接时长优先通过 `RasEnumConnectionsW` 获取活动连接句柄，再由
  `RasGetConnectionStatistics` 读取 Windows 维护的 `dwConnectDuration`；Worker 由系统
  持续毫秒数反推 `connected_at`，软件重启后仍能延续当前 RAS 会话的真实时长。
- `RASCONN` / `RAS_STATS` 按 Windows `ras.h` 使用 4 字节结构打包；若枚举、统计或结构版本
  读取失败，则保留原有“软件首次观察时间”回退，不影响状态刷新和连接操作。

## 影响范围

- 开机自动连接、30 秒断线重连、授权后重连、手动切换/并行连接/断开以及续期默认值。
- 不改变 VPN 的默认项，不修改系统 VPN 配置，不改变用户主动选择的并行连接模式。

## 注意事项

- 用户切换到 B 后，只要 B 保持在线，自动连接不会拉起默认 A；B 断开且系统中没有其它活动
  VPN 后，默认 A 会在下一次自动检查时恢复连接。
- 系统时长仅适用于当前仍活动的 RAS 会话；连接一旦断开，该会话统计即失效。API 读取失败
  时会回退为软件观察时长，快照通过 `connection_time_source=system/observed` 标记来源。
